Arising from int-0002 — zero-ceremony operation, one binary, no daemon.

Go, not Elixir/OTP, despite kazi’s stack.

dira is invoked from hooks several times a session, in the latency path of a human waiting on a prompt. OTP’s value is the supervision of long-lived concurrent work — exactly what kazi needs, and exactly what dira has none of.

Arguments considered

Go — one static binary, sub-100 ms cold startupheld

The standard library already covers files, JSON and YAML, an embedded HTTP server for dira ui, and SQLite through a single dependency. A wide contributor pool matters for a tool that wants drive-by pull requests.

Elixir/OTP, reusing kazi’s Burrito and Homebrew pipelinerefused

BEAM start-up costs tens to hundreds of milliseconds before any work happens, and a Burrito-wrapped binary pays a first-run unpacking cost besides. Free CI and free distribution is a real saving, and it loses anyway: paying BEAM’s start-up for a process with no concurrency and no uptime is paying for the one thing that does not apply.

revisit if  dira grows a genuinely long-lived component — a watch daemon or a hosted service — which could be Elixir without changing the CLI.

Rustrefused

An equivalent start-up and single-binary story with better guarantees, but slower to write and a smaller contributor pool for an open-source tool that wants casual contribution.

revisit if  never on performance grounds; only if the team’s expertise shifts.

A TypeScript CLI on Node or Bunrefused

Node’s start-up sits in the same range as BEAM’s. Bun fixes that but ships a large binary and a young ecosystem, for a tool meant to be boring infrastructure.
