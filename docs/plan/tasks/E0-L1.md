## Notes on the decomposition

**Seven tasks, bound is eight.** The advisory decomposition in the L2 prompt is
followed with one departure: its items 4 and 5 are kept separate (T4, T5) because they
fail for unrelated reasons and one is an in-process test while the other shells out to
the toolchain.

**T6 is E0-L2 work pulled forward.** The lane table assigns ledger validation to
E0-L2, and `docs/plan.md` §E0 makes it an epic-level `acc:` clause. It landed here
because the ledger had no gate at all — `docs/roadmap.md`'s "all validate against the
schema" claim rested on an uncommitted script. What landed is the **schema-visible**
half only. E0-L2 still owns everything the schema cannot see, and its `acc:` is
unchanged and still red:

- id prefix vs `kind` agreement (independent fields in the schema)
- filename vs `id` agreement (filenames are outside the schema's world)
- `derives_from` edges pointing at entries that do not exist (`$defs/ref` is defined
  and never referenced, so `edge.to` carries no pattern)

No fixture was written for those three, because a fixture asserted to fail that the
schema cannot reject would have to be faked. `schema/` is a Go package with test files
only; E0-L2 adds `schema.go` with the `go:embed` there — `go:embed` cannot reach above
its own directory and the `$id` of `entry.schema.json` is a public URL that must not
move.

**No package was created that is not populated.** There is no `internal/ledger`,
`internal/ui`, or `internal/check`. `cmd/dira` and `schema` are the only two packages
in the module.

**Two commands are registered, `help` and `version`, both fully implemented.** No
`log`/`why`/`brief` placeholders: a command advertised in `--help` that refuses to run
would make T3's predicate green against non-functional entries. E1 adds one line to
`newApp`.

**Exit-code contract set here and depended on later:** `0` success, `1` runtime error,
`2` usage error. E2's hooks need to tell "dira said no" from "dira is broken" so they
can fail open.
