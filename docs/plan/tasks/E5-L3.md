## What is already true, so no task re-derives it

- **The three states and their meaning are decided, not this lane's to invent.**
  `dec-0011`: *oriented* (edge present, target resolved and readable), *withheld*
  (edge present, parent namespace declared but not readable here), *orphan* (no
  `derives_from` edge at all). Only orphan is drift. `dec-0018` adds the rendering
  rule: withheld "reads as neither an error nor a warning" and must never carry those
  words.
- **The resolution primitive already exists and this lane consumes it rather than
  rebuilding it.** `chain.Resolve` (`docs/plan/tasks/E5-L2.md`, T1+T2) already
  returns exactly `Oriented` / `Withheld` / a named error for a ref naming an
  undeclared namespace, walking the full parent chain read-only. This lane's whole
  job is: for each active intent, look at whether it has a `derives_from` edge at
  all, and if it does, hand the ref to `chain.Resolve` and translate the answer into
  the drift vocabulary. It adds no second resolver.
- **Status is never stored** (`dec-0004`). The classification this lane computes is
  read-time only — recomputed from the ledger and the chain on every call — and never
  written into an entry file. `internal/enforcer` and `internal/brief` both already
  hold this discipline; this lane is held to the same one.
- **The scope is intents, and only intents.** `dec-0006`: "an active intent with no
  `derives_from` into a parent is surfaced as drift." A decision, question,
  constraint or note with no parent is not drift by this flag — a rejected decision
  citing no precedent is not unexplained work. This lane's classifier therefore reads
  `kind == intent && state == active` and nothing else.

## What this lane does not own

**The kazi execution status shown alongside each bet in `docs/design.md` §8.1's
mockup** (`kazi: 4 done · 2 running · 1 stuck`) **is E4's join, not this lane's.**
`docs/plan/lanes/E4.md` says so from the other side: "the drift row is E5's... E4-L4
emits the unparented group so E5 can flag it; E4 must not [build the flag itself]."
E4 is still an outline epic (`docs/plan.md` §E4, `T-E4.0` unclaimed) — its `dira map`
command does not exist yet. This lane's `acc:` line does not ask for execution
status anywhere in its text, so no task below fabricates a kazi client or a stub
join to produce it. **Any future task that adds execution counts to the rendering
this lane builds depends on E4** and is deliberately not created here — creating it
now would give it an `acc:` line nothing in the tree could make pass, which
`docs/plan.md`'s own rule rejects ("a node without a testable `acc:` line is not a
plan, it is a wish"). `deps: [E4]` is the honest marker for that gap, recorded here
rather than papered over with a stub.

**Wiring this into a CLI verb (`dira map`, or a `--workspace` form of `dira brief`)
is not this lane's either.** `docs/plan/lanes/E4.md` §E4-L4 owns `dira map`, "the
intent tree grouped by why, with roll-ups" — the natural caller of this lane's
classifier. This lane produces the function E4-L4 will call; it does not invent a
competing verb to demonstrate it, and its `acc:` is satisfied entirely at
`go test` level.

### E5-L3-T1 — Classify every active intent as oriented, withheld or orphan

**Files:** `internal/drift/drift.go`, `internal/drift/drift_test.go`,
`internal/drift/testdata/fixtures/abc/{.dira/config.toml,.dira/entries/*.md,sire/.dira/...}`

**acc:** `go test ./internal/drift -run TestClassify` passes, against a fixture copied
into a fresh `t.TempDir()` per subtest (L-0014):

- over a fixture ledger holding three active intents — `A` with no `derives_from`
  edge at all, `B` with `derives_from: sire:int-0002` where `sire` is declared and
  readable, `C` with `derives_from: sire:int-0009` where `sire`'s ledger holds a
  matching entry but the `sire` directory itself is unreadable (`chmod 000`) —
  `Classify` returns exactly `{A: Orphan, B: Oriented, C: Withheld}`, asserted as a
  map compared whole rather than key by key, so a fourth, miscategorised state cannot
  hide in an untested key;
- re-running `Classify` after `chmod`-ing `sire/` back to readable moves `C` to
  `Oriented` and leaves `A` and `B` unchanged — the same map, one key different —
  proving the drift set (`{ids where State == Orphan}`) is exactly `{A}` in both
  runs, not `{A, C}` in the second;
- an active intent whose `derives_from` ref names a namespace declared **nowhere** in
  the chain (a typo) is reported as neither `Oriented`, `Withheld` nor `Orphan` — a
  fourth, explicitly distinct value (`Broken`, or equivalent), asserted by name — so a
  classifier collapsing "typo" into "withheld" (which `dec-0011`'s implementation
  notes forbid) or into "orphan" (which would hide a real ref behind a state meaning
  "no edge at all") cannot pass;
- a decision, question, constraint or note with no `derives_from` edge is **not**
  present in `Classify`'s result at all — the map's keys are exactly the active
  intents' ids, asserted by comparing the key set to the fixture's own list of active
  intents;
- `git status --porcelain` in this repository is empty after every subtest, and a
  sha256 over every file under the fixture's temp copy (including `.dira/cache/`) is
  identical before and after every call — `Classify` never writes, matching `dec-0004`.

**Both sides:** the four-state assertion is proven able to fail — a build that folds
`Broken` into `Withheld` is exercised in a subtest and shown to produce `{A: Orphan,
B: Oriented, D: Withheld}` instead of `{A: Orphan, B: Oriented, D: Broken}`, so the
map-equality assertion in the main case is shown able to catch the collapse it exists
to catch. The re-run transition is proven both ways in one test: `C` moves state, and
`A`/`B` are asserted **unchanged**, because a classifier that recomputed every id from
scratch and happened to agree twice would pass a check that only looked at `C`.

**depends_on:** none · **verifies:** `dec-0006` (the drift flag), `dec-0011` (the
three-state model)

### E5-L3-T2 — Render the three states without withheld reading as an error

**Files:** `internal/drift/render.go`, `internal/drift/render_test.go`

**acc:** `go test ./internal/drift -run TestRender` passes, over T1's classified
fixture:

- the rendered report contains one line per active intent, in a stable order (by id),
  and the orphan line for `A` is the only one carrying a drift marker — asserted by
  a distinctive drift-only token the test defines and searches for, present exactly
  once;
- the withheld line for `C` contains neither the substring `error` nor `warning`,
  case-insensitively, matching `dec-0018`: "withheld reads as neither an error nor a
  warning" — asserted as a zero-occurrence search over the **whole** rendered report,
  not just `C`'s line, so a global banner reading "1 error found" elsewhere in the
  same output still fails this;
- the withheld line names the namespace (`sire`) but — for a parent declared with
  `visibility = "private"` and a `label` — never prints the label, asserted as a
  zero-occurrence search for the label string over the whole report (the runtime
  counterpart of `scripts/privacy-lint.py`'s P2, which only checks committed bytes);
- the oriented line for `B` renders the resolved entry's title; the report never
  renders any text belonging to `C`'s unread parent entry, because `Withheld` from
  T1 carries no entry to render in the first place — asserted by constructing the
  report from a `Classify` result whose `C` entry, if `Render` tried to read one,
  would be a distinctive sentinel string, and asserting that string is absent;
- `Render` takes T1's result and produces a string; it opens nothing and reads
  nothing further — asserted by a `Classify` result built by hand in the test with no
  ledger behind it at all, over which `Render` still succeeds.

**Both sides:** the error/warning-word check is shown red first against a
deliberately worded withheld line ("parent unreachable: treat as an error") and green
against the real renderer's line, in the same subtest — the check would otherwise be
unfalsifiable, exactly the shape L-0019 records for a bare substring search. The
label-absence check is shown red against a renderer that prints `Decl.Label` and green
against the real one.

**depends_on:** E5-L3-T1 · **verifies:** `dec-0011`, `dec-0018` (withheld is
first-class, never an error or a warning), `dec-0004` (nothing here is stored — see
T1's git-status clause, which this task's fixture reuses unchanged)
