## What is already known, so no task re-derives it

`dira brief` landed in E1-L5 and was measured **in process**: 17.3 ms warm, 61.2 ms cold
over the 200-entry fixture (`docs/decisions-pending/E1-L5-report.md` §4). **That number
is not this lane's number.** It excludes process start, `embed.FS` init, config read and
the cache open — everything between `execve` and `local.Open`. Nothing in the repo
measures the spawned binary, and closing that gap is the whole of this lane.

The nearest prior art is `internal/index/latency_test.go`. Read its `measureWithSetup`
before writing a line of T1: it takes the **minimum** of its samples, not the median,
because `go test ./...` runs packages in parallel and contention can only ever *add*
time. Its comment is the argument, and it is correct. **It does not license changing
this lane's statistic** — E1-L6's `acc:` says *median of N≥20*, and a minimum-based gate
fires strictly less often than a median-based one, so substituting it would be a
weakening. The discipline this lane inherits is the *diagnosis*, not the substitution:
the instrument was wrong, not the claim. T1 fixes the instrument by measuring where
there is no contention (a `perf`-tagged package run alone), reports the minimum
alongside the median as the uncontended estimate, and leaves the asserted statistic
exactly as the lane wrote it.

Two figures every task should hold in view, both from a machine running a dozen parallel
sessions, so both are inflated: `dira version` (spawn baseline) 92.8 ms median, and
`dira brief --context --chain` cold 184.0 ms median / 226.2 ms p90. Also
`internal/ledger/fixture`'s `TestFullLedgerReadIsWithinBudget` has already failed once
under full-suite load (254 ms against a 150 ms budget) and passes when run alone. That is
the failure mode T1 and T4 exist to design around.

**The verification standard this lane is held to** (`docs/lore.md` L-0001): a gate is
evidence only once **both** sides have been observed — red on a constructed defect of the
class it claims to catch, **and** green on the untouched correct baseline. Rule 2 is the
one nobody applies, and a timing test is where it bites hardest: a harness that measures
nothing at all (an empty ledger, a binary that exited on a usage error, a "cold" run
whose cache was never removed) returns a very fast number and looks exactly like a pass.
Every task below carries both sides in its `acc:`.

### E1-L6-T1 — Build the cold-start harness and the one budget block

**Files:** `internal/perf/doc.go`, `internal/perf/budget.go`, `internal/perf/harness.go`,
`internal/perf/coldstart_test.go`

**acc:** `go test -tags perf -count=1 -p 1 ./internal/perf -run TestColdStartBudget -v`
passes and, on the same tree, fails as described below.

The harness must:

- **Build and run the shipped binary as a subprocess.** `go build -o <tmp>/dira
  ./cmd/dira` once per test run, then `exec` it — never `go run` (which measures the
  compiler) and never an in-process call (which is what E1-L5 already measured and what
  this lane exists because of). It skips rather than fails where there is no `go` on
  `PATH`, matching `goTool` in `cmd/dira/build_test.go`.
- **Measure the argv the hook actually installs.** The measured command is
  `dira brief --context --chain`, and a sibling assertion fails if that exact string is
  no longer present in `hooks/settings.example.json`'s `SessionStart` block — so the
  measurement cannot drift away from the thing a user pays for.
- **Materialise the 200-entry fixture** via `internal/ledger/fixture` (`fixture.Seed`,
  `fixture.Size`) into a `t.TempDir()`, exactly as `benchLedger` in
  `internal/index/latency_test.go` does.
- **Be cold N≥20 times.** `.dira/cache/` is removed *before every timed run*, and the
  removal is outside the timer (`measureWithSetup`'s split).
- Fail if the **median of N≥20 cold runs exceeds `coldMedianBudget` (100ms)** or if
  **any single cold run exceeds `coldMaxBudget` (150ms)**, and name in the failure
  message *which* budget broke and by how much.
- `t.Log` the full distribution — n, min, median, p90, max — with the minimum labelled as
  the uncontended estimate per `internal/index/latency_test.go`'s reasoning, so a red run
  is diagnosable without a re-run.
- Skip under `testing.Short()` and under the race detector, for the reason
  `internal/index/latency_test.go` states (the detector costs several times the work
  being measured).

Every duration constant lives in `internal/perf/budget.go` and nowhere else: the check is
that `grep -l 'Millisecond' internal/perf/*.go` lists `budget.go` only. `budget.go`
declares all four budgets used by this lane up front — `coldMedianBudget`,
`coldMaxBudget`, `warmBudget`, `reindexBudget` — so T2 never edits this file and the two
tasks cannot collide.

**Both sides, per L-0001, transcribed into the lane report:**

- **Red on a constructed defect.** Lowering `coldMedianBudget` to `1 * time.Millisecond`
  turns the test red with a message naming the median budget; restoring it turns it
  green. Same for `coldMaxBudget`.
- **Green on the untouched baseline.** The unmodified tree passes, run alone, on the
  maintainer's machine, and the observed numbers are recorded.
- **The measurement cannot pass vacuously.** The test fails, as "measured nothing"
  rather than passing fast, if: the subprocess exits non-zero; its stdout does not
  contain content derived from the fixture (at minimum the brief's open-blockers
  section header and ≥1 fixture entry id); or the cache directory was already present at
  the start of a run labelled cold. Each of these three is proven to fire by construction
  (an empty ledger, a deliberately broken argv, and a skipped `RemoveAll`), because a
  harness that would return 3 ms against an empty ledger is a green light on nothing.

**Do not raise a budget to make this pass.** 100ms is `int-0002`'s stated achievement
condition. If it is unreachable, that is T5's finding and T6's ledger entry, not a
constant edit.

**depends_on:** none · **verifies:** `int-0002`

### E1-L6-T2 — Assert the warm and `reindex` budgets on the same harness

**Files:** `internal/perf/warm_test.go`, `internal/perf/reindex_test.go`

**acc:** `go test -tags perf -count=1 -p 1 ./internal/perf -run
'TestWarmBriefBudget|TestReindexBudget' -v` passes, reusing T1's harness and T1's
`budget.go` without adding a constant to either.

- **Warm.** `dira brief --context --chain` run N≥20 times against an already-built cache
  fails if its median exceeds `coldMedianBudget` — the lane's `acc:` requires warm to not
  exceed the cold budget — and additionally fails if it exceeds `warmBudget`, the tighter
  number `budget.go` declares. The test asserts the runs were actually warm: a warm run
  that rebuilt the cache fails as mislabelled rather than being reported as a slow warm
  number (the cache file's mtime/size is unchanged across the N runs, or the binary
  reports zero entries re-indexed).
- **`reindex`.** `dira reindex` over the 200-entry fixture with `.dira/cache/` removed
  before each run fails if its median exceeds `reindexBudget`. That constant carries, in
  a comment beside it, the measurement it was derived from and the headroom factor
  applied — a budget with no stated origin is a number somebody liked. The test asserts
  the reindex actually did the work: it fails if fewer than `fixture.Size` entries were
  indexed.

**Both sides:** lowering each budget to 1 ms turns exactly its own test red and names
itself; restoring turns both green on the untouched tree; and a `reindex` run against an
empty ledger fails as "indexed 0 of 200" rather than passing in microseconds.

**depends_on:** E1-L6-T1 · **verifies:** `int-0002`

### E1-L6-T3 — Prove the measured run opened no socket, and publish the method's limits

**Files:** `internal/perf/network_test.go`, `internal/perf/NETWORK.md`

**acc:** `go test -tags perf -count=1 -p 1 ./internal/perf -run TestTheBriefOpensNoSocket
-v` passes, and `internal/perf/NETWORK.md` states what the method proves and what it does
not.

The lane's `acc:` asks for two different things and they need two different mechanisms:

1. **"The run happens with no network available."** On Linux, the cold brief runs under a
   network namespace with no route (`unshare -rn`, or the runner's equivalent), and the
   test fails if stdout, stderr or the exit code differ in any byte from the same run
   with the network up. That is an assertion about *dependence*.
2. **"The test asserts the binary opened no socket."** On Linux, the same run is traced
   (`strace -f -e trace=socket,connect,socketcall`) and the test fails if any matching
   syscall is attributed to the process. That is an assertion about *behaviour*, and it
   is the only one of the two that is actual evidence.

**The linkage shortcut is not available here, and NETWORK.md must say so.** `cmd/dira`
links `net`, `net/http` and `crypto/tls` today — reachable through `internal/ui`, which
serves the read-only localhost UI (`go list -deps ./cmd/dira | grep -c '^net/http$'`
returns 1). A denylist over linked stdlib packages would therefore be red on a correct
binary, which is L-0001 rule 2 in its purest form. Do not write it. Linkage is not
evidence of abstinence; the runtime trace is.

**Both sides:**

- **Red:** a fixture helper that deliberately opens a socket (a one-line `net.Dial` in a
  `_test`-only binary built the same way) is caught by the same assertion. Without this,
  a `strace` invocation that silently failed to attach is indistinguishable from a clean
  run.
- **Green:** the untouched `dira brief` run passes both checks, and the test additionally
  fails if the trace produced **no output at all** — an empty trace means tracing did not
  work, not that nothing happened.
- **Where the method is unavailable** (darwin: `dtrace` needs SIP disabled; any runner
  without `CAP_SYS_PTRACE`), the test **skips with the reason named in the skip message**
  and `NETWORK.md` records it. It never asserts a weaker thing under the same test name —
  a skipped platform is honest, a renamed assertion is not. T4 is responsible for making
  sure the platform where it does run is a platform CI actually runs on.

**depends_on:** E1-L6-T1 · **verifies:** `cst-0004`, `int-0002`

### E1-L6-T4 — Make it a CI gate, on CI hardware, with the variance policy stated

**Files:** `.github/workflows/ci.yml`, `hooks/pre-commit`, `scripts/ci-local.sh`

**acc:** a dedicated `perf` job in `.github/workflows/ci.yml` runs
`go test -tags perf -count=1 -p 1 ./internal/perf`, is not `continue-on-error`, and is
red when the budget is exceeded. Specifically:

- The job **asserts a non-zero count of executed tests**, in the same shape and for the
  same reason as the existing `go` job's `ran -eq 0` check. A `perf` build tag that stops
  matching — renamed, dropped, misspelled — produces a green job over zero tests, which
  is the single easiest false victory this lane can hand itself.
- The job **publishes the distribution** (n, min, median, p90, max, and which budget each
  was measured against) to `$GITHUB_STEP_SUMMARY`, so a future regression is diagnosable
  from the run page without a re-run.
- **`-p 1` and a job of its own.** The perf package is build-tagged out of
  `go test ./...` precisely so it never competes with the rest of the suite for CPU and
  disk. This is the `internal/index/latency_test.go` lesson applied at the job level:
  remove the contention, do not loosen the assertion.
- **The runner-variance policy is decided in this task and written down in the workflow
  comment**, with its reasoning — which runners it runs on, why, and what happens when
  they are noisy. It must be one of: a stated CI multiplier applied to `budget.go`'s
  numbers with the multiplier and its derivation in the comment; a stated
  higher-percentile threshold with its N; or a dedicated runner. Whichever is chosen, the
  comment states what was rejected and why, because a flaky gate that gets disabled after
  three false alarms is worse than a slower stated budget that holds. **A multiplier is
  not a budget change** — `budget.go` keeps `int-0002`'s 100 ms; the multiplier, if any,
  is named, applied only in CI, and visible in the summary output.
- **`hooks/pre-commit` and `scripts/ci-local.sh` gain the same invocation**, because
  `ci.yml`'s own header requires it: *"If you add a gate here, add it to hooks/pre-commit
  and scripts/ci-local.sh in the same change."* A gate a contributor cannot reproduce
  locally is a `cst-0004` violation in the repo's own terms.
- The platform T3's socket assertion runs on must be one this job actually runs — if the
  method is Linux-only, the job includes a Linux runner and the report says so.

**Both sides, evidenced by run URLs in the lane report:** one CI run red on a branch with
`coldMedianBudget` lowered to 1 ms, showing the failure names the median budget; one CI
run green on the untouched branch, showing a non-zero executed-test count and the
published distribution. A gate whose green side has never been observed on CI hardware is
not a gate — it is a claim about the maintainer's laptop.

**depends_on:** E1-L6-T1, E1-L6-T2, E1-L6-T3 · **verifies:** `int-0002`

### E1-L6-T5 — Attribute the cold run to named phases, then close the gap if there is one

**Files:** `docs/decisions-pending/E1-L6-report.md`, and — only if the measurement demands
it — `internal/index/*.go`, `internal/brief/*.go`, `internal/ledger/local/*.go`

**This task owns the only authorisation in this lane to touch code outside
`internal/perf`.** The lane file grants it explicitly: *"its owner is explicitly
authorized to modify their code — otherwise it becomes a lane that can only file bugs."*
No other task here may edit `internal/index`, `internal/brief` or `internal/ledger`.

**acc:** `docs/decisions-pending/E1-L6-report.md` carries a phase attribution of one cold
`dira brief --context --chain` run, measured (pprof, `GODEBUG=inittrace=1`, or explicit
phase timing behind the `perf` tag — the method is stated), broken into at least: process
start and Go runtime init; package init including `embed.FS`; config read; cache open and
cold build; entry-file reads; render; exit. Each phase is reported in ms, and **the
phases sum to within 10% of the harness's measured cold median** — an attribution that
does not add up is a story, not a measurement, and the 10% reconciliation is what makes
it falsifiable.

Then, whichever case holds:

- **If T1's gate is already green:** no optimisation lands. The report states the headroom
  per phase and names the phase that will break the budget first, so the next regression
  is diagnosable rather than merely detected. `int-0002`'s "well under 100ms" is quoted
  against the observed median, honestly, including if the answer is "green but with 6 ms
  of headroom, which is not *well* under".
- **If it is red:** the change that closes the gap lands in the same task, with a
  before/after taken from **T1's harness, not a new measurement**, both numbers in the
  report, and no edit to any constant in `budget.go`. Candidate directions the lane file
  already named: lazy body parsing, not reading 200 markdown bodies to render eight
  titles, skipping the cache open on the happy path. Which one is chosen must follow from
  the attribution above, not from this list.
- **No daemon, no resident process, no warm-up trick** (`int-0002`), and no network cache
  (`cst-0004`). Meeting the budget by keeping something alive violates the constraint the
  budget exists to protect, and the test would not catch it — so it is stated here as a
  refusal, and T6 records it.
- **If 100 ms cold is unreachable on CI hardware without one of those**, the report says
  so plainly with what it would cost to reach, and T6 becomes a superseding-entry task
  rather than a record-the-policy task. It does not become a budget edit.

Every full-suite regression this task introduces elsewhere (`go test ./...`,
`golangci-lint`, `gofmt`) is fixed in this task, not left for T6.

**depends_on:** E1-L6-T4 · **verifies:** `int-0002`

### E1-L6-T6 — Record the measurement decisions as a ledger entry

**Files:** `.dira/entries/dec-00NN.md` (id allocated by `dira log`, never hand-picked)

**acc:** a new `decision` entry exists under `.dira/entries/`, written by
`dira log --kind decision …` so the id is the lowest unused one and cannot collide with
another lane running concurrently. It records, each with its alternatives:

1. **Why the budget is measured as a spawned subprocess** rather than in process, and
   what E1-L5's 61.2 ms cold in-process number does and does not cover.
2. **The CI runner-variance policy** T4 chose, and what it rejected.
3. **The minimum-vs-median instrument discipline** — that the asserted statistic is the
   median `int-0002` was written against, that the minimum is reported as the uncontended
   estimate, and that contention is answered by isolating the measurement rather than by
   changing the statistic.
4. If and only if T5 concluded the budget is unreachable: a `supersedes` edge to whatever
   `int-0002` clause is being changed, with the measured cost of reaching 100 ms stated as
   the `why_not` on the alternative of keeping it. **Absent that finding, this entry does
   not touch `int-0002`'s number.**

The entry validates: `go test ./schema` and `go test ./internal/ledger` pass with it in
place; it carries ≥1 `alternatives[].why_not`, each non-empty; it carries a
`derives_from` edge to `int-0002`; `grep -c 'int-0002' .dira/entries/dec-00NN.md` returns
≥1; and `python3 scripts/coverage.py` and `python3 scripts/privacy-lint.py` both still
pass.

## The clause this lane may not be able to meet, stated rather than quietly adjusted

`acc:` requires that **no single cold run exceeds 150 ms**. On a machine running parallel
sessions, `dira version` alone — a binary that reads nothing — took 92.8 ms median and
95.6 ms p90, and a cold `dira brief` took 226.2 ms at p90. A single-run maximum is the
statistic most exposed to a scheduler hiccup, and it is asserted over N≥20 samples, so one
outlier fails the run. T1 and T4 are designed to give it the best chance available without
touching the number: isolate the package, run it alone, publish the distribution. If it
still cannot hold on CI hardware after T5's attribution, that is a finding for T6's ledger
entry and the lead — **not a constant to raise**. It is flagged here on the way in rather
than discovered as a flake later.
