# E3-L3 — tasks (L2)

**Lane:** `docs/plan/lanes/E3.md` §E3-L3. **Prompt:** `docs/plan/prompts/L2-E3-L3.md`.
**Status: not started.** Nothing here is an as-built record: every `acc:` below is **red
today**, and each task states how it is red so a claimant watches the gate fail before
making it pass (L-0001). The checkbox on each `acc:` bullet is the claimable unit.

**Bound:** 7 tasks (≤8 per the L2 prompt).

**Waves:** `[T1, T2]` → `[T3]` → `[T4, T5]` → `[T6, T7]`.
No two tasks in the same wave own the same file. `T5` and `T7` both edit
`internal/enforcer/render.go`; that is why `T7` depends on `T5` rather than sitting
beside it.

**This is a security lane.** `cst-0003` says a violation is a security bug, not a UX bug,
and a private strategic note in public git history cannot be un-published. Every
privacy-adjacent task below therefore states how it is *proved* not to leak — a sentinel
searched across every output byte, and a byte-level digest of the parent ledger before
and after the run, which is the standard `dira supersede` already set
(`docs/plan/lanes/E3.md` §E3-L4: *"writes nothing, and leaves the parent ledger
byte-identical"*).

## What is already true, so no task re-derives it

- **`cst-0003` has an enforcement point.** `scripts/privacy-lint.py` runs four invariants
  in CI (P1 no `private: true` entry in a public ledger; P2 no private parent's `label` in
  any committed file; P3 every namespaced ref resolves to a namespace declared in
  `[parents]`; P4 mirrored ADRs carry refs, never foreign prose). It exits 0 today. This
  lane extends what it already asserts rather than starting a second privacy check, and
  the runtime tasks below assert at run time what P2 and P3 assert on committed bytes.
- **`dira supersede` already refuses to write upward.** `cmd/dira/supersede.go`'s
  `checkRefs` rejects a namespaced ref on either side **before the ledger is opened**, at
  exit 2, and the acceptance for that clause is the parent tree's sha256 being provably
  unchanged. Reuse that shape — refuse before you touch anything, then prove it with a
  digest — instead of inventing a second refusal.
- **`qst-0001` is answered, not open.** `.dira/entries/qst-0001.md` reads
  `state: answered`, answered on 2026-07-30 by `dec-0011`: cross-boundary parent refs
  publish verbatim and opaquely, and resolution reports **three** states —
  *oriented* / *withheld* / *orphan*, of which only orphan is drift. `dec-0018` makes
  withheld a declared first-class state that must never render as an error.
  `docs/plan/lanes/E3.md` still describes `qst-0001` as open; that lane file predates the
  answer and is not edited here. **No task below is blocked on it**, and none needs to
  assume an answer, because there is one on the record.
- **The boundary that survives the answer** is still real and is respected: this lane
  resolves a parent that is present on this machine and reports when it is not. It does
  **not** decide what a *public clone's rendered surface* displays for a dangling private
  ref — that is E5's, and T7 below is a CLI report line on stderr, not a rendered surface.
- **`check.schema.json` already encodes the ref-only rule.** A `private: true` conflict is
  forbidden from carrying `title`, `rejected_alternative`, `why_not`, and its `revisit_if`
  must be null. `internal/enforcer/render.go` implements the same rule in both modes. What
  is missing is the *inherited* citation reaching those code paths at all.
- **`internal/config` reads `[parents]` as bare names.** `Config.Parents` is a
  `[]string`; the `{ path, ref }` shape committed in `.dira/config.toml`, and `dec-0011`'s
  `visibility` field, are not parsed yet.

## The landmine this lane will hit if nobody names it

**L-0014:** `internal/enforcer/testdata/ledgers/<name>/` is a flat directory of `*.md`
and **not a ledger `dira` can open**. `local.Find` walks *up*, so pointing a command at a
fixture path silently grades against **this repository's own `.dira`** — with no error.
A leak test that did that would pass while proving nothing. Every task below that runs
the binary copies its fixture into a real temp `.dira/entries/` tree and asserts the
citation is present *before* asserting the sentinel is absent.

### E3-L3-T1 — Parse `[parents]` into declarations, not names

`.dira/config.toml` already commits the shape — `sire = { path = "…", ref = "main" }`,
`me = { visibility = "private" }` — and `dec-0011` adds `visibility` and an optional
`label`. Read it in the existing config reader; do not invent a second config surface and
do not link a TOML library (the package's own contract: three values do not justify a
dependency in a binary that runs in a hook's latency path).

- **files:** `internal/config/config.go`, `internal/config/config_test.go`
- [x] **acc:** `go test ./internal/config` passes: a config declaring
  `sire = { path = "../x", ref = "main" }`, `me = { visibility = "private", label = "…" }`
  and a commented-out example yields exactly **two** declarations in file order — `sire`
  with its path and ref, `me` with `visibility: private` and no path — and a commented
  line is never a declaration (the rule `scripts/privacy-lint.py` already applies, for the
  same reason: a reader that counted them would report parent ledgers nobody configured);
  a value written for a key dira reads that cannot be made sense of is *reported* rather
  than guessed at, matching the package's existing error contract; every existing caller
  of `Config.Parents` still compiles, with `go build ./...`, `go vet ./...` and
  `gofmt -l .` each exiting 0 and `gofmt` printing no paths; and
  `python3 scripts/privacy-lint.py` still exits 0.
- **depends_on:** none
- **red today:** `Config.Parents` is `[]string`; nothing reads `path`, `ref`,
  `visibility` or `label`.

### E3-L3-T2 — Open a parent ledger through a store that cannot write

`cst-0003` rule 1 is architectural, so the guarantee belongs in a type, not in care. The
shape already exists twice in this repo: `internal/sniff`'s `stagedOnly` wrapper, and
`supersede`'s refuse-before-you-open ordering. The specific hazard here is not `Put` — it
is the **cache**: `index.Open` writes to `local.CacheDir(diraDir)`, so opening a parent
the ordinary way writes a SQLite file under the parent. `.dira/cache/` is gitignored, so
a git-based check would not see it; the digest must be over the filesystem tree.

- **files:** `internal/ledger/readonly.go`, `internal/ledger/readonly_test.go`
- [x] **acc:** `go test ./internal/ledger -run TestReadOnly` passes: the wrapper's
  `Create`, `Put` and `Delete` each return an error naming `cst-0003` rule 1 **before**
  any call reaches the inner store, asserted with a recording inner store that must have
  received zero calls; `Get` and `List` pass through unchanged; and a sha256 digest over
  **every file** under a fixture parent ledger directory — including `.dira/cache/`,
  which is gitignored and therefore invisible to a git-based check — is identical before
  and after a full read of that parent through the wrapper, with the test shown red when
  the read path is swapped for `index.Open`.
- **verifies:** lane `acc:` — *"no dira invocation in the test writes any byte under the
  parent ledger path (assert by parent-tree digest, `cst-0003` rule 1)"*.
- **depends_on:** none
- **red today:** no read-only store exists; every `ledger.Store` in the module can write.

### E3-L3-T3 — Inherit the parent's active constraints, namespaced

Collect the parent's `constraint`/`active` entries, namespace their refs, and add them to
the enforcement set the matcher already builds. The enforcement table in
`docs/plan/lanes/E3.md` is closed and does not widen across the boundary: a parent's
decisions, questions, intents, notes, staged and superseded entries contribute nothing.

The namespace is the key under `[parents]` in the **child's** config, not the parent's own
`[ledger].name` — those can disagree, and `dec-0011` makes the declared key the thing that
resolves (`scripts/privacy-lint.py` P3 already resolves committed refs the same way). Keep
this read path narrow and reusable: E5 builds namespaced ref resolution on it and must
extend it rather than write a second one.

- **files:** `internal/enforcer/inherit.go`, `internal/enforcer/inherit_test.go`
- [x] **acc:** `go test ./internal/enforcer -run TestInherit` passes: given a child ledger
  and one parent declared as `me`, the enforcement set gains exactly the parent's
  `constraint`/`active` entries, each cited as `me:cst-NNNN`, with a fixture in which the
  parent's own `[ledger].name` differs from the declared key proving the declared key
  wins; the parent's decisions, questions, intents, notes, staged and superseded entries
  produce no unit at all; every inherited citation carries `Private: true` when the
  parent's `[ledger].tier` is `person` **or** the entry sets `private: true` — the rule is
  unconditional, so the test includes a non-private entry in a `person`-tier parent and
  requires it private too; the ordering of inherited units is total, so two runs produce
  the same bytes; and `Verdict.Enforced` equals local plus inherited, shown red when
  inheritance silently contributes nothing.
- **depends_on:** E3-L3-T1, E3-L3-T2
- **red today:** `internal/enforcer` has no notion of a second ledger; `enforcementSet`
  reads one slice of entries.

### E3-L3-T7 — Report an unresolved parent, and a withheld one, without changing the verdict

A check that quietly drops inherited constraints is a firewall with a hole in it, and it
fails silently in exactly the configuration a public clone has. It must report — and the
report must not become a verdict: `dira check`'s 2 means a cited conflict and nothing
else, so an unreachable parent may not move the exit code in either direction.

Two shapes, and `dec-0011` says they are different: a declared parent whose path is not
there is **unresolved**; a parent declared `visibility = "private"` and not readable here
is **withheld**, a designed state that must never render as an error or a warning
(`dec-0018`). Where such a parent carries a `label`, the label must not appear in any
output — the runtime counterpart of `privacy-lint` P2.

`schema/check.schema.json` is `additionalProperties: false` with a fixed `required` list,
so carrying this in `--json` is a schema change made deliberately, not a key added
quietly.

- **files:** `internal/enforcer/enforcer.go`, `internal/enforcer/render.go`,
  `schema/check.schema.json`, `cmd/dira/check_unresolved_test.go`
- [x] **acc:** `go test ./cmd/dira -run TestUnresolvedParent` and `go test ./schema` pass:
  with `[parents]` pointing at a path that does not exist, a plan that conflicts locally
  still exits **2** and a plan that is locally clean still exits **0** — the unresolved
  parent never changes the exit code; both runs print one line naming the unresolved
  parent and stating how many of its constraints were evaluated (zero), and a parent that
  exists but is unreadable prints the same shape with the same count, with no line
  claiming a total the run could not have read; a parent declared
  `visibility = "private"` and unreadable here prints as **withheld**, with neither the
  word `error` nor `warning` in that line, and its declared `label` appears nowhere in
  stdout, stderr or `--json`, asserted as a zero-occurrence search over all three; the
  report goes to **stderr**, so stdout stays the parseable verdict — the shape
  `cmd/dira/check.go` already uses for the index notice; `--json` carries the same report
  in a `parents` block described by `schema/check.schema.json`, a document carrying an
  undescribed key still fails validation, and every existing `--json` test still passes.
- **verifies:** lane `acc:` — *"with `[parents]` pointing at a nonexistent path the same
  command still exits on its *local* verdict while printing a line naming the unresolved
  parent and the number of constraints not evaluated"*.
- **depends_on:** E3-L3-T4, E3-L3-T5
- **red today:** an unresolvable parent is not detected at all, because `[parents]` is
  not read; `schema/check.schema.json` has no `parents` key and forbids one.

## Not decomposed further

No task here felt too large to converge in one kazi run, so the stop rule does not apply
and no L3 exists. Two notes on where the line was drawn.

**T6 is one task even though it asserts three properties** (no leak, no child write, no
parent write). They share one fixture pair and one run; splitting them would have made
three tasks each stand up the same two ledgers, and the digests are only meaningful
around the run that the leak assertion is also measuring.

**The `[parents]` reader is deliberately narrow (T1 + T2 + T3).** E5 builds namespaced ref
resolution on this path. It resolves what is declared and present, and reports what is
not; it holds no policy about what a public surface displays.

## Reported rather than assumed

**`docs/plan/lanes/E3.md` describes `qst-0001` as open.** It is `answered` in the ledger
(`dec-0011`, 2026-07-30). The tasks above are planned against the answer; the lane file is
out of scope for this pass and is left for whoever owns it to correct.

**The unresolved-parent count is honest only as "evaluated: zero".** The lane `acc:` asks
for "the number of constraints not evaluated". For a parent that cannot be read, that
number is not knowable — a ledger nobody can open has no countable constraints — so T7
requires the line to state the count it *can* know and forbids it from claiming one it
cannot. The predicate is met without being weakened; the reading is recorded here rather
than resolved silently.
