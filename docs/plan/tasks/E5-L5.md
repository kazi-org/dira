## What is already true, so no task re-derives it

- **Entry construction and validation already exist and this lane reuses them
  rather than writing a second copy.** `ledger.DecodeDraft` parses an entry with no
  `id` yet and validates it against every rule a stored entry obeys except the two
  fields a draft does not have (`internal/ledger/draft.go`); `dira log`'s whole write
  path already goes through it. This lane's interview produces the same kind of
  draft — YAML frontmatter plus a markdown body — and hands it to the same
  validation, not a parallel one.
- **No `.dira` creation primitive exists yet, and this lane is where the gap is real.**
  `local.Open`'s own doc comment: "the `.dira` directory... must exist... Open
  deliberately creates nothing." `local.ReadConfig`'s doc comment names this
  explicitly: "a ledger with no config file is a working ledger... `dira init` —
  which would write one — has no owner in this release." This lane is that owner.
- **No model client is in the binary, and this interview does not add one**
  (`dec-0003`). "The interview is conducted by the already-running session, not by
  dira" (`docs/plan/lanes/E5.md`'s entries note): dira's role is to ask fixed
  questions on stdout and read answers from stdin, one line per question, and to
  validate what comes back — not to generate questions, not to interpret free text
  semantically. A scripted answer fixture (piped stdin, no live model) is not a test
  shortcut standing in for the real thing; it **is** the real thing, because the real
  interview loop has no code path that reads a model at all.
- **The five kinds are closed** (`cst-0002`) and **status is never stored**
  (`dec-0004`) — an interview-produced intent gets `state: active`, never a
  `planned`/`in-progress` value dira has no field for.
- **`cmd/dira` may import `os` and nothing else from the filesystem set**
  (`internal/ledger/boundary_test.go`'s allowlist). Creating `.dira/` itself is a path
  operation and belongs in `internal/ledger/local`, the one package allowed
  `path/filepath`, not inlined into `cmd/dira/init.go`.

## The landmine this lane will hit if nobody names it

**A half-written ledger is worse than no ledger**, and nothing in `ledger.Store`
today prevents one: `Store.Create` writes one file per call, so an interview that
writes its intent, then its constraint, then dies before its question would leave
`.dira/entries/` holding two files and dec-0010's "no successful init produces an
empty ledger" guarantee half-kept — the ledger is not *empty*, but it is not what the
interview promised either, and nothing marks it incomplete. T2 exists because the
guarantee this lane is graded on ("aborted or unanswered init exits non-zero leaving
**no** `.dira/entries/` directory behind") is stricter than "eventually consistent":
it demands **all-or-nothing**, which means every answer is collected and validated in
memory before the first byte reaches disk.

### E5-L5-T1 — Write the fixed interview script and the answers-to-drafts builder

The script is fixed, not generated: a short, ordered list of prompts covering the
three kinds `dec-0010`'s guarantee needs (at least one intent, one constraint, one
question) plus which tier is being seeded (person or workspace — this lane's scope
per the lane header; a repo-tier `.dira` is not seeded by this command). Each answer
maps onto one entry's `title` and body; a blank answer where the script requires one
aborts rather than writing an empty title.

**Files:** `internal/interview/interview.go`, `internal/interview/interview_test.go`

**acc:** `go test ./internal/interview -run TestBuild` passes:

- `Build` given a complete scripted answer set (a `[]string`, one line per prompt, no
  model, no I/O) returns `≥1` intent draft, `≥1` constraint draft and `≥1` question
  draft, each of kind matching its prompt and state `active`/`active`/`open`
  respectively, and each passing `(*ledger.Entry).ValidateDraft()` unmodified;
- the tier the script asked for (`person` or `workspace`) is returned alongside the
  drafts as a plain string, not baked into any entry — no entry kind carries a tier
  field (`entry.schema.json` has none);
- an answer set missing a required prompt (fewer lines than the script has prompts,
  simulating stdin closing early) returns a named error and **zero** drafts — not a
  partial slice a caller might forget to check the error before using;
- a required prompt answered with only whitespace returns the same named-error,
  zero-drafts shape — a title of `"   "` would fail `ValidateDraft`'s `minLength: 3`
  after trimming anyway, and this task catches it before that far, with a message
  naming which prompt was blank;
- `Build` performs no I/O of any kind — asserted by running it with `t.Chdir` pointed
  at a directory containing no `.dira` at all, which would make any accidental
  filesystem read fail loudly rather than silently succeed against the wrong ledger;
- calling `Build` twice with the same answers produces two draft sets with identical
  titles, bodies, kinds and states — no field is randomised or time-derived (`created`
  is stamped later, by T2's writer, not by `Build`).

**Both sides:** the missing-prompt and blank-prompt cases are each shown to produce
zero drafts, and the complete case is shown to produce the full set, in the same test
run — a `Build` that always returned zero drafts would pass the two red cases and
fail the green one, which is exactly what the assertion on draft **count**, not just
on the error being non-nil, is there to catch.

**depends_on:** none · **verifies:** `dec-0010` (no successful init is empty — this is
the "successful" side), `dec-0003` (no model client — `Build` takes strings and
returns drafts, nothing else), `cst-0002` (the five kinds — three of them, by
prompt-to-kind mapping asserted literally)

### E5-L5-T2 — Give `local` an all-or-nothing ledger creation, no partial `.dira` on any failure

**Files:** `internal/ledger/local/init.go`, `internal/ledger/local/init_test.go`

**acc:** `go test ./internal/ledger/local -run TestInitLedger` passes:

- `InitLedger(dir string, cfg []byte, drafts []*ledger.Entry) (*Store, error)`,
  given a directory with no `.dira` inside it and a non-empty `drafts` slice, creates
  `.dira/config.toml` (the given bytes verbatim) and one file per draft under
  `.dira/entries/`, each allocated the lowest unused id for its kind and stamped
  `created`, then returns a `*Store` open over it — the entries are readable through
  the ordinary `Store.List`/`Get` path immediately, with no cache to warm;
- called with an **empty** `drafts` slice, `InitLedger` creates **nothing** — no
  `.dira` directory at all — and returns a named error: an empty-drafts call is not a
  degenerate success, because `dec-0010`'s guarantee is exactly what an empty
  successful init would violate;
- a write failure partway through the draft list (simulated: the third of four drafts
  is given an id collision that cannot be allocated, forced by pre-seeding a
  conflicting file) leaves **no** `.dira` directory behind at all — not the two drafts
  that wrote successfully before the failure — asserted by listing the target
  directory's contents before and after and finding it unchanged;
- called on a directory that **already has** a `.dira`, `InitLedger` refuses before
  writing anything and the existing `.dira`'s contents are byte-identical afterwards
  (sha256 over the whole tree) — this command seeds a fresh ledger, never merges into
  one, unlike `dira install-hooks`'s merge-never-clobber contract, which this
  deliberately does not copy;
- `TestNoFilesystemImportsAboveTheBackend` (`internal/ledger`) still passes with this
  file added, and `internal/ledger/local` needed no new allowlist entry — it already
  has one.

**Both sides:** the partial-failure clause is proven able to fail — a naive
write-each-draft-as-you-go implementation is exercised in the same test (a small
inline variant, or a flag forcing the real function to skip its own rollback step)
and shown to leave two of four entry files behind, before the real all-or-nothing
version is shown to leave none. The empty-`.dira`-directory assertion after a failure
is the one L-0001 rule 1 calls out by name: an assertion of the shape "no leftover
entries" would pass vacuously if `InitLedger` created no `.dira` at all on *every*
call, so the success-path bullet (a `.dira` that **does** get created and **is**
readable) is asserted in the same test run.

**depends_on:** none · **verifies:** `dec-0010` ("no successful init produces an
empty ledger" — restated here as its strict converse: no *unsuccessful* attempt
produces a non-empty one either)

### E5-L5-T3 — Wire `dira init --interview`: stdin-driven, fails closed, never partial

**Files:** `cmd/dira/init.go`, `cmd/dira/init_test.go`, `cmd/dira/main.go` (the one
registry line only, per the lane's shared protocol with `docs/plan/tasks/E2-L3.md`)

**acc:** `go test ./cmd/dira -run TestInitInterview` passes, run against an injected
temp working directory so no test ever touches a real repository:

- `dira init --interview` fed a complete scripted answer set on stdin (the exact
  fixture T1's test data uses) exits **0**, prints the path it created, and a
  `dira brief` run immediately afterward from that directory (a second, real
  in-process call, not a canned string) produces non-empty output naming at least one
  of the drafts' titles — the lane's own "the brief run immediately afterwards is
  non-empty" clause, checked by actually running `brief` rather than asserting the
  ledger merely has files in it;
- the same run fed an **incomplete** answer set (stdin closes after the second
  prompt) exits **non-zero**, and the target directory holds **no** `.dira` at all —
  asserted by listing the directory, not by checking a specific file's absence;
- a `--tier` mismatch between the flag and what the script would otherwise infer is
  rejected before any prompt is asked, at exit **2** (misuse, `docs/lore.md` L-0020's
  convention: a mistyped flag is 2, dira failing to complete real work is 1);
- running `init --interview` a second time against a directory that already has a
  `.dira` exits **1** with one line on stderr naming the existing ledger, and writes
  nothing — asserted by a whole-tree digest of the existing `.dira` taken before and
  after;
- the whole suite is run with the injected root set to a temp path and fails if
  anything under the real `$HOME` or the process's real working directory was created
  or modified — the same assertion `docs/plan/tasks/E2-L3.md`'s T6 makes for
  `install-hooks`, reused here because the hazard (a command that creates files) is
  the same shape;
- the verb appears in `dira --help` because it is registered in `newApp(...).commands`
  — the existing help test (`cmd/dira/registered_test.go`, L-0027's fix) already
  iterates the registry, so no separate help assertion is written here, and this
  clause exists specifically so L-0027 cannot happen a fourth time: `go test
  ./cmd/dira -run TestRegisteredCommandsAreReachable` (or whatever `registered_test.go`
  names its check) passes with `init` counted.

**Both sides:** the "no `.dira` on abort" clause is proven able to fail against a
version of `init.go` that writes drafts as they are collected rather than buffering
until T2's `InitLedger` is called once at the end — exercised as a subtest using T1's
`Build` directly wired to `Store.Create` per-answer, shown to leave partial files,
before the real implementation (buffer everything, call `InitLedger` once) is shown
to leave none. The `$HOME`-untouched clause carries its own red control, copied from
`install-hooks`'s precedent: pointed at the real home directory in a subtest skipped
by default, and shown to trip.

**depends_on:** E5-L5-T1, E5-L5-T2 · **verifies:** `dec-0010`, `dec-0003` (the
interview loop's only I/O is one stdout prompt and one stdin read per question — no
network call, no API key read, asserted by running the whole suite with no network
access, which nothing in this repository's test setup grants anyway)

### E5-L5-T4 — Prove every produced entry validates against the JSON Schema, not just Go's own rules

L-0015 exists for exactly this gap: `ValidateDraft` is dira's own Go rules, and they
have drifted from `entry.schema.json` before nothing forces the two to agree on a
freshly-authored entry the way they do for entries read back off disk (which
`internal/ledger/schema_test.go`, if it exists, already covers for the read path —
this task is the write path's equivalent).

**Files:** `cmd/dira/init_schema_test.go`

**acc:** `go test ./cmd/dira -run TestInitEntriesValidateAgainstSchema` passes:

- every entry file `dira init --interview` writes for T1's complete scripted answer
  set is read back and validated with `schema.NewValidator()` /
  `validator.Validate(content)` (`schema/schema.go`) — the same helper
  `internal/ledger/schema_test.go`'s `TestValidateAgreesWithTheSchema` uses for the
  read path, which already calls `AssertFormat()` internally (L-0015's fix — without
  it an unquoted `created` timestamp would validate cleanly against `"format":
  "date-time"` and this test would certify nothing). This task reuses that helper
  rather than standing up a second schema compiler;
- the test fails if fewer than 3 entry files were validated — an empty or
  short-circuited read would otherwise satisfy "every entry validates" vacuously
  (L-0001 rule 1);
- a deliberately corrupted copy of one written entry (an `id` whose prefix does not
  match its `kind`, constructed by the test) is validated against the same schema and
  is shown to **fail**, proving the compiler is actually checking these bytes and not
  returning a cached success.

**Both sides:** the corrupted-entry subtest is the red control; the untouched
freshly-written entries are the green case, both run against the same compiler
instance in the same test.

**depends_on:** E5-L5-T3 · **verifies:** `dec-0010` (a ledger that validates is what
"successful" means here — an init that wrote unschema-valid files would not count)

Four tasks: the pure script-and-builder (T1), the storage primitive it needs and does
not yet have (T2), the CLI that composes them under the all-or-nothing rule (T3), and
the schema-drift proof T3's own fixture makes possible for free (T4). None felt large

their own single-purpose tasks.

## What this lane does not own

**Import — reading an existing ADR/decision corpus into a ledger — is excluded**, per
the lane's own risk note and `dec-0028`/`qst-0003`. Nothing in this lane's `internal/
interview` package reads any file the operator did not type in answer to a prompt.

**A repo-tier `dira init`** (seeding `.dira/` for a plain codebase, as opposed to a
person or workspace ledger) is not this lane's scope either — the lane header says
"seeds a workspace or personal ledger," and `dira log --stdin` already seeds a repo
ledger's first entry today without a dedicated `init` verb. Whether a repo tier
eventually wants its own `--interview` form is a question for whoever revisits this
lane, not a gap silently left open here.
