## What is already known, so no task re-derives it

**E1's inbound-edge index exists and is queryable — confirmed by reading the source, not
assumed.** `internal/index/query.go:116`:

```go
// In returns the edges pointing at id, ordered by the entry that declares them
// and then by that entry's own edge order.
func (ix *Index) In(ctx context.Context, id string) ([]Backlink, error)
```

with `Backlink{From, Type ledger.EdgeType, Note string}` (`query.go:39`). This is exactly
the API `DecisionBlocked` (T4) needs: a question `qst-X` declares `blocks → dec-Y` on its
own file, so `dec-Y`'s inbound edges — never `dec-Y`'s own, which the schema's own comment
says edges are never stored on the object side — are `ix.In(ctx, "dec-Y")`, filtered to
`Type == ledger.EdgeBlocks` and `From`'s entry `State == ledger.StateOpen`. **No task in
this lane builds a second index.** `internal/index` is already on `cst-0004`'s and
`dec-0005`'s allowlist for its own filesystem needs (`internal/ledger/boundary_test.go:51`);
this lane consumes it through `*index.Index`, never opens a file itself, and needs no
allowlist entry of its own.

**The real ledger already contains a live `blocks` example**, useful for a sanity fixture
though not for the committed corpus (see T2's note on why the corpus is a frozen copy, not
a live read): `.dira/entries/qst-0005.md` carries `edges: [{type: blocks, to: dec-0008}]`
and `.dira/entries/qst-0003.md` carries a `blocks` edge of its own. Both are `state: open`
questions, so both are live examples of exactly T4's target shape.

**The entry and edge types this lane reads, already defined by E1** (`internal/ledger/entry.go`):
`Entry{ID, Kind, Title, State, Edges []Edge, ...}`, `Edge{Type EdgeType, To, Note string}`,
`Kind.States()` naming which `State` values are legal per kind (`KindIntent` →
`active|achieved|abandoned`; `KindDecision` → `accepted|rejected|superseded|staged`;
`KindQuestion` → `open|answered`). This lane imports `internal/ledger` for these types and
`internal/index` for `*index.Index`, `index.Selector` and `index.Backlink` — nothing else.

**The shared types this lane owns, fixed here so E4-L3 needs no conversation with this
lane's implementer** (T1's deliverable, `internal/status/types.go`):

```go
package status

// Bucket is dira's six-value derived-status vocabulary (dec-0004's join
// table, read top to bottom). It shares no value with ledger.State: a
// ledger.State describes the entry FILE (accepted, active, open); a Bucket
// describes where that entry sits once joined against kazi, or — for the two
// rows this lane derives — against nothing but the ledger itself.
type Bucket string

const (
	ToBePlanned      Bucket = "to_be_planned"
	Planned          Bucket = "planned"
	InProgress       Bucket = "in_progress"
	Completed        Bucket = "completed"
	ExecutionBlocked Bucket = "execution_blocked"
	DecisionBlocked  Bucket = "decision_blocked"
)

// Buckets lists the six in dec-0004's table order. len(Buckets) == 6 is
// asserted by T1's test directly — the CLI (E4-L4) ranges over this slice
// rather than a literal switch, so a seventh bucket cannot be added without
// this test naming it.
var Buckets = []Bucket{ToBePlanned, Planned, InProgress, Completed, ExecutionBlocked, DecisionBlocked}

// Source names what produced a Row's bucket. This lane only ever sets
// SourceLedger; E4-L3's join.go sets the other two. Defined here, not there,
// so E4-L3 has no reason to touch types.go.
type Source string

const (
	SourceLedger     Source = "ledger"        // to_be_planned / decision_blocked / terminal — no kazi call made
	SourcePortfolio  Source = "kazi portfolio" // E4-L3
	SourceKaziStatus Source = "kazi status"    // E4-L3
)

// A Row is one entry's derived status.
type Row struct {
	ID     string
	Kind   ledger.Kind
	Title  string
	Bucket Bucket
	Source Source

	// BlockedBy is set only when Bucket == DecisionBlocked: the blocking
	// question's id and title (the lane acc: line's "naming the question's
	// id and title" clause).
	BlockedBy *BlockingQuestion

	// Evidence, Ambiguous and Unresolved are E4-L3's fields (Completed
	// evidence-by-reference, and the two non-guess reports). This lane
	// never sets them; they are declared here so the struct shape is fixed
	// once, not extended by E4-L3 in a second file that redeclares Row.
	Evidence   *KaziEvidence
	Ambiguous  *AmbiguousDetail
	Unresolved *UnresolvedDetail
}

type BlockingQuestion struct{ ID, Title string }
type KaziEvidence struct{ RunID, ReleaseRef string }
type AmbiguousDetail struct{ Statuses []string }
type UnresolvedDetail struct{ Ref, Reason string }

// TerminalGroup is a ledger-only lifecycle end-state that predates any kazi
// join: an intent achieved or abandoned by ledger record alone. Not one of
// dec-0004's six buckets — an achieved intent needs no goal and is not
// "to be planned," so it is reported separately rather than forced into
// either.
type TerminalGroup string

const (
	Achieved  TerminalGroup = "achieved"
	Abandoned TerminalGroup = "abandoned"
)

type TerminalRow struct {
	ID, Title string
	Group     TerminalGroup
}
```

### E4-L2-T3 — `ToBePlanned` derivation

An accepted decision or active intent with no outgoing `realized_by` edge is `ToBePlanned`.
An entry that **does** carry a `realized_by` edge is excluded here even when nothing else
in this lane can say what it resolves to — that is deliberate: it is not to-be-planned, it
is *unknown until E4-L3 joins it*, and a `ToBePlanned` implementation that includes it
because "nothing else claimed it yet" would make E4-L3's degraded-join guarantee
(an entry with `realized_by` is never demoted to `ToBePlanned` when kazi is unavailable)
impossible to hold, because this function would already have put it there.

**Files:** `internal/status/ledger.go`, `internal/status/ledger_test.go`

**acc:** `go test ./internal/status -run TestToBePlanned` passes over T2's fixtures:
`no-realized-by/`'s decision and intent both appear as `Row{Bucket: ToBePlanned, Source: SourceLedger}`;
`real-snapshot/`'s entries carrying a `realized_by` edge (there is at least one — this
project's own `.dira/entries/dec-0060`-style edges, confirm the actual id at authoring
time) are **absent** from the result, asserted by id rather than by count; a `rejected` or
`superseded` decision and an `achieved`/`abandoned` intent are also absent (they are
neither to-be-planned nor any of the other five buckets — `superseded-target/` and
`achieved-intent/`/`abandoned-intent/` supply these); and running `ToBePlanned` twice over
the same fixture returns rows in the same order both times (`ID` ascending, or whatever
total order is chosen — the point is that it is total, not "whatever the map iteration
gave this run").

**Both sides:** the `realized_by`-exclusion clause is proven able to fail against a
mutated copy of `no-realized-by/`'s decision with a `realized_by` edge added, asserting it
now does **not** appear in the result, and proven to pass on the untouched fixture where it
does.

**depends_on:** E4-L2-T2 · **verifies:** `dec-0004`

### E4-L2-T4 — `DecisionBlocked` derivation, the load-bearing row

The one row no execution tracker can produce, and the cheapest to get subtly wrong: the
`blocks` edge lives on the **question's** file, so an implementation that inspects only
`dec-X` and finds nothing on it will report `ToBePlanned` — plausible-looking, and the
precise failure the bucket exists to prevent. Use `ix.In(ctx, "dec-X")`, filter to
`Type == ledger.EdgeBlocks` and the declaring entry's own `State == ledger.StateOpen`, and
exclude any candidate whose own state is `superseded` (or any other non-live decision
state — the acc line names `superseded` explicitly; a decision that is `rejected` is
already not a candidate because it is never `ToBePlanned` either, per T3).

**Files:** `internal/status/blocked.go`, `internal/status/blocked_test.go`

**acc:** `go test ./internal/status -run TestDecisionBlocked` passes over T2's fixtures:

- `real-snapshot/`'s `qst-0005 → dec-0008` edge produces a `Row{ID: "dec-0008", Bucket: DecisionBlocked, BlockedBy: &BlockingQuestion{ID: "qst-0005", Title: "..."}}` — the title asserted equal to `qst-0005`'s actual `Title` field, read from the entry, not hardcoded in the test;
- `answered-question/`: with the blocking question's `state: answered`, the target produces
  **no** `DecisionBlocked` row; a second sub-test flips only that one field back to `open`
  in a mutated in-memory copy (or a paired fixture) and asserts the row reappears, "with no
  other diff" checked by comparing every other field of the row before and after;
- `superseded-target/`: the blocked entry's own `state: superseded` suppresses the row even
  though the blocking question is `open`;
- **the naive-implementation control, run inline in the test rather than committed as
  production code:** a deliberately wrong resolver defined in `blocked_test.go` that reads
  only the candidate entry's own `Edges` (never `ix.In`) is run over the same fixtures and
  asserted to find **zero** `DecisionBlocked` rows where the real implementation finds at
  least one — proving the "without `dec-X` itself carrying any edge" clause is not
  vacuously true of any resolver, only of ones that get it wrong;
- a decision blocked by **two** open questions (a fixture case this task adds beyond T2's
  named set, since the lane acc line implies but does not enumerate it) produces one row
  per blocking question, not one row picking arbitrarily — or, if the design instead
  chooses one `Row` with multiple `BlockedBy` entries, `BlockedBy` is a slice and this
  clause is rewritten accordingly; whichever shape is chosen, the test asserts neither
  question is silently dropped.

**Both sides:** the naive-resolver control above **is** the red side, run against every
fixture in the corpus, not just the one with a blocking edge — it must produce zero rows on
`answered-question/` and `superseded-target/` too, for the boring reason (no live block),
which distinguishes "the naive resolver is wrong" from "the naive resolver happens to
agree by accident on the trivial fixtures." The `open`↔`answered` flip is its own
two-sided pair, explicit in the second bullet above.

**depends_on:** E4-L2-T2 · **verifies:** `dec-0004`, `schema/entry.schema.json`

### E4-L2-T6 — The no-subprocess structural proof

`internal/status` derives everything from the ledger and the index; it must never be able
to shell to `kazi`, because that capability belongs to `internal/kazi` alone (E4-L1) and
this lane's whole reason to exist is that it answers two buckets **without** kazi.

**Files:** `internal/status/boundary_test.go`

**acc:** `go test ./internal/status -run TestNoSubprocess` passes: `go list -deps
./internal/status`'s output (captured via `os/exec` **from the test**, which is fine — the
rule constrains the package under test, not the test harness, mirroring
`internal/ledger/boundary_test.go`'s own precedent) does not contain `os/exec`; and the
full `go test ./internal/status -run 'TestLedger|TestDecisionBlocked'` suite (the lane
`acc:` line's exact invocation) is run a second time with `PATH` set to an empty temp
directory and still passes — proving no test in this package accidentally depends on a
`kazi`, a `go`, or any other executable being resolvable, which is what an emptied `PATH`
without a passing suite would reveal.

**Both sides:** the `go list -deps` assertion is proven able to fail by a throwaway
`internal/status/poison_test.go`-shaped source added temporarily to a scratch copy of the
package (not committed) that imports `os/exec` and observing the check name it, mirroring
how `internal/ledger`'s own boundary test is itself proven able to fail per that file's own
precedent — record in the test's comment that this was checked, since the poison file
itself must not land in the tree.

**depends_on:** E4-L2-T3, E4-L2-T4, E4-L2-T5 · **verifies:** `dec-0004`
