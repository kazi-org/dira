## What is already known, so no task re-derives it

**There is no model client in the binary and there is no network** (`dec-0003`,
`cst-0004`). Tier 2 is the Claude session that is *already running with the transcript in
context*. The handoff is a block of text on stdout that a skill picks up; it is not an API
call, and no task here adds one. `dira sniff --deep` cannot ask the session anything — it
is a subprocess.

**E2-L1 landed and this lane builds on it, not beside it.** `dira sniff` is at
`cmd/dira/sniff.go` and `internal/sniff/`. The tier's may-only-ever-stage rule is
enforced **structurally**, not by convention: `sniff.Stage` wraps the caller's
`ledger.Store` in a `stagedOnly` (`internal/sniff/stage.go:193`) whose `Put` and `Delete`
always refuse and whose `Create` rejects anything that is not staged / decision-kind /
regex-tier / from a capture hook. `--deep` writes through that same wrapper. Any task
that routes around it has broken the lane it depends on.

**The schema question E2-L1 settled, and the part it left open for this lane.**
`state: staged` is legal only on `kind: decision`, and the `alternatives` `minItems: 1`
floor is lifted for a staged decision — *deliberately, so the semantic tier can fill in a
`why_not` on an entry that is still staged* (`docs/decisions-pending/E2-L1-report.md`
§6.1 and its note to E2-L2). What forbids tier 1 from writing alternatives is `mustStage`,
which is `internal/sniff`'s rule, not the schema's. So the semantic tier adds
alternatives through `dira log`, never through the sniff writer.

**`dira log` already accepts everything the skill needs**, so nothing here reimplements
entry writing (`cmd/dira/log.go`): `--kind`, `--title`, `--state`, `--body`,
`--alternative` / `--why-not` / `--revisit-if` (positional, repeatable),
`--edge TYPE=TARGET`, `--edge-note`, `--hook`, `--session`, `--excerpt`, `--tier`,
`--confirmed-by`, `--stdin`, `-C`.

**Why this lane blocks E2-L3.** `hooks/settings.example.json`'s `PreCompact` block writes
`dira sniff --deep --stage 2>/dev/null || true`. E2-L3's `acc:` clause (f) requires that
*every command string the installer writes is accepted by the built binary*. Today
`--deep` is not a registered flag, so that command exits 2. E2's lane file records the
dependency correction made 2026-07-31. **T3 is the task that unblocks E2-L3**, and its
`acc:` says so in a form E2-L3 can re-run.

**The verification standard this lane is held to** (`docs/lore.md` L-0001): a gate is
evidence only once **both** sides have been observed — red on a constructed defect of the
class it claims to catch, **and** green on the untouched correct baseline. Rule 2 is the
one nobody applies, and this lane is full of extract-then-assert checks (T5, T7) where an
extractor that finds nothing passes silently and looks identical to a clean repo. Every
such task below carries both sides in its `acc:`. E8-L5-T7 already paid for the specific
variant that bites here: a scanner that flags its own source, fixed with a **named**
exclusion list rather than a string-splitting trick that was tried first and failed the
same run.

### E2-L2-T2 — Pin the handoff block as a golden format, bounded and redacted

The block `--deep` emits is a contract between the binary and the skill, so it is a golden
file rather than free prose that drifts.

**Files:** `internal/sniff/handoff.go`, `internal/sniff/handoff_test.go`,
`internal/sniff/testdata/handoff.golden`

**acc:** `go test ./internal/sniff -run TestHandoffGolden` passes:

- the block rendered for a 3-candidate fixture matches `testdata/handoff.golden`
  **byte-for-byte**, and it names all three staged ids;
- it names `alternatives`, `why_not` and `derives_from` **literally**, and carries the
  exact `dira log` invocation shape the session is to call back with — using only flags
  `cmd/dira/log.go` actually defines (T5 is the mechanical check of that; this task must
  not invent one);
- it is **≤400 tokens by `brief.Tokens`** — the binary's own counter, the same one
  `cst-0001` is enforced with — *regardless of candidate count*, degrading to ids-only
  past a fixed candidate count rather than growing without bound. This text lands in a
  context window that is about to be compacted precisely because it is full, so the bound
  is the point, not a formality;
- it contains **no API key, no URL and no model name**, asserted by pattern;
- rendered from `internal/sniff/testdata/transcripts/with-credentials.jsonl`, it contains
  **none of that fixture's secret literals** — the handoff goes through the same
  redaction the excerpt path already uses (`internal/sniff/redact.go`), not a second
  implementation of it;
- and the shape it describes reflects **T1's finding** about where this text is delivered.

**Both sides, per L-0001:** the golden comparison is proven able to fail (one byte changed
in the renderer turns it red naming the diff) **and** proven able to pass on the untouched
tree; the ≤400-token bound is proven able to fail by rendering a 50-candidate fixture
against a build with the degradation removed; and the credential assertion is proven able
to fail against a build with redaction bypassed. A pattern assertion over a block that
rendered empty is worthless, so the test fails if the rendered block is empty or names
zero ids.

**depends_on:** E2-L2-T1 · **verifies:** `dec-0003`, `cst-0001`

### E2-L2-T3 — Wire `--deep` so tier 1 always runs first and tier 2 is additive

`--deep` never replaces the regex pass. It stages exactly what `dira sniff --stage` would
— E2-L1's writer, through the same `stagedOnly` wrapper, unchanged — and then emits the
handoff. A `PreCompact` with no live cooperation therefore still loses nothing tier 1
could catch, which is what makes it an insurance policy rather than a gamble.

**Files:** `internal/sniff/deep.go`, `internal/sniff/deep_test.go`, `cmd/dira/sniff.go`
(the flag, its usage line, and the dispatch only)

**acc:** `go test ./internal/sniff -run TestDeepHandoff` passes:

- on `internal/sniff/testdata/transcripts/pre-compact.jsonl`, `dira sniff --deep --stage`
  writes **exactly the same entry set** as `dira sniff --stage` on the same fixture —
  asserted by comparing the two resulting ledgers file-by-file, not by counting — **and**
  additionally emits T2's handoff block on stdout;
- every entry it writes is still `state: staged`, `source.tier: regex`,
  `source.hook: PreCompact`, with a non-empty bounded `source.excerpt` and **no**
  `alternatives[]`. `--deep` does not upgrade the tier of anything it stages; the semantic
  tier's output arrives later, through `dira log`;
- with `--deep` and a fixture yielding zero candidates (`no-decisions.jsonl`) it emits **no
  handoff block** and exits 0 with empty stdout under `--quiet`;
- it **exits 0 and still stages the regex candidates even when handoff rendering is forced
  to fail** — the hook's job is to not lose the session, and a broken renderer must not
  cost the capture;
- it completes in under 10 seconds on the fixture, inside the `PreCompact` hook's 60 s
  budget declared in `hooks/settings.example.json`;
- and **the E2-L3 unblock is asserted here, in a re-runnable form**: the exact string
  `hooks/settings.example.json` installs for `PreCompact` — `dira sniff --deep --stage` —
  is accepted by the built binary and exits 0. Before this task, that command exits 2 with
  a usage error; the test transcript records both the before and the after.

**Both sides:** the ledger-equality assertion is proven able to fail (a build where
`--deep` skips the regex pass turns it red) and proven able to pass on the untouched tree;
and the zero-candidate case is distinguished from "the sniffer found nothing because the
plumbing is broken" by asserting the positive fixture stages ≥1 entry in the same test
run.

**depends_on:** E2-L2-T2 · **verifies:** `dec-0003`, `int-0002`

### E2-L2-T4 — Write the skill

The skill is the tier-2 worker: it reads the handoff, fills in the because, the
alternatives with their `why_not`s, and the `derives_from` edge, then calls `dira log`. It
also carries the `qst-0005` fallback — wrapping `kazi approve` / `kazi reject` so a
disposition still gets logged while kazi has no post-disposition hook — and it runs
`dira check` before planning, per `docs/design.md` §10 step 4. (`dira check` is E3's and
already landed; the skill names it, this lane does not build it.)

**Two hard rules for the text.** It never instructs the model to invent a `why_not` that
was not said in the session — a fabricated rationale is worse than an absent one, because
it will be quoted back at the user as their own reasoning three weeks later. And it never
tells the model to call a network service (`cst-0004`).

**Files:** `skills/dira/SKILL.md`

**acc:** `go test ./internal/skill -run TestSkillShape` passes: `skills/dira/SKILL.md`
exists; its YAML frontmatter parses with non-empty `name` and `description`; the
description names the triggering conditions (a handoff block, a `PreCompact`, a
disposition); the body contains a literal `dira log` invocation and a literal `dira check`
invocation; it instructs writing `--tier semantic` and never `--confirmed-by human` (only
a human disposition may set that — E2-L4's verb, not this skill's); and it contains no
API-key environment variable name, no `http://` or `https://` call instruction, and none
of the words `.agents/product-marketing.md` §10 bans (`revolutionary`, `seamless`,
`supercharge`, `10x`, `AI-powered`) — asserted by pattern.

**Both sides:** each pattern assertion is proven able to fire against a spliced copy of the
skill carrying the banned thing, and the whole test is proven able to pass on the real
file. A frontmatter parser that silently returned an empty document would satisfy every
"contains no X" clause, so the test fails first if `name` or `description` is empty.

**depends_on:** E2-L2-T2 · **verifies:** `dec-0003`, `cst-0004`

### E2-L2-T5 — Test that the skill names only real commands and real flags

kazi already proved this test earns its keep
(`test/kazi/teach/skill_covers_commands_test.exs`): a skill that instructs the model to
run a verb the binary does not have produces a silent capture failure that looks like a
model mistake.

**A correction to the prompt's file assignment, stated rather than silently applied.**
`docs/plan/prompts/L2-E2-L2.md` puts this test at `internal/skill/covers_test.go`. It
cannot live there: the command registry is `newApp(...).commands` in
`cmd/dira/main.go`, unexported and in package `main`, so no `internal/` package can
enumerate it. Enumerating it by re-listing the verbs in a slice inside `internal/skill`
would be a check that validates a declaration rather than a result — L-0001's closing
line. So: the **extractor** is `internal/skill/extract.go` with its own unit tests in
`internal/skill`, and the **assertion against the real registry** is
`cmd/dira/skill_covers_test.go`, in package `main`, where the registry and every
command's `flag.FlagSet` are reachable. The lane's `acc:` names the packages that must
pass, and this adds one; it removes nothing.

**Files:** `internal/skill/extract.go`, `internal/skill/extract_test.go`,
`cmd/dira/skill_covers_test.go`

**acc:** `go test ./internal/skill ./cmd/dira -run
'TestExtractInvocations|TestSkillCoversCommands'` passes: every `dira …` invocation
extracted from `skills/dira/SKILL.md` resolves to a command registered in
`newApp(...).commands`, with every flag accepted by that command's own flag set.

**Both sides, and this is the task where rule 2 matters most:**

- **Red:** a deliberately invented verb (`dira frobnicate`) and a deliberately invented
  flag (`dira log --magic`), each spliced into a *copy* of the skill, each turns the test
  red with a message naming the offending token.
- **Green:** the untouched `skills/dira/SKILL.md` passes.
- **Not vacuous:** the test fails if the extractor returns **zero** invocations, and
  asserts the extracted set contains at least `dira log` and `dira check`. An extractor
  whose regex stops matching finds nothing and passes every "all of them resolve" clause —
  that is the exact shape of the five rule-1 instances `docs/lore.md` L-0001 lists.

### E2-L2-T6 — Replay a recorded skill output end to end into a validated entry

The tier-2 path cannot be tested with a live model, so record one. Capture a real
session's response to a real handoff block, store it as testdata, and replay the `dira log`
invocation it produced. This is what makes the tier-2 half of the lane's `acc:` falsifiable
rather than aspirational.

**Files:** `internal/skill/testdata/skill/handoff-response.txt`,
`internal/skill/testdata/skill/expected-entry.md`, `internal/skill/replay_test.go`

**Path note:** the lane's `acc:` says "replayed verbatim from `testdata/skill/`". The
fixtures therefore sit at `internal/skill/testdata/skill/`, which satisfies that string
literally as well as the prompt's `internal/skill/testdata/`. Cheaper than arguing about
which reading was meant.

**acc:** `go test ./internal/skill -run TestReplay` passes: the `dira log` invocation is
extracted from the recorded response and executed **against the built binary** (built with
`go build -o <tmp>/dira ./cmd/dira`, skipping where there is no `go` on `PATH`, as
`cmd/dira/build_test.go` does) into a temp ledger — replaying it through an in-process
helper would test a code path the skill does not use. The resulting entry:

- validates against `schema/entry.schema.json`;
- has `source.tier: semantic` and `source.hook: PreCompact`;
- has ≥1 `alternatives[].why_not`, each non-empty;
- has a `derives_from` edge and a non-empty markdown body;
- has `confirmed_by` **absent or not `human`** — the semantic tier proposes, a human
  disposes (E2-L4);
- and matches `testdata/skill/expected-entry.md` on every field except the allocated id
  and the timestamps.

**Both sides:** replaying a mutated response whose `why_not` is empty is **rejected by
`dira log` with a non-zero exit** and writes no file — asserted, not assumed; and the
unmutated response produces the entry and exits 0. The test fails if the extractor found
no invocation to replay, for the same reason as T5.

**depends_on:** E2-L2-T4 · **verifies:** `dec-0003`

### E2-L2-T7 — Make `dec-0003` a build-time invariant: no model client, no API key

The constraint most likely to be violated by a well-meaning later change ("just add a
fallback extractor") is the one with no test. Give it one.

**Files:** `internal/nomodel/nomodel_test.go`, `internal/nomodel/scan.go`

**acc:** `go test ./internal/nomodel` passes with two independent checks:

1. **Linkage.** `go list -deps ./cmd/dira` is filtered to **non-stdlib module paths** and
   fails on any match against a denylist covering the known model-provider SDKs
   (`anthropic`, `openai`, `google.golang.org/genai`, `cohere`, `mistral`, `ollama`) and
   any module whose path contains `sdk-go` under a provider host. The check runs for a
   stated `GOOS`/`GOARCH` matrix rather than only the host's — `docs/lore.md` L-0008 is
   exactly this bug: an allowlist right on a Mac was stale on Linux and CI's first ubuntu
   run caught it.
2. **API keys.** Every non-`_test.go` file under the module is scanned and any occurrence
   of an API-key environment variable name (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, and
   `*_API_KEY` by pattern) fails the test. The scanner's own source and its own fixtures
   necessarily contain those literals, so they are excluded by a **named list of file
   paths**, not by a string-splitting trick — E8-L5-T7 tried the trick first and it failed
   the same run (`docs/decisions-pending/E8-L5-report.md`).

**Do not denylist stdlib network packages.** `cmd/dira` legitimately links `net`,
`net/http` and `crypto/tls` today, reachable through `internal/ui`, which serves the
read-only localhost UI (`go list -deps ./cmd/dira | grep -c '^net/http$'` returns 1). A
check phrased as "no network packages linked" would be **red on a correct binary**, which
is L-0001 rule 2 in its purest form. `dec-0003` forbids a model client, not a socket; the
socket question is E1-L6-T3's, measured at runtime.

**Both sides:** both checks are proven able to fail against inline fixtures — one carrying
a denylisted module path, one carrying `os.Getenv("ANTHROPIC_API_KEY")` — **and** proven
to pass on the untouched module. Each also fails if its input set is empty: zero modules
listed, or zero files scanned, is a scanner that broke, not a clean repo.

**depends_on:** none · **verifies:** `dec-0003`, `cst-0004`

**Both sides:** the no-clobber rule is proven by modifying the installed file and
observing the second install refuse it by name, **and** by observing an unmodified second

every second run looks identical to one that protects edits.

## One `acc:` clause that may not survive T1's finding, flagged not softened

The lane's `acc:` requires that `dira sniff --deep --stage` "emits a handoff block on
stdout naming each staged id plus the fields the live session must fill". That clause is
mechanically testable regardless — a block on stdout is a block on stdout, and T2 and T3
assert it as written. What T1 may falsify is the *claim around* it: that emitting the
block on `PreCompact` stdout causes the live session to act on it. If `PreCompact` stdout
is discarded, the `acc:` still passes honestly while the **insurance policy is weaker than
`hooks/settings.example.json` claims**, and the correct response is T1's comment
correction plus a recorded entry — not a loosened test, and not a test that quietly keeps
asserting the stronger claim. This is written down on the way in because
`docs/plan/lanes/E2.md` records that one `acc:` in this epic has already been found
unpassable as scheduled, and that correction was recorded rather than made silently.
