**Status: not started.** Every `acc:` below is **red today** — `internal/chain` does

## What is already true, so no task re-derives it

- **The config surface this lane needs is already parsed.** `internal/config.Config`
  reads `[ledger].tier` and `[parents]` declarations in full — `path`, `ref`,
  `visibility`, `label` — including `dec-0011`'s `visibility = "private"` marker, and
  falls closed (`VisibilityPrivate`) on a value it cannot read
  (`internal/config/config.go:72-123,237-244`). This lane adds **no new config key**;
  the lane's ownership clause ("this lane owns the config keys") is satisfied by
  pointing at what E3-L3-T1 already built, not by adding a second reader.
- **The write guarantee is already a type.** `ledger.ReadOnly(inner Store) Store`
  (`internal/ledger/readonly.go`) refuses `Create`/`Put`/`Delete` before the inner
  store is ever reached and wraps `ErrReadOnly`. This lane wraps every store it opens
  in it; it does not reimplement the refusal.
- **The path arithmetic is already a backend function.** `local.ParentDira(diraDir,
  declared string) string` joins a `[parents]` declaration's `path` onto the
  declaring ledger's own `.dira` directory and appends `.dira`
  (`internal/ledger/local/local.go:452-454`). `local.Open` opens a store over an
  existing `.dira` directory and creates nothing; `local.ReadConfig` reads a ledger's
  `config.toml` bytes, returning `nil, nil` for a ledger with none. This lane calls
  these three functions; it does not reimplement path joining, and `path/filepath`
  therefore never has to appear in `internal/chain`'s own non-test files —
  `internal/ledger/boundary_test.go`'s `filesystemPackages` check runs over every
  package in the module and would fail this lane the moment it did.
- **A one-hop version of "open a declared parent" already exists, for a narrower
  purpose, and this lane does not duplicate it.** `internal/enforcer.Inherit` opens
  exactly the parents a child's own `[parents]` names, collects only their active
  constraints, and is `dira check`'s enforcement path — it does not walk into a
  *grandparent*, and it is not this lane's to change (`docs/plan/tasks/E3-L3.md`:
  "E5 builds namespaced ref resolution on this path. It resolves what is declared and
  present, and reports what is not; it holds no policy about what a public surface
  displays."). This lane is the general case that quotation describes: resolving one
  namespaced ref to the entry it names, at whatever depth in the chain declares it,
  for any consumer — `dira why`, E5-L3's drift flag, E5-L4's brief chain — not just
  `dira check`'s constraint set.
- **`ledger.ValidRef` already recognises a namespaced ref** (`sire:int-0002`) as
  distinct from a bare id (`internal/ledger/entry.go:236-248`). This lane's `Resolve`
  takes a ref already known to be well-formed; malformed input is the caller's
  problem, not this package's.

## The landmine this lane will hit if nobody names it

**L-0014, restated for a three-ledger fixture.** `local.Find` walks *up* from a
start path looking for the nearest `.dira`; a test that points a `chain.Resolve` at a
`testdata/` path directly, rather than a copy of it under a real temporary root, risks
silently resolving against whichever `.dira` happens to sit above the process's
working directory. Every task below builds its fixture by copying committed testdata
into `t.TempDir()` before opening anything, and constructs `me/`, `sire/` and `repo/`
as **sibling** directories under that temp root — the shape `local.ParentDira`'s
relative-path arithmetic assumes.

### E5-L2-T1 — Build the transitive parent walker, read-only at every hop

`dec-0006`'s own diagram is two hops deep (`kazi/.dira → derives_from: sire:int-… →
derives_from: me:int-…`), and a repository does not, in the common case, declare its
grandparent directly — `sire` declares `me`, not `kazi`. So the walk has to recurse:
starting from a ledger's own `[parents]`, open each declared parent read-only, read
*its* `config.toml`, and repeat, accumulating one `Ancestor` per namespace discovered
at any depth. Stop recursing at a hop that cannot be opened — its own further
ancestors are then unknowable, not absent — and refuse a namespace that would revisit
a `.dira` directory already in the chain, rather than recursing forever.

**Files:** `internal/chain/chain.go`, `internal/chain/chain_test.go`,
`internal/chain/testdata/fixtures/tier3/{me,sire,repo}/.dira/{config.toml,entries/*.md}`

**acc:** `go test ./internal/chain -run TestWalk` passes, against fixtures copied into
a fresh `t.TempDir()` per subtest (never pointed at `testdata/` directly, per L-0014):

- over the three-tier fixture — `repo/.dira` declaring only `sire` (not `me`), and
  `sire/.dira` declaring `me` with `visibility = "private"` and a relative `path` —
  `Walk(ctx, "<tmp>/repo/.dira")` returns two `Ancestor`s, `sire` then `me`, each
  opened through `ledger.ReadOnly`, `me`'s carrying `Tier: "person"` read from its own
  `config.toml`;
- with `me/` absent entirely (no directory, not even an unreadable one), `Walk`
  returns the `sire` ancestor with `Store` set and a `me` ancestor with `Store == nil`
  and a non-nil `Err`, and does **not** fail the whole walk — one unreachable ancestor
  degrades that ancestor, not the call;
- with `me/.dira` present but `chmod 000`, the same shape holds: `me`'s `Store` is
  `nil`, its `Err` is non-nil, and `sire`'s `Ancestor` is unaffected — asserted as a
  distinct subtest from the absent-path case, because a caller reporting "declared but
  unreadable" (withheld) must not read the same as "not there" without checking `Err`'s
  text, and the two are produced by different code paths (`os.Stat` failing inside
  `local.Open` vs. `local.Open` succeeding and a later read failing);
- a fixture where `me/.dira` declares `sire` as `me`'s own parent (a two-node cycle)
  returns a named error mentioning both directories, not a stack overflow or a hang —
  asserted with `go test -timeout 5s`;
- `Walk` over a `.dira` with an **empty** `[parents]` section returns zero ancestors
  and no error — the base case a recursive walker can get wrong by returning `nil,
  err` for "nothing to do";
- the whole run leaves every fixture ledger byte-identical: a sha256 over every file
  under `<tmp>/me`, `<tmp>/sire` and `<tmp>/repo` (including `.dira/cache/`, which is
  gitignored and invisible to a git-based check) taken before `Walk` and after it are
  equal in every subtest, including the ones that fail to open a hop.

**Both sides:** the cycle guard is proven able to fire — the two-node cycle fixture
above — and proven not to fire on the acyclic three-tier fixture, in the same test run,
so a guard that rejected every input could not pass. The "unreachable ancestor
degrades, not fails" clause is proven both ways too: the *absent-me* subtest asserts
`Walk`'s error return is `nil` and `sire`'s ancestor is still usable, which fails
immediately if `Walk` propagates `me`'s open failure as its own return error.

**depends_on:** none · **verifies:** `dec-0006` (the fractal chain), `cst-0003` rule 1
(downward only)

### E5-L2-T2 — Resolve one namespaced ref through the walked chain, three ways

This is the lane's own scenario, verbatim: `resolving me:int-0002 from repo/`. `Resolve`
splits the ref on its namespace, looks it up in T1's `Walk` result, and reports one of
three outcomes: the entry (namespace found, hop readable), the withheld state
(namespace found somewhere in the chain, but the ledger holding it could not be opened
here), or a named error (the namespace is not declared *anywhere* in the walked chain —
`dec-0011`'s "a typo or an invention", never treated as withheld, because that would let
a real mistake hide behind the privacy boundary).

**Files:** `internal/chain/resolve.go`, `internal/chain/resolve_test.go` (reuses
T1's `testdata/fixtures/tier3/`)

**acc:** `go test ./internal/chain -run TestResolve` passes, over the same three-tier
fixture copied fresh into `t.TempDir()` per subtest:

- with `me/` readable, `Resolve(ctx, "<tmp>/repo/.dira", "me:int-0002")` returns
  `State: Oriented` and the entry whose id is `int-0002`, read from `me`'s ledger —
  the lane's own literal scenario;
- with `me/` made unreadable (path absent, and separately `chmod 000` — both cases, as
  two subtests) the same call returns `State: Withheld`, a nil `*ledger.Entry`, and a
  **nil error** — `Resolve` reporting withheld is success, not failure, matching
  `dec-0018`: "withheld reads as neither an error nor a warning";
- a ref naming a namespace absent from the whole chain (`Resolve(ctx, repoDira,
  "nowhere:int-0001")`) returns a named error identifying the unrecognised namespace,
  and both `State` and the entry are zero values — this is the case `dec-0011`'s
  implementation notes single out as the one that must **not** read as withheld;
- after every subtest, `git status --porcelain` run in the fixture's checked-out
  location (the repo this test executes in, not the temp copy) is empty — nothing
  under version control was touched — and a canary string present only in
  `me/.dira/entries/int-0002.md`'s body is absent from every file under
  `<tmp>/repo/.dira/` after the call, checked with `grep -r <canary> <tmp>/repo/.dira/`
  finding nothing;
- `Resolve` called with a malformed ref (`ledger.ValidRef` false) returns a named error
  before `Walk` runs at all, asserted by a `Walk` call counter that stays at zero.

**Both sides:** the withheld/error distinction is proven able to invert — a build that
reports "undeclared namespace" as withheld would pass every withheld-shaped assertion
above and only the dedicated undeclared-namespace subtest would catch it, so that
subtest is run and shown to fail against a deliberately merged withheld/undeclared
branch before the real implementation is exercised. The canary-absence clause is
proven non-vacuous by first asserting the canary string **is** present in
`me/.dira/entries/int-0002.md` in the untouched fixture — an assertion against a
canary nothing carries would pass trivially.

**depends_on:** E5-L2-T1 · **verifies:** `dec-0011` (opaque refs, three-state
resolution), `cst-0003` rule 3 (ref-only citation across the boundary — a resolved
entry is returned to the caller, who decides what may render; `Resolve` itself never
truncates or redacts, matching `internal/enforcer.Inherit`'s split between "resolve"
and "render")

### E5-L2-T3 — Prove no hop can acquire a write path, adversarially

The lane's own risk: "the resolver acquiring a write path... a resolver that caches a
parent entry to disk under the child's tree satisfies every functional test and is a
security bug." T1 and T2 already assert byte-identical trees; this task adds the
assertion that is still missing after that — that **every** `Ancestor.Store` `Walk`
returns, at **every** depth, is the wrapped one, not the raw backend, checked directly
rather than inferred from an absence of side effects.

**Files:** `internal/chain/writesafety_test.go`

**acc:** `go test ./internal/chain -run TestNoHopCanWrite` passes:

- over the three-tier fixture, for **every** `Ancestor` `Walk` returns (`sire` and
  `me`), calling `.Store.Put(ctx, someEntry)` returns an error satisfying
  `errors.Is(err, ledger.ErrReadOnly)`, and the same holds for `.Create` and
  `.Delete` — nine assertions (two ancestors × three methods, plus the base case
  below), not one generic check that could pass by only exercising the leaf;
- the same three calls against a **`local.Store` opened directly** on the same `me/`
  directory (bypassing `Walk` entirely) succeed and actually write a file — the
  control proving the refusal above is `ledger.ReadOnly` doing its job and not, say,
  a filesystem permission the test environment happens to enforce;
- a deliberately broken variant of the walker — literally, a copy of `Walk`'s body
  in the test file with the `ledger.ReadOnly(...)` wrapper on the grandparent hop
  removed — is exercised in place of the real one and the first bullet's `me`-level
  assertions are shown to **fail** against it: `Put` on the unwrapped `me` ancestor
  succeeds and a file lands on disk, cleaned up by the test. This is the construction
  L-0001 asks for: the check is shown able to catch the exact defect it exists to
  catch, not just able to pass the real implementation.
- after every subtest, a sha256 over the fixture's `me/` and `sire/` directories
  (excluding the deliberately-broken subtest's own cleanup, asserted separately)
  matches the pre-run digest.

**Both sides:** the third bullet **is** the red side — a check that could only ever run
against the real `Walk` and see refusals would be evidence of nothing, per L-0001
rule 1. The first two bullets are the green side: refusal through `Walk`, and a
successful write through the same directory opened the ordinary way, in the same run,
so the refusal is shown to be `ledger.ReadOnly`'s doing and not an accident of the
fixture.

**depends_on:** E5-L2-T1 · **verifies:** `cst-0003` rule 1 ("dira has no verb that
writes upward")

## Not decomposed further

Three tasks cover the lane's whole surface: the walk (T1), the single-ref answer built
on it (T2), and the adversarial proof that the walk cannot be the write path `cst-0003`
forbids (T3). None felt too large for one converge run — the walk is one recursive
function over an interface already narrow (`ledger.Store`'s four methods), and the
resolve and write-safety tasks are each one function plus the test that forces it,
the same shape `docs/plan/tasks/E3-L3.md` used for its own read-only store (T2) and its
own leak proof (T6).

## What this lane does not own

**Rendering a resolved or withheld ref is not this lane's job.** `Resolve` returns
data; what a caller does with it — a citation line in `dira why`, a drift flag in
E5-L3, a chain block in E5-L4's brief, an `--ink-low` `unresolved` state in E6-L4's
public HTML — is each consumer's own policy. `cst-0003` rule 3's "ref only, never the
text" is enforced by what a *renderer* prints, not by what this package returns; this
lane returns the entry because withholding it from every caller, including ones with a
legitimate reason to read it (E5-L4's brief chain, which is not a public surface), would
be enforcing the rule in the wrong layer.

**`dira check`'s constraint inheritance (E3-L3) is not extended to walk multiple
hops by this lane.** `internal/enforcer.Inherit` still resolves only a child's own
directly-declared `[parents]`; a repo-tier `dira check` today does not see a
grandparent's constraints unless the repo also declares that grandparent's namespace
directly. Whether it should is a real question this lane surfaces but does not answer
— extending `Inherit` to consume T1's `Walk` is a natural follow-up and is recorded
here so it is a decision made in writing rather than an oversight discovered later.
