## What is already known, so no task re-derives it

**The write path is E2's, not this lane's.** `internal/distill` exports four
surface-independent functions, none with a terminal, an `io.Reader` or an
`io.Writer` in its signature (E2-L4-T4, E2-L4-T6, landed):
`Confirm(ctx, store, e, now) (*Disposition, error)`,
`Discard(ctx, store, e) (*Disposition, error)`,
`EditBody(ctx, store, e, editor BodyEditor, now) (*Edit, error)`, and
`Staged(ctx, store) (*Queue, error)`. **`internal/distill/edit.go`'s own package
comment already names this lane's shape:** *"`dira distill` reads `EditorVar`,
builds the `BodyEditor`, and hands it in; E6's web surface hands in a textarea; a
test hands in a fake."* T4 implements exactly that sentence. This lane calls these
four functions and writes nothing of its own — `internal/ui` is not on
`dec-0005`'s allowlist for `os` (`TestNoFilesystemImportsAboveTheBackend`), so a
second file-writing path here would not compile, which is the mechanical form of
the risk `docs/plan/lanes/E6.md` names for this lane: *"if this lane reimplements
disposition, two state machines exist and they will disagree."*

**The served index and decision pages already derive real roll-ups with no kazi
client**, and T1 depends on this being read correctly. `internal/ui/indexview.go`'s
`BuildIndex` computes `Settled`/`Moving`/`Staged`/`Open`/`Tracked`/`Percent` and the
dial's arc geometry from **ledger state and edges alone** — `ref.State`,
`EdgeDerivesFrom`, `EdgeBlocks`, `EdgeRealizedBy` — and states so in its own
`StatusNote`: *"No kazi join is available here, so these are the ledger's own
states."* None of that is invented and none of it needs E4. The mockups' "43%",
"6 converged / 4 in motion / 4 to be planned" and per-row "converged" / "in motion"
/ "to be planned" labels are **not** that computation — they are hand-picked
numbers with no fixture behind them (`docs/decisions-pending/E6-L2-report.md` §6.3)
and, separately, they use words ("converged") the served page reserves for a real
kazi join it does not have. Regenerating from what `BuildIndex` and `BuildDecision`
already, legitimately compute closes nearly all of the gap without any new
mechanism.

**The one place that is genuinely a kazi join is `realized_by`, and the served page
already refuses to invent it.** `internal/ui/view.go`'s `buildChain`: *"`dira` does
not ask kazi whether this converged and must not imply that it did (dec-0004), so
the row carries the target and the edge's own note and nothing else."* The fixture
entry the mockups draw this from, `dec-0001.md`, has a `realized_by` edge to
`kazi:prop-8a1f` with **no `note:` field** — so a correct render of that fixture
today shows the bare id and nothing else, not `s1-decision.html`'s "converged 3/3
predicates green". `edge.Note` (`internal/ledger/entry.go:162`, ≤280 runes) is a
general, already-schema-legal field for recorded prose on an edge — the same kind
of field `why_not` is. Adding one by hand to this one fixture edge, stating plainly
that it is a recorded annotation and not a live query, is the "fixture-level kazi
join" the founder decision names; a live, automatic version of the same join, for
a real ledger, is E4's job and is not this lane's to build.

**`s3-distill.html` has the same defect as `s1`/`s2`, in a form the report never
measured because the route did not exist yet.** `internal/distill.Staged` returns
only entries whose file says `state: staged`
(`internal/distill/queue.go:191`, `entry.State != ledger.StateStaged` skips
everything else) — never a `question`, and the package comment says why
("dec-0021 lets only decisions be staged"). Against the fixture ledger,
`grep -h '^state:' docs/design/fidelity/fixtures/ledger-design/entries/*.md` shows
**exactly two** entries at `state: staged` — `dec-0011`, `dec-0012` — not three.
`s3-distill.html`'s third card is `qst-0006`, `state: open`: a route built on
`Staged` structurally cannot ever show it there. **Second, and load-bearing for
T1:** `dec-0011.md` and `dec-0012.md` both carry `confirmed_by: "agent:claude-code"`
in their fixture frontmatter. `queue.go`'s `statusOf` reads any non-empty
`ConfirmedBy` as `StatusPendingExtraction`, not `StatusAwaiting`
(`internal/distill/queue.go:211-219`) — so **as the fixture stands today, neither
staged entry is actionable**, and the mockup's fully-actionable top card
(Confirm/Reject/Edit, all live) cannot be produced by `Staged` over this ledger at
all. T1 does not get to pick which side gives: it regenerates the mockup **and**
brings the two fixture entries into a shape `Staged` actually renders as an
actionable card, and says in its own commit which fields it touched and why —
because a fixture entry is drawn from by name in `fixture-check.mjs`, and this is
exactly the kind of drift that check exists to stop reappearing.

**`internal/ui`'s no-`<script>` claim is package-wide today and T5 narrows it.**
`internal/ui/assets.go`'s package comment: *"this package emits no `<script>` at
all — asserted by `TestNoScriptAnywhere` rather than by intention."* The comment
names a test that does not exist under that name — the real one is
`TestNoScriptOnAnySurface` (`internal/ui/ui_test.go:232`), pre-existing drift and
not this lane's to fix, noted so T5 does not go looking for a function called
`TestNoScriptAnywhere` and conclude it was deleted. `/distill` is licensed to
break the guarantee, by name, in the same comment block `s3-distill.html` already
carries: *"Either the distill surface gets JS (defensible: it is a localhost app
view, NOT the crawlable public renderer `dec-0012`'s reasoning covers) or the
hints stay gone."* T5 is the lane taking that option. It must narrow
`TestNoScriptOnAnySurface` to `/` and `/e/<id>` explicitly and add its own
equivalent for `/distill`, rather than deleting the guarantee for the two surfaces
that still need it — a narrowed scope is not the same change as a removed test,
and the package comment's own claim needs updating in the same commit so it
stops overstating what the package now does.

**The verification standard this lane is held to** (`docs/lore.md` L-0001): a gate
is evidence only once both sides are observed — red on a constructed defect of the
class it claims to catch, and green on the untouched correct baseline. Rule 2, the
green side, is the one this repo's own count says gets skipped five times out of
five instances recorded so far. Every task below names its red-today state and its
green proof separately.

  form)

- **Both sides:** the frontmatter-preservation assertion is proven able to fail
  against a handler that writes the raw form body over the whole file (a
  deliberately wrong handler, reverted), and proven to pass on the real one.

the risk `docs/plan/lanes/E6.md` states for this lane and the "What is already
known" section above for the mechanical reason a second path cannot compile.

bare edge target, exactly as `internal/ui/view.go`'s `buildChain` already does
today. Anything that would need a *live* join — the served index showing real,
current kazi convergence for a repo's actual `.dira/` — is E4's, not marked as a
task here because it has no exported function yet to call, and stays a named gap
rather than a fixture-only stand-in wired into production code.

**The chain-at-scale question (`DESIGN.md`'s open design question 1) and the

`DESIGN.md` already settled (the ≤6/>6 `<details>` split, the withheld state); it
