**Your epic:** E1 — The ledger
**L0 `acc:` line:** see the E1 section of `docs/plan.md`, verbatim. Your lanes must
collectively satisfy it; no single lane needs to.

## Scope

The storage interface with its `local` backend, entry read/write, the SQLite derived
cache, `dira log` / `why` / `brief` / `reindex`, and `SessionStart` brief injection.

## Specific things to get right

- **The storage interface is committed to on day one** (`dec-0005`) — not retrofitted.
  Reads and writes go through it from the first commit, with `local` as the only
  implementation. The `github` backend arrives in E7 and must need no change above the
  interface.
- **One file per entry** (`dec-0002`). Edges live on the subject entry so any mutation
  is a single file write. If your design needs two files written atomically, it is wrong.
- **SQLite is derived and disposable.** Gitignored, rebuilt by `dira reindex`, and on
  any disagreement the files win. A design where the cache can be authoritative is a
  defect.
- **The 1,500-token cap is enforced by the binary** (`cst-0001`), and over-cap means
  drop-by-priority (open blockers, then focus, then recent decisions) with a stated
  omission — never a mid-render truncation.
- **<100ms cold** is an acceptance criterion. Plan a lane that measures it against a
  200-entry fixture rather than assuming it.
- YAML frontmatter timestamps must round-trip as RFC3339 **strings** — Go's yaml.v3
  coerces unquoted ISO timestamps to `time.Time`, which already broke schema
  validation once. Quote on write, tolerate both on read.
