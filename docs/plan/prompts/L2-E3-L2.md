# L2-E3-L2 — Implement `dira check` end to end over a single ledger

You are an L2 planner. You produce **tasks**, not code, and not lanes.

## Context

**Epic:** E3 — the enforcer. `dira check` runs *before* predicates are drafted and exits
non-zero on contradiction, citing the entry, the rejected alternative, and its
`why_not`. This is the relitigation firewall, and the one moment in the product that
produces a felt "it caught me".

**Your lane:** E3-L2. The whole verb over a **single local ledger**: read the
enforcement set, match, render, exit. Includes the human-readable format and `--json`,
because the engine and the renderer meet at a verdict struct and splitting them would
put a handoff in the middle of the lane. Cross-ledger inheritance is E3-L3's; the
supersede verb is E3-L4's.

**depends_on:** E3-L1 (the contract, the fixture ledgers, the frozen corpus).
**Cross-epic prerequisites:** E0 (Go module, `go build ./...`, `go test ./...`, the
schema-validation test) and E1 (storage interface + entry reader — the check is a reader
over the same query path as `dira why`, and must not grow a second one).

**Your lane's `acc:` line, verbatim:**

> `go test ./internal/enforcer` reports ≥90% of the corpus's expected-conflict rows
> detected **with the correct entry id cited** and **zero** compliant rows flagged,
> having first asserted the corpus matches `corpus.sha256`;
> `dira check "add a background daemon to track run state"` against
> `internal/enforcer/testdata/ledgers/daemon` exits 2 and matches
> `internal/enforcer/testdata/golden/daemon.txt` byte-for-byte, that golden containing
> the `rejected alternative`, `why_not`, and `revisit_if` lines for dec-0060;
> `dira check "write the checkpoint file atomically"` against the same ledger exits 0
> and emits no `✗`; a matched alternative with no recorded `revisit_if` renders an
> explicit "none recorded — supersede <id> to reopen" line rather than omitting the
> field; the fixture's `state: staged` decision is cited by nothing; and
> `dira check --json` validates against a committed `schema/check.schema.json`.

## Fixed before you start — do not re-decide these

From `docs/plan/lanes/E3.md`. Read that file; the short form:

**The enforcement set.** `decision`/`accepted` → match each `alternatives[].option`.
`decision`/`rejected` → match the entry's own title; rejected decisions are first-class
permanent substrate and a check that reads only accepted decisions misses the epic.
`decision`/`staged` → never enforced (regex-tier guess, `dec-0003`).
`decision`/`superseded` → not enforced here (E3-L4 handles the redirect).
`constraint`/`active` → enforced. `constraint`/`superseded` → not.
`intent`/`question`/`note` → never enforcement substrate.

**Exit codes.** `0` compliant · `2` at least one cited conflict · `1` dira's own errors
only. A hook caller must be able to tell "you are contradicting yourself" from "dira is
broken", so never return 1 as a verdict.

**Private entries are cited ref-only, always** — in every mode including `--json`. This
lane reads one ledger so it may not encounter one, but the renderer is where the rule
lives, so build it in rather than leaving it for E3-L3.

**The output format is frozen by marketing.** `.agents/product-marketing.md` §6
pre-registers the exact terminal block as E8's primary demo asset — one clip, under 20
seconds, no narration. Reproduce it, golden-file it, and treat a diff as a break rather
than a preference. Voice per §10: precise, unhyped, states limits. No exclamation marks,
no "AI-powered".

**`revisit_if` is what stops the check being merely obstructive** — it distinguishes a
closed door from a locked one. Every conflict block surfaces it, and where an
alternative recorded none, it says so explicitly instead of omitting the line. A silent
omission reads as "never", which is the opposite of the truth.

## The task bound

**≤8 tasks.** Each task needs: `id` (`E3-L2-T<n>`), `title` (one line, imperative),
`files` (actual paths), `acc:` (one machine-checkable predicate — a command and an
observable outcome), `depends_on` (task ids or `none`).

An `acc:` that passes before the task runs is a defect. `acc: dira check exists` is the
exact failure mode kazi is built to catch — do not hand it one.

Seams where the work divides — **guidance, not your task list:** loading the enforcement
set through E1's reader; normalizing the input string; scoring and the threshold; the
verdict model; the human renderer against the golden file; `--json` plus
`schema/check.schema.json`; exit-code wiring and the compliant path; the corpus
precision/recall gate test.

## The risk to plan against

Zero false positives across E3-L1's ≥15 deliberate near-misses, at ≥90% recall, may not
be reachable by the chosen matcher. If it is not, the honest output is a reported
precision/recall curve plus a proposal — move the threshold, or change the contract and
supersede E3-L1's decision entry. It is **not** an edited corpus, which is why the
checksum assertion sits inside the `acc:` line. At least one task should make that
assertion its own explicit predicate.
