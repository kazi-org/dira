### E6-L3-T1 — Template `/distill` from staged entries

One actionable card, the rest dimmed and non-actionable — "a queue of three is a decision, a
queue of thirty is a chore". The because is the hero; the title is the label. The rejected
alternative the agent extracted is shown, because approving a decision means approving what
it rules out. The `.src` line names the hook and the capture tier, which is how `dec-0003`'s
trust distinction reaches the human.

**acc:** `GET /distill` against `docs/design/fixtures/ledger-design/` renders one `.stage`
plus the remaining staged entries as `.stage.next`, driven by the fixture's staged entries
(adding a staged fixture entry adds a card; accepting one removes it); every card shows its
id, its `staged`/`open question` chip, its `source.hook` and `source.tier` in `.src`, the
`because` as the largest text on the card, the title under a `Decides`/`Blocks` label, and
the extracted alternative struck through where one exists; no entry with `state: accepted`
appears; the served `<style>` block is byte-equal to `docs/design/screens/s3-distill.html`'s;
and `grep -oE '#[0-9a-fA-F]{3,6}'` over the served body returns only `#0f151c` and
`#f7f4ed`.

### E6-L3-T2 — Make disposition work with JavaScript disabled

The screen's actions are `<button>` elements in the mockup; served, they must be a real form
that works without scripting. Both `cst-0004`'s spirit and `DESIGN.md`'s "print,
reduced-motion, and no-JS all show real content" require it. The write goes through **E2's**
disposition function, not through file writes in this package.

**acc:** with JavaScript disabled, submitting Confirm on `/distill` issues a POST, changes
exactly one file under the ledger's `entries/` directory (byte-diff shows one file changed,
none created or deleted), redirects to `/distill`, and the disposed entry is no longer
offered; Reject does the same with the opposing outcome; a Go test asserts the write path
calls E2's exported disposition function and that `internal/ui` contains no direct entry-file
write, proven by grep plus a test double that records the call; a POST for an id that is not
staged returns 4xx and changes no file; and repeating the same POST twice disposes once
(second attempt is a no-op with a 4xx or a redirect, never a second write).

### E6-L3-T3 — Add the keyboard layer as progressive enhancement

`Y` confirm, `N` reject, `E` edit — the hints are permanently visible in the mockup, because
hover is never the only affordance. The script enhances the form that already works; it
never becomes the only path.

**acc:** with JavaScript enabled, `Y` and `N` produce the same single-file change as the
no-JS POST without a full page load, verified by comparing the on-disk diff from both paths
for the same entry; the keyboard hints are present in the served HTML regardless of
JavaScript; the shortcuts do not fire while focus is in a text input; the script is served
from `embed.FS` from a loopback path with no external request; removing the script leaves
T2's behaviour intact, demonstrated by a capture with scripting disabled; and focus is
visibly managed after a disposition (the next card's primary action receives focus, with a
`:focus-visible` outline per `tokens.css`).

### E6-L3-T4 — Render the empty state as one sentence

`DESIGN.md` records why the empty state was *removed* from the mockup — sitting below three
populated cards, it read as though the queue were empty — and preserves its copy for the
real empty case: one sentence, zero filled buttons (TASTE 14).

**acc:** `GET /distill` against a ledger with no staged entries renders the recorded
sentence — "When the queue is empty, nothing is waiting on you — and the ledger is
current." — byte-equal to the string in `DESIGN.md`, with zero `.btn-primary` and zero
`.cta` elements on the page; the empty state is absent whenever ≥1 staged entry exists; and
the page still passes the `render.mjs` gate including the near-blank-mount probe at all
three viewports.

### E6-L3-T5 — Measure design law 2 on the served DOM

> **The because outranks the title.** On any surface where a human disposes of an entry, the
> `because` is set larger than the title. *Measured test:* `.stage .because` font-size >
> `.stage .titleline` font-size.

`DESIGN.md` states this as a measured test, so it must be a script reading computed styles
from the running page — not a CSS grep, which a `clamp()` or a media query would defeat.

**acc:** `node docs/design/scripts/laws.mjs` loads the served `/distill` at 390px, 1024px
and 1440px and reports the computed font-size of `.stage .because` and `.stage .titleline`
at each, exiting non-zero if the because is not strictly larger at any viewport; the script
**fails** when `.stage .because` is temporarily set to `13px`, demonstrated; it also asserts
law 1 (`--caught` appears in no rule that applies to `/distill`) and law 3 (the served
chain, where one is present, contains no `<svg>`, `<canvas>` or `<img>` and select-all
yields its ids as text); and it runs against a URL argument so it works for any route.

### E6-L3-T6 — Extend the 3 × 2 gate to `/distill` including the mobile form

The mobile layout is a different composition, not a narrower one: actions become full-width
and thumb-reachable, the keyboard hint disappears, and the swipe note appears. All three are
gate-checkable.

**acc:** the E6-L2 gate command also captures `/distill` at mobile/laptop/wide × light/dark
against a freshly regenerated `s3-distill` baseline and reports a pixel diff within the
tolerance recorded in `DESIGN.md`, exiting non-zero above it; the gate asserts `.swipe-note`
is visible at 390px and not visible at 1440px, and that `.actions .hint` is the reverse
(this is the r2→r3 source-order bug, and the assertion must fail if the base `display: none`
is moved after the media query — demonstrated); every `.btn` has a computed height ≥44px at
390px and ≥40px at 1440px; and `render.mjs`'s full gate passes on the served page with zero
non-loopback asset requests.
