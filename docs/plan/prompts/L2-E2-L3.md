# L2-E2-L3 — Build `dira install-hooks` to kazi's proven contract, and prove hooks fail open

You are an L2 planner. Decompose this one lane into tasks and write them to

## Context

**Epic:** E2 — Capture (roadmap M2). **Lane:** E2-L3.

`dira install-hooks` registers three hook entries in Claude Code's settings:
`SessionStart` → `dira brief --context`, `Stop` → `dira sniff --stage --quiet`,
`PreCompact` → `dira sniff --deep --stage`. It writes into a file other tools also own,
so the failure mode is severe and specific: clobbering an operator's hand-tuned
settings. **kazi already paid for that lesson** (`dec-0008`), so this lane ports a proven
contract rather than inventing one — merge-never-clobber, idempotent, operator keys
preserved byte-identically, `--uninstall` reverting exactly, `--local` targeting the
uncommitted settings file.

It also owns the epic's fail-open clause: a non-zero `dira` exit must never block a
session.

**Lane `acc:` verbatim:**

> `go test ./internal/installhooks` passes with, against a temp settings directory:
> (a) installing into a `settings.json` that already holds an operator's own hooks and
> unknown top-level keys leaves every pre-existing entry present and unchanged; (b) a
> second install is a no-op — file bytes identical, exit 0, `UNCHANGED` on stdout;
> (c) `--uninstall` immediately after a fresh install restores the pre-install bytes
> exactly (equal sha256), and deletes the file if and only if install created it;
> (d) `--local` writes `.claude/settings.local.json` and never a committed
> `.claude/settings.json`; (e) malformed input JSON writes nothing and exits non-zero;
> (f) **every command string the installer writes is accepted by the built binary** —
> the test parses the installed settings and rejects any unknown flag; and (g) a
> fail-open test that puts a `dira` on `PATH` exiting 1 shows each installed `Stop` and
> `PreCompact` command string still exiting 0.

**depends_on:** `E2-L1` (clauses f and g run the real `dira sniff`, so its flags must
exist — testing them against a stub would make the strongest predicate in this lane
vacuous), `E1-L5` (`dira brief --context --chain`, the command the `SessionStart` entry
invokes), and `E0-L1` (module, command skeleton). Read `docs/plan/lanes/E0.md` and
`docs/plan/lanes/E1.md` for the real package layout; the paths below are provisional.

**The one implementation fact that decides whether this lane succeeds:** kazi does
**not** decode the settings file into a map and re-encode it. It validates the bytes with
Jason, scans *the same bytes* into a span tree, and then splices insertions in or drops
byte spans out (`install_hooks.ex:32-38`, `apply_inserts/2:425`, `drop_spans/2:487`). Its
own entries are identified by their command strings (`kazi_entry?/2:365`). A Go port that
does `json.Unmarshal` → `json.Marshal` **cannot** satisfy clauses (a) or (c): Go sorts
map keys, discards formatting, and would rewrite every line of a file it was asked to
merge into — including the `//`-prefixed documentation keys this project's own example
file uses. Port the span-splice approach.

### E2-L3-T2 — Pin the three hook registrations as one source of truth

The registrations are specified by `hooks/settings.example.json`: `SessionStart` →
`dira brief --context --chain 2>/dev/null || true` (timeout 5), `Stop` →
`dira sniff --stage --quiet 2>/dev/null || true` (timeout 10), `PreCompact` →
`dira sniff --deep --stage 2>/dev/null || true` (timeout 60). Pin them as data in one
place, the way kazi's `hook_commands/0` does, so the installer, the uninstaller, and the
tests all read one source.

**The `--chain` trap, and who already owns it.** `--chain` walks the tier parents (repo →
workspace → personal), which is **E5 — and E5 is blocked on `qst-0001`**. Writing a flag
the binary rejects makes the hook fail open and the session *silently never briefed* — a
failure that looks exactly like success, which is the worst available outcome for a tool
whose whole value is arriving unbidden. **This instance is already resolved:**
`docs/plan/lanes/E1.md` §"Constraints this epic inherits" item 3 takes the obligation, and
`E1-L5`'s `acc:` requires `dira brief --context --chain` with no `[parents]` configured to
exit 0 stating that no parent ledger is configured. So this task **keeps** `--chain` in
the registration table and does not re-decide it; T7 is what proves E1 kept the promise.
If E1-L5 lands without it, report the contradiction — do not quietly drop the flag, and do
not weaken T7.

`files:` `internal/installhooks/hooks.go`, `internal/installhooks/hooks_test.go`.

`acc:` `go test ./internal/installhooks -run TestRegistrations` passes: the pinned
registration table matches `hooks/settings.example.json` exactly — same three events,
same command strings, same timeouts, asserted by parsing the example file rather than by
duplicating its contents in the test; every command string contains `|| true`; the table
is the single source the installer, the uninstaller, and T7/T8 all read (asserted by the
test failing if any of those packages contains a second literal copy of a command
string); and the test fails if the example file and the table drift in either direction.

### E2-L3-T3 — Build the byte-span JSON scanner and splicer

Validate the bytes with `encoding/json` first (that is the authoritative malformed-JSON
check), then scan **the same bytes** into a span tree recording the byte offsets of each
object member and array element, so edits are computed as insertions at offsets and
deletions of spans. Everything not spliced is preserved byte-identically because it is
never rewritten. This mirrors `install_hooks.ex:243-259` and is the reason kazi can
promise byte-identical preservation at all.

`files:` `internal/installhooks/spans.go`, `internal/installhooks/spans_test.go`.

`acc:` `go test ./internal/installhooks -run TestSpans` passes: for every fixture from
T1 that is valid JSON, scanning and then re-emitting with an empty edit set returns bytes
equal to the input (sha256 equal) — including the fixture with `//`-comment keys and the
fixture with unusual whitespace; scanning the malformed fixture returns an error and no
span tree; a single insertion at a computed offset changes exactly the intended byte
range (asserted by diffing offsets, not by eyeballing output); and a span deletion
followed by re-insertion of the same text is the identity.

### E2-L3-T4 — Implement install: merge-never-clobber and idempotent

Insert the three registrations, creating only what is missing: the file if absent, the
`hooks` object if absent, an event array if absent, an entry if that event has no dira
entry already. Identify dira's own entries by their command strings, as kazi identifies
its own. If all three are already present the install is a **byte-level** no-op —
nothing written, `UNCHANGED` reported.

`files:` `internal/installhooks/install.go`, `internal/installhooks/install_test.go`.

`acc:` `go test ./internal/installhooks -run TestInstall` passes over the full T1 table:
into an absent file it writes a minimal settings file containing exactly the three
registrations and nothing else; into a file holding an operator's own `Stop` hook it
leaves that entry present and byte-identical while adding dira's alongside it; into a
file with unknown top-level keys those keys survive sha256-identically as spans; a
second install writes nothing and the file's sha256 is unchanged, exit 0, stdout
contains `UNCHANGED`; the malformed fixture writes nothing and exits non-zero with one
line on stderr; and no case ever removes or reorders a pre-existing array element
(asserted by comparing the pre-existing elements' bytes before and after).

### E2-L3-T5 — Implement uninstall: exact inverse, including file deletion

Remove exactly the entries install added — spans only, everything else untouched. If the
file's bytes equal what a fresh install creates, delete the file, because that file *is*
the thing install created (`install_hooks.ex:152-160`). An uninstall with nothing
installed is `UNCHANGED`, not an error.

`files:` `internal/installhooks/uninstall.go`,
`internal/installhooks/uninstall_test.go`.

`acc:` `go test ./internal/installhooks -run TestUninstall` passes over the full T1
table: for every fixture, `install` then `uninstall` restores the pre-install bytes
exactly (sha256 equal); for the absent-file case, install-then-uninstall leaves **no
file** on disk; an operator's own hook entry under the same event survives an uninstall
byte-identically; uninstall with no dira entries present writes nothing, exits 0, and
reports `UNCHANGED`; and an entry a human has since edited (dira's command with an added
flag) is **not** silently removed — the command says which entry it left alone and exits
0.

### E2-L3-T7 — Assert every written command string is accepted by the binary

This is the clause that catches the `--chain` class of bug, and it is the reason clause
(f) is in the lane's `acc:` line. Parse the settings file the installer just wrote,
extract each hook command, strip the shell guards, and check the verb and every flag
against the built binary's own command registry.

`files:` `internal/installhooks/commands_test.go`.

`acc:` `go test ./internal/installhooks -run TestWrittenCommandsAreReal` passes: for

bogus flag is spliced into the pinned registration table (negative case asserted, so a
broken extractor cannot pass it silently); and the test names which event's command
failed, not merely that one did.

### E2-L3-T8 — Assert hooks fail open under a failing `dira`

The epic's third clause. Put a `dira` on `PATH` that exits 1 (and one that panics, and
one that hangs past the timeout), then run each installed command string through a real
shell and assert exit 0 and no output on stdout. This tests the *installed string*,
including `2>/dev/null || true`, which is where the fail-open property actually lives.

`files:` `internal/installhooks/failopen_test.go`,
`internal/installhooks/testdata/fakedira/`.

`acc:` `go test ./internal/installhooks -run TestFailOpen` passes: with a fake `dira`
exiting 1, each of the three installed command strings executed via `sh -c` exits 0 and
prints nothing to stdout or stderr; with a fake `dira` writing to stderr and exiting 2,
the same holds; with a fake `dira` that sleeps past its declared timeout, the recorded
timeout value in the settings file is ≤60 for `PreCompact` and ≤10 for the others
(asserted from the written file); and the test fails if any command string in the pinned
table lacks `|| true`.
