## The standard this lane is held to

Every clause is **two-sided**. An absence assertion alone is worthless — a banner test
passes when the banner is the only output; a read-only test passes when nothing was read
either; a lint passes when its pattern list is empty. So each check needs a paired
positive: a poisoned fixture, an injected label, a mutated file — something that must make
the check **fail**. A task whose `acc:` has only the green half is not done.

## Tasks — at most 8

Each task needs `id` (`E4-L5-T<n>`), `title`, `files`, `acc:`, `depends_on`.

Suggested spine — refine it, but do not lose a clause of the lane `acc:`:

1. **The stub-kazi matrix** — absent, exit 2, garbage stdout, foreign `kind`, hangs past
   the deadline. `acc:` asserts five *distinct* reasons surface in five distinct rendered
   lines, and that a stub which succeeds produces none of them.
2. **The label-absence assertions** — with kazi unavailable, no execution-bucket label
   appears anywhere in stdout, paired with a positive run (kazi available via a fixture
   stub) where each label *does* appear. Without the positive half this test passes on an
   empty renderer.
3. **The no-write proof** — sha256 of every `.dira/` file before and after `dira map`,
   plus the read-only-mount run still exiting 0, plus a mutation control proving the hash
   comparison would catch a write.
4. **The stale-cache honesty check** — a cached snapshot is permitted only with a visible
   staleness statement; assert that a snapshot older than its freshness bound is either
   refreshed or labelled, and that a fixture presenting a stale snapshot as live fails.
5. **The vocabulary lint** — over `tags` and edge `note` on every entry, with the
   poisoned fixture that must fail it. Record the vocabulary list explicitly in the task
   file; a lint with an implicit list is unauditable.
6. **The structural write-barrier** — `go list -deps` showing the map command's graph does
   not reach the ledger writer package, with a control asserting the check fails if an
   import is added.
7. **Wire all of it into CI** as a named suite, so the verdict is "this named suite ran
   and passed N tests", not "tests passed".
