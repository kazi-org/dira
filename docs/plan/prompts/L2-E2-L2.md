## Context

**Epic:** E2 — Capture (roadmap M2). **Lane:** E2-L2.

Capture tier 2 is **the already-running Claude session**, not a model dira calls. The
binary never embeds a model client and never holds an API key (`dec-0003`). At
`PreCompact` — Claude Code's lossiest moment — `dira sniff --deep --stage` stages what
the regex found and hands off to the live session, which fills in what a regex cannot:
the because, the rejected alternatives with their `why_not`s, and the `derives_from`
edge. Then the session calls `dira log` with a complete entry.

This lane owns three things: the handoff, the skill that receives it, and a build-time
test that turns `dec-0003` from a promise into an enforced invariant.

**Lane `acc:` verbatim:**

> `go test ./internal/sniff -run TestDeepHandoff ./internal/skill ./internal/nomodel`
> passes: `dira sniff --deep --stage` on `testdata/transcripts/pre-compact.jsonl` both
> stages the regex candidates **and** emits a handoff block on stdout naming each staged
> id plus the fields the live session must fill (`because` body,
> `alternatives[].why_not`, `derives_from`); a linkage test over
> `go list -deps ./cmd/dira` fails if any model-provider client module is linked and if
> any non-test source file references an API-key environment variable; and the skill's
> own documented `dira log` invocation, replayed verbatim from `testdata/skill/`,
> produces an entry that validates against `schema/entry.schema.json` with
> `source.tier: semantic`, `confirmed_by` absent or non-`human`, and ≥1
> `alternatives[].why_not`.

**depends_on:** `E2-L1` (the `sniff` command, the matcher, and the staging writer —
`--deep` is a flag on that command and must not fork it) and `E1-L2` (`dira log` and the
write path the skill calls back into). `E0-L1` supplies the module and command skeleton.
Read `docs/plan/lanes/E0.md` and `docs/plan/lanes/E1.md` for the real package layout;
the paths below are provisional.

### E2-L2-T1 — Establish how `PreCompact` output reaches the session, and record the answer

**This is the lane's unresolved prerequisite and it must be settled first.**
`dira sniff --deep` is a subprocess; it cannot ask the session anything. The design in
`hooks/settings.example.json` assumes the handoff reaches the model — which is true for
`SessionStart` (its output is injected as context) but is **not established for
`PreCompact`**. Determine it against Claude Code's actual hook contract: which events
support injecting additional context, whether `PreCompact` stdout is delivered to the
model, to the user, or discarded, and whether a JSON hook response with an
additional-context field is honoured there.

If it is not injected, `--deep` degrades honestly to: stage the regex candidates, and
leave the handoff where the *next* turn will see it (a `UserPromptSubmit`-delivered
note, or a staged-entry count in the next `SessionStart` brief). In that case the
PreCompact insurance policy is weaker than `settings.example.json` claims and **that
file's comment gets corrected** — do not quietly loosen the test instead.

`files:` `.dira/entries/dec-00NN.md` (new), `hooks/settings.example.json` (comment
correction if the finding requires one).

`acc:` a new entry exists under `.dira/entries/` recording the mechanism with cited
evidence (a documentation reference or an observed hook invocation, quoted), validating
against `schema/entry.schema.json`, with ≥1 `alternatives[].why_not` and a
`derives_from` edge to `dec-0003`; and `hooks/settings.example.json` parses as JSON with
its `PreCompact` `//` block naming that entry id, so the wiring cites its own evidence.

### E2-L2-T2 — Specify the handoff block as a golden format

The block `--deep` emits is a contract between the binary and the skill, so pin it as a
golden file rather than letting it drift into free prose. It must name each staged id,
the fields the session has to fill (`because` body, `alternatives[].why_not`,
`derives_from` edge), and the exact `dira log` invocation shape to call back with. It
must be bounded — the same reasoning as `cst-0001`, applied to a smaller surface: this
text lands in a context window that is about to be compacted precisely because it is
full.

`files:` `internal/sniff/handoff.go`, `internal/sniff/handoff_test.go`,
`internal/sniff/testdata/handoff.golden`.

`acc:` `go test ./internal/sniff -run TestHandoffGolden` passes: the block rendered for
a 3-candidate fixture matches `testdata/handoff.golden` byte-for-byte; it names all
three ids; it names `alternatives`, `why_not`, and `derives_from` literally; it is
≤400 tokens by the binary's own counter (the same counter `dira brief` uses, per
`cst-0001`) regardless of candidate count, degrading to ids-only past a fixed candidate
count rather than growing without bound; and it contains no API key, no URL, and no
model name.

### E2-L2-T3 — Wire `--deep` so tier 1 always runs first and tier 2 is additive

`--deep` never replaces the regex pass. It stages exactly what `dira sniff --stage`
would (E2-L1's writer, unchanged), then emits the handoff. So a `PreCompact` with no
live cooperation still loses nothing that tier 1 could catch — which is what makes it
an insurance policy rather than a gamble.

`files:` `internal/sniff/deep.go`, `cmd/dira/sniff.go`, `internal/sniff/deep_test.go`,
`internal/sniff/testdata/transcripts/pre-compact.jsonl`.

`acc:` `go test ./internal/sniff -run TestDeepHandoff` passes: on
`testdata/transcripts/pre-compact.jsonl`, `dira sniff --deep --stage` writes exactly the
same entry set as `dira sniff --stage` on the same fixture (asserted by comparing
ledgers) **and** additionally emits the handoff block; with `--deep` and a fixture
yielding zero candidates it emits no handoff block and exits 0 with empty stdout; it
exits 0 and stages the regex candidates even when handoff rendering is forced to fail;
and it completes in under 10 seconds on the fixture, inside the hook's 60s budget.

### E2-L2-T4 — Write the skill

The skill is the tier-2 worker: it reads the handoff, fills in the because, the
alternatives with their `why_not`s, and the `derives_from` edge, then calls `dira log`.
It also carries the `qst-0005` fallback — wrapping `kazi approve` / `kazi reject` so a
disposition still gets logged while kazi has no post-disposition hook — and it runs
`dira check` before planning, per `docs/design.md` §10 step 4 (calling a command E3
owns; the skill names it, this lane does not build it).

Two hard rules for the text: it never instructs the model to invent a `why_not` that was
not said in the session (a fabricated rationale is worse than an absent one, because it
will be quoted back as the user's own reasoning), and it never tells the model to call a
network service.

`files:` `skills/dira/SKILL.md`.

`acc:` `go test ./internal/skill -run TestSkillShape` passes: `skills/dira/SKILL.md`
exists, its YAML frontmatter parses with non-empty `name` and `description`, the
description names the triggering conditions (a handoff block, a `PreCompact`, a
disposition); the body contains a literal `dira log` invocation and a literal
`dira check` invocation; and it contains no occurrence of an API-key env var name, no
`http://`/`https://` call instruction, and none of the words banned by
`.agents/product-marketing.md` §10 (`revolutionary`, `seamless`, `supercharge`, `10x`,
`AI-powered`) — asserted by pattern.

### E2-L2-T5 — Test that the skill names only real commands and real flags

kazi already proved this test earns its keep
(`test/kazi/teach/skill_covers_commands_test.exs`): a skill that instructs the model to
run a verb the binary does not have produces a silent capture failure that looks like a
model mistake. Extract every `dira …` invocation from `SKILL.md` and check each verb and
flag against the binary's own command registry.

`files:` `internal/skill/covers_test.go`, `internal/skill/extract.go`.

`acc:` `go test ./internal/skill -run TestSkillCoversCommands` passes: every `dira`
invocation extracted from `skills/dira/SKILL.md` resolves to a registered command with
every flag accepted by that command's flag set, and the test fails when a deliberately
invented verb (`dira frobnicate`) or an invented flag (`dira log --magic`) is spliced
into a copy of the skill — both negative cases asserted, so the test cannot pass
vacuously on an extractor that finds nothing.

### E2-L2-T6 — Replay a recorded skill output end to end into a validated entry

The tier-2 path cannot be tested with a live model, so record one. Capture a real
session's response to a real handoff block, store it as testdata, and replay the
`dira log` invocation it produced. This is what makes the tier-2 half of the lane's
`acc:` line falsifiable rather than aspirational.

`files:` `internal/skill/testdata/handoff-response.txt`,
`internal/skill/testdata/expected-entry.md`, `internal/skill/replay_test.go`.

`acc:` `go test ./internal/skill -run TestReplay` passes: replaying the recorded
`dira log` invocation against a temp ledger produces an entry that validates against
`schema/entry.schema.json`, has `source.tier: semantic`, `source.hook: PreCompact`, ≥1
`alternatives[].why_not` non-empty, a `derives_from` edge, a non-empty markdown body,
and `confirmed_by` either absent or not `human`; and replaying a mutated response whose
`why_not` is empty is **rejected** by `dira log` with a non-zero exit rather than
written.

### E2-L2-T8 — Install the skill on kazi's contract

**Scope note, stated rather than hidden:** `docs/plan.md`'s E2 scope names
`dira install-hooks` but not a skill installer. A skill nobody can install is not a
capture tier, so this task exists — bounded to the minimum, mirroring
`Kazi.Teach.InstallSkill`'s consent contract: only this explicit command writes harness
config, the target directory is injectable so tests never touch the real `~/.claude`,
and a file the operator has since edited is never silently overwritten. If the lead
would rather this move to E0 or its own lane, that is a reasonable call — say so instead
of expanding it.

`files:` `cmd/dira/install_skill.go`, `internal/skill/install.go`,
`internal/skill/install_test.go`.

`acc:` `go test ./internal/skill -run TestInstallSkill` passes against an injected temp
directory: a first install writes `skills/dira/SKILL.md` and exits 0; a second install
is a byte-level no-op reporting `UNCHANGED`; a locally modified skill file is **not**
overwritten without an explicit force flag and the command says which file it left
alone; and no code path in the package can write outside the injected directory
(asserted by running with the injected dir set to a temp path and failing if anything
under `$HOME` is created).
