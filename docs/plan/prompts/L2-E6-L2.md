### E6-L2-T1 — Record the server-rendered-HTML decision as a ledger entry

`docs/design.md` §9 and `docs/plan.md` §E6 both say `dira ui` is a "static SPA". The three
built screens contain zero JavaScript, and the growth engine depends on pages a crawler can
read — `.agents/product-marketing.md` §7 lists "public ledgers as long-tail SEO" as a
channel, which a client-rendered SPA defeats. An SPA also buys nothing on localhost, where
the data is already in-process, and would add a JSON API layer nobody asked for. This lane
therefore proposes Go `html/template` + `embed.FS`, with JavaScript only as progressive
enhancement on `/distill` (E6-L3).

**This is a divergence from a written document, so it is recorded rather than assumed.**
Write it as a decision entry with its rejected alternatives (client-side SPA; a JSON API
plus static JS bundle) and their `why_not`, and update `docs/design.md` §9 to match.

**acc:** a new entry exists at `.dira/entries/dec-00NN.md` taking the next free `dec-`
id, with `kind: decision`, `state: accepted`, a `derives_from` edge to `int-0002`, an
`informs` edge to `dec-0010`, and ≥2 populated `alternatives` each carrying a `why_not`;
it validates against `schema/entry.schema.json`; `docs/design.md` §9 no longer describes
`dira ui` as an SPA and cites the new entry; and no dangling edge is introduced (every
`to:` resolves to an existing entry id or a namespaced external ref).

### E6-L2-T2 — Serve `tokens.css` from the binary with a drift test

`tokens.css` is the single source of colour and spacing truth, and `docs/design/screens/`
loads it by relative path. Go's `embed` cannot reach outside its package directory, so the
binary needs its own copy — and a copy is a drift risk, which is exactly what the token
system exists to prevent. The copy must therefore be mechanically pinned to the original.

**acc:** `GET /tokens.css` from the running server returns bytes identical to
`docs/design/tokens.css` (byte count and sha256 both equal), served with
`content-type: text/css`; a Go test compares the embedded bytes against
`docs/design/tokens.css` and **fails** when either file is edited alone, demonstrated by
running the test with a one-character change in each direction; and the asset is served
from `embed.FS`, proven by the test binary succeeding with the working directory changed
to a temporary directory containing no repo files.

### E6-L2-T3 — Stand up `dira ui` — embedded assets, loopback server, routing

`int-0002` forbids a daemon and a permanently owned port: `dira ui` is a foreground process
bound to loopback that stops when it stops. Routes: `/` (index), `/e/<id>` (decision),
`/tokens.css`. An unknown id is a 404 that is a real page, not a stack trace.

**acc:** `dira ui` binds `127.0.0.1` on an ephemeral port by default, prints the URL, and
serves `/`, `/e/<id>` and `/tokens.css` with 200; it refuses to bind a non-loopback
interface (an explicit `--addr 0.0.0.0:…` is rejected with a non-zero exit and a message
naming `cst-0004`, or is absent entirely); `/e/<unknown-id>` returns 404 with a rendered
page carrying the topbar and the attribution line; a Go test asserts every route is served
from `embed.FS` with the process working directory outside the repo; and the process exits
0 on `SIGINT` releasing the port, verified by binding the same port again immediately.

### E6-L2-T4 — Template `s1-decision` from a real entry

The page a stranger lands on. Composition is fixed by the mockup: invocation line, the
chain, the ruling, the because, alternatives with grounds, the rail, the footer. The mobile
`.chain-stack` is the same graph in a different typographic form and must carry the same
data in the same order. Copy the screen's `<style>` block into the template **verbatim** —
that byte-equality is the cheapest fidelity invariant available, and it must hold in both
directions from here on.

**acc:** `GET /e/dec-0001` against the repo's own `.dira/` renders the real entry — its
title as the ruling, its body as the because, every element of its `alternatives` array
with `why_not` as grounds and `revisit_if` where present, and every `edges` entry in the
rail; the served page's `<style>` block is byte-equal to the one in
`docs/design/screens/s1-decision.html`; the accepted alternative renders `.arg.upheld` and
every other renders struck-through in `--ink-low` with **no** `--caught` anywhere in the
served CSS or markup (design law 1); the chain block is selectable text with no `<svg>`,
`<canvas>` or `<img>` inside it (design law 3); `grep -oE '#[0-9a-fA-F]{3,6}'` over the
served body returns only `#0f151c` and `#f7f4ed`; and the full page content is present with
JavaScript disabled, verified by a capture with scripting turned off.

### E6-L2-T5 — Template `s2-index` with derived status, legend, and conversion block

The acquisition surface, grouped by *why*, not by goal. Three elements are not decoration
and must survive: the permanently-visible `.legend-key` that closes the jargon gate (a
hover tooltip or an onboarding carousel would break `DESIGN.md`'s recorded r3→r4 reasoning),
the single restrained `.take` conversion block, and the drift row as the only red on the
page. Roll-ups and the dial are **derived at read time** (`dec-0004`) — no status field is
read from or written to any entry file. When the kazi join is unavailable, the page shows
ledger-side buckets and says execution status is unavailable rather than guessing.

**acc:** `GET /` against the repo's own `.dira/` lists every id under `.dira/entries/`
grouped under its parent intent, with counts and dial arc lengths computed from the ledger
(changing a fixture entry's edges changes the rendered numbers); the served page's
`<style>` block is byte-equal to `docs/design/screens/s2-index.html`'s; the legend key and
the `.take` block are present in the served HTML with no JavaScript and are not
hover-revealed (both visible in a capture with no pointer interaction); `--caught` appears
only within the drift block; no status string in any served page originates from a field in
an entry file, asserted by a test that greps the entry corpus for `converged`/`in motion`
and finds none; with the kazi join absent the page still renders and states that execution
status is unavailable; and the dial's `aria-label` reports the same counts as the visible
legend.

### E6-L2-T6 — Assert markup fidelity structurally, not only by pixel

A pixel diff catches drift but does not explain it, and it cannot run in `go test`. Add the
cheap structural assertions: the style blocks match their mockups byte-for-byte, the class
contract the mockups establish is present, the two sanctioned `theme-color` hexes are the
only literal colours, and the served markup contains no hardcoded px value that should be a
token.

**acc:** `go test ./internal/ui` asserts, per route, that the served `<style>` block is
byte-equal to its mockup's, that `<link rel="stylesheet" href="/tokens.css">` is present,
that both `<meta name="theme-color">` tags are present with `#0f151c` and `#f7f4ed`, and
that no other hex literal appears in the served document; the test **fails** when a single
declaration is changed in either the template or the mockup, demonstrated in both
directions; and it asserts `lang="en"`, one `<h1>` per page, and that every `<a>` with an
external `href` is `rel="noopener"`.

### E6-L2-T7 — Wire the 3 × 2 pixel gate against regenerated baselines

Fidelity is only measured if the baseline is generated in the same run and the same
environment as the capture. `docs/design/renders/` is gitignored precisely so no stale
baseline can be smuggled in. The gate: regenerate the mockup baselines from
`docs/design/screens/`, start `dira ui` against `docs/design/fixtures/ledger-design/`,
capture the same routes at the same 3 viewports × 2 schemes, and diff.

**acc:** one command regenerates the mockup baselines, starts `dira ui` on the design
fixture ledger, captures `/` and `/e/dec-0001` at mobile/laptop/wide × light/dark, and
reports a per-capture pixel diff within the tolerance recorded in `DESIGN.md`, exiting
non-zero if any pair exceeds it; the underlying `render.mjs` gate passes on the served
pages — no console errors, no page errors, no failed requests, no non-loopback asset
requests, no near-blank mount, no byte-identical light/dark pair, no layout shift; the gate
**fails** when a single token value in `tokens.css` is changed, demonstrated; and
`node docs/design/scripts/contrast.mjs` reports `0 failures` with `hover > rest` as part of
the same command's output.
