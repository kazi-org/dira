## Gated. Plan to lane level ONLY; do not emit L2 prompts.

`dec-0007` sequences this deliberately: the team tier ships "when teams pull for it,
**not before**", and the paid apps are bought by people who already use dira — they
cannot create the audience that produces those people. Planning tasks now optimizes
the wrong end of the funnel.

This epic also depends on E6 shipping, since the apps reuse the storage interface and
the design system.

## Scope (provisional)

The `github` storage backend (`dec-0005`), the PWA, the one-off iOS + desktop bundle.

## Specific things to get right

- **GitHub is the sync server and it was already paid for.** No dira-operated sync
  service — that violates `cst-0004` and destroys the strongest claim the product has
  to this audience.
- Every mutation is one entry-file change, therefore one GitHub `PUT` (`dec-0002`).
  If the mobile write path needs more than that, the storage layer is wrong.
- Honest caveats already recorded in `dec-0007`: one-off revenue is a decaying curve
  per release, App Store discovery is brutal without the OSS funnel, and one-off
  buyers expect updates forever — plan for pay-once-per-major-version.
