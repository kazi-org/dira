## Context

**Epic:** E2 — Capture (roadmap M2). **Lane:** E2-L4.

Everything upstream in this epic stages entries a human has not seen. This lane is where
the human sees them, and it is **the product's entire clerical surface**. From
`docs/design.md` §10 step 2: *"You say 'confirm.' That is your entire clerical

### E2-L4-T1 — Resolve and record what "reject" means, before writing the keymap

`docs/design/screens/s3-distill.html` offers **Confirm / Reject / Edit**, but two
unrelated acts are hiding behind "Reject":

- *"the regex misread me — this was never a decision"* (a bad capture), and
- *"we considered that and decided against it"* (a real, permanent, first-class
  `rejected` decision — the substrate `dira check` reads to stop relitigation, per
  `schema/entry.schema.json`'s own note and `docs/design.md` §7).

The schema has one word for both, and `additionalProperties: false` means there is no
field to distinguish them. Conflating them is not cosmetic: a regex misfire disposed with
`N` would be stored as a `rejected` decision and quoted back at the user three weeks
later, by `dira check`, as **their own recorded reasoning**. That is worse than losing
the capture.

**Recommendation:** `N` means *discard the capture* — the staged file is deleted, because
a capture the human says was never a decision has nothing to remember and a ledger of
noise is the failure `int-0001` names. Recording *"we decided against X"* is a different
act with a different verb (`dira log` of a `rejected` decision with a real `why_not`),
never a keystroke on a card the regex wrote. Under that reading the schema needs no
change.

**The cost to state honestly:** a discard is destructive, and a staged file created since
the last commit is not in git, so a misfired keystroke is unrecoverable. T4's single-level
undo is the mitigation; if the resolution keeps deletion, the undo is not optional.

`files:` `.dira/entries/dec-00NN.md` (new).

`acc:` a new entry exists under `.dira/entries/` naming both meanings, recording which
one `N` performs, validating against `schema/entry.schema.json`, carrying ≥1
`alternatives[].why_not` for the rejected reading and a `derives_from` edge to
`dec-0003`; and if the resolution requires a schema change, E0's schema-validation test
passes on the amended schema and a fixture violating the new rule makes it fail.

### E2-L4-T2 — Build the disposition transitions as a surface-independent package

One function per disposition, taking an entry and returning the write to perform — no
terminal, no stdin, no printing. This is what E6's web surface will call, so a dependency
on a TTY here would force E6 to reimplement the semantics and the two surfaces would
drift.

Per kind, the legal confirmed state comes from the schema's `allOf`, not from a guess:
a staged `decision` → `accepted`; a `question` → `open` (or whatever E2-L1-T1 resolved
for staged questions). Confirming sets `confirmed_by: human` and bumps `updated`; it
does not touch any other field, and it may not add an `alternatives` entry the human did
not write.

`files:` `internal/distill/dispose.go`, `internal/distill/dispose_test.go`.

`acc:` `go test ./internal/distill -run TestDispose` passes: for every kind that can be
staged, confirming produces an entry that validates against `schema/entry.schema.json`
with a state legal for that kind, `confirmed_by: human`, `updated` bumped, and every
other frontmatter field byte-identical to the input; confirming an entry that is not
`staged` is an error that writes nothing; discarding performs exactly the resolution from
T1 and nothing else; the package's exported API takes no `io.Reader`, `io.Writer`, or
terminal handle (asserted by the test compiling against the signatures); and no
transition can produce a non-empty `alternatives[]` (asserted over all transitions).

### E2-L4-T3 — Build the staged queue reader

Read every entry in `state: staged`, ordered so the queue is stable across runs — the
progress indicator in the design (`1 of 3 reviewed`) is meaningless if the order shifts
between invocations. Read through E1's storage interface, and reconcile with `dec-0002`:
if the derived cache and the files disagree, the files win.

`files:` `internal/distill/queue.go`, `internal/distill/queue_test.go`.

`acc:` `go test ./internal/distill -run TestQueue` passes: over a temp ledger of 3 staged
and 5 non-staged entries the queue returns exactly the 3, in an order that is identical
across two reads and across a cache rebuild; an entry whose file says `staged` while a
stale cache says otherwise is **included** (files win); a malformed entry file is skipped
with a named one-line warning rather than failing the whole queue; and an empty ledger
returns an empty queue and no error.

### E2-L4-T4 — Build the one-keystroke loop, with single-level undo

One card actionable at a time. A single byte from the terminal disposes it — no Enter, no
confirmation prompt, no menu. `y` confirm, `n` discard, `e` edit, `q` quit leaving the
rest staged, and `u` undo the last disposition. The undo exists because T1's `n` is
destructive and the queue is driven by muscle memory; one level is enough, and it is
in-session only.

`files:` `internal/distill/tui.go`, `internal/distill/tui_test.go`.

`acc:` `go test ./internal/distill -run TestKeystrokes` passes on a temp ledger of 3
staged entries: a scripted stdin of exactly the three bytes `y`, `n`, `e` disposes all
three and the ledger then holds zero `staged` entries; the driver is given **no** other
input bytes — a test that requires a newline fails; stdout between cards contains no
second prompt matching `[y/n]` or `confirm?` (asserted by pattern); `u` after an `n`
restores that entry to `staged` with frontmatter byte-identical to before the discard;
`q` after one disposition leaves exactly the remaining 2 staged and exits 0; and an
unrecognised byte is ignored without advancing the queue.

### E2-L4-T5 — Make `e` edit the body and only the body

`E` in the design is "Edit the because" — the markdown body, which is the prose the human
is actually approving. It is not a frontmatter editor: a hand-edited `state` or `source`
would let a keystroke forge provenance. Open `$EDITOR` on the body alone, splice the
result back, and bump `updated`.

`files:` `internal/distill/edit.go`, `internal/distill/edit_test.go`.

`acc:` `go test ./internal/distill -run TestEditBody` passes with a fake `$EDITOR`: after
an edit that rewrites the body, the entry's frontmatter is byte-identical to before apart
from `updated`; an editor that also writes frontmatter-looking text into the body does
**not** change any frontmatter field; an editor exiting non-zero leaves the file
byte-identical and the entry still `staged`; an editor that writes an empty body leaves
the file unchanged and says so; `$EDITOR` unset produces one clear line naming the
variable and exits non-zero without touching the file; and the edited entry still
validates against `schema/entry.schema.json`.

### E2-L4-T6 — Handle the non-interactive and empty cases without hanging

`dira distill` will be run from scripts, from CI, and with a piped stdin, and a
raw-mode read on a non-TTY that blocks forever is the kind of bug that makes a tool
untrustworthy in exactly the automated setting dira lives in. Also: an empty queue is the
common case most days and must cost one line, not a screen.

`files:` `internal/distill/session.go`, `internal/distill/session_test.go`.

`acc:` `go test ./internal/distill -run TestNonInteractive` passes: with stdin not a TTY
and no input available, the command exits 0 within 1 second without entering raw mode and
without modifying any entry (asserted by a test timeout and a ledger sha256 comparison);
with a zero-length queue it exits 0 printing exactly one line and reads no input at all;
terminal raw mode is restored on every exit path including a simulated interrupt
(asserted by a fake terminal recording its mode transitions and requiring a matched
restore); and no exit path leaves a partially-written entry file (asserted by validating
every file in the ledger after each case).

### E2-L4-T7 — Write the printed copy to the design and the voice guide

This is the screen a demo screenshots (`.agents/product-marketing.md` §6 makes the demo
the single most important marketing asset), so the copy is part of the deliverable. Take
the structure from `docs/design/screens/s3-distill.html`: the *because* leads, the title
is the secondary label, the rejected alternative is shown because approving a decision
means approving what it rules out, the source line reads `PreCompact · 14:22 · semantic`,
and progress is visible. Take the register from §10: precise, unhyped, no
"successfully", no exclamation marks, name real ids.

`files:` `internal/distill/render.go`, `internal/distill/render_test.go`,
`internal/distill/testdata/*.golden`.

`acc:` `go test ./internal/distill -run TestRender` passes: the rendered card for a
fixture entry matches a golden file byte-for-byte; the body/because is rendered above the
title in the output (asserted by byte offsets, not by inspection); when the entry has a
non-empty `alternatives[]` the `why_not` is rendered and when it is empty nothing implies
one exists; the source line names the hook, the time, and the tier; the rendered output
contains none of `successfully`, `!`, `revolutionary`, `seamless`, `supercharge`, `10x`,
`AI-powered` (asserted by pattern); and every card renders within the terminal width
reported by the test harness without wrapping mid-word.
