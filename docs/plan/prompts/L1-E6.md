## Design is already done. This epic is implementation.

`docs/design/` contains the locked token layer (`tokens.css`), three gate-verified
screens, and `DESIGN.md` with the POV, three checkable laws, recorded law breaks, and
the render harness. **Do not redesign.** If you believe a design decision is wrong,
say so in your output rather than quietly diverging.

## Scope

`dira ui` serving the embedded SPA from the Go binary; the read-only public ledger
renderer (`dec-0010`); and closing the three open design questions in DESIGN.md.

## Specific things to get right

- **The renderer is the growth engine** (`dec-0010`), not a nicety — it is the answer
  to dira being invisible by design. It ships ahead of the apps.
- **It must never become required** (`cst-0004`). Read-only, stores nothing, no
  account to view, and the CLI behaves identically without it. Plan a lane that
  asserts the CLI works with the network unplugged.
- **The three open design questions are real work**, each already scoped in DESIGN.md:
  chain-at-scale (8 lines is legible, a 40-entry supersession chain is not — needs a
  collapse rule); long-content verification (screens are not yet tested against a
  400-word `why_not` or a 20-alternative decision); and the private-parent state
  (`qst-0001` — "unresolved" must not look like an error).
- **The design's own tests are inherited, not optional:** the contrast matrix must
  report 0 failures with hover exceeding rest in both schemes, and the 3-viewport ×
  2-scheme render gate must pass (console errors, blank mounts, byte-identical
  light/dark pair, layout shift).
- `docs/design/scripts/render.mjs` exists and works. Reuse it; Playwright currently
  lives outside the repo by design.
- Vercel's `web-interface-guidelines` skill is **not installed** and is the authority
  for the implementation layer. Plan installing it as a prerequisite.
