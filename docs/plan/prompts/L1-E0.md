## Why this epic exists

The roadmap assumed a Go project that **does not exist**. The repo today is docs,
a JSON schema, a `.dira/` ledger, and design mockups — no `go.mod`, no source, no CI,
no release path. `dec-0001` chose Go over Elixir and explicitly accepted the cost
("goreleaser instead of Burrito, a second formula in the existing tap, a separate
release workflow — a few days of setup, paid once"), but no milestone ever owned it.

**Everything else in the tree blocks on this epic.** Plan it as if it is the only
thing standing between the project and its first shipped artifact.

## Scope

Go module and package layout; the `dira` command skeleton; CI on push; goreleaser;
a formula in the **existing** `kazi-org/homebrew-tap` (do not create a new tap);
versioning; and a test that validates every `.dira/entries/*.md` against
`schema/entry.schema.json` so the ledger cannot drift from its own contract.

## Specific things to get right

- **Reuse, do not reinvent.** kazi already ships a Homebrew tap and a release
  pipeline. Read how `kazi-org/homebrew-tap` is structured before designing anything.
- **The schema validator is not optional.** 22 entries exist and a Python one-off
  currently validates them. That must become a Go test in CI, or the ledger silently
  rots. This is the highest-value single task in the epic.
- **Cold start is a requirement, not a hope** (`int-0002`, `dec-0001`). If the command
  skeleton pulls in a heavy framework, the whole language decision was pointless.
  Prefer stdlib `flag` or a minimal router over cobra unless you can justify it.
- Binaries for darwin-arm64 and linux-amd64 at minimum.
