# L1-E4 — Derived status

**Read `docs/plan/prompts/_L1-CONTRACT.md` first.** It defines lane structure, the
`acc:` rules, the bounds, and how to emit your L2 prompts. This file supplies scope only.

**Your epic:** E4 — Derived status
**L0 `acc:` line:** see the E4 section of `docs/plan.md`, verbatim. Your lanes must
collectively satisfy it; no single lane needs to.

## Scope

The `kazi portfolio --json` join, `dira map`, the six buckets, decision-blocked
detection, and degradation when kazi is absent.

## Specific things to get right

- **Status is never stored** (`dec-0004`). Not cached into entries, not written back.
  Plan a test that greps entry files for status fields and fails if any appear.
- **The real join surface, verified 2026-07-29** (`dec-0008`): `kazi portfolio --json`
  exists — `cli.ex:1254`, `portfolio_json/1` at `cli.ex:4249` — emitting
  `schema_version`, `kind`, `planned`, `by_repo`, `fleet_remote`, `totals`, `todo`,
  `blocked` (with `cause` and `blocker`), `rate`. Bucket enum is authoritative at
  `lib/kazi/portfolio.ex:55`: `[:done, :running, :blocked, :todo, :planned]`.
- **But `portfolio` is not registered in `Kazi.CLI.Schema`** (which covers only
  apply/plan/bus/status). The shape is versioned yet undocumented, so **pin it against
  a recorded fixture** and plan for E9 ask #1 possibly never landing.
- **Decision-blocked is the row only dira can produce** — an open question with a
  `blocks` edge, gating work before any goal exists. It appears in no execution
  tracker. Do not let it become an afterthought; it is the differentiator.
- **Degradation must be honest.** kazi absent or erroring means ledger-side buckets
  plus an explicit statement that execution status is unavailable. Never a guess,
  never a stale cache presented as live.
- `dira map` groups by **why**; `kazi portfolio` groups by goal. Do not rebuild
  portfolio.
