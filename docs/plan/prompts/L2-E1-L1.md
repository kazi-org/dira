# L2-E1-L1 — Commit the storage interface, the entry codec, and a deterministic 200-entry fixture

You are an L2 planner. Your job is to turn **one lane** into **tasks**, and nothing
else. **Write no Go code.**

## Context

**Epic:** E1 — the ledger (`docs/plan/lanes/E1.md`), roadmap M1.
**Lane:** `E1-L1`. **depends_on:** `E0` (the Go module, package layout, CI, and the
schema-validation test). No other E1 lane can start until this one lands, so it is
the critical path inside the epic.

**Lane `acc:` verbatim:**

> `go test ./internal/ledger/...` passes with (a) a round-trip test that reads every
> `.dira/entries/*.md` in this repo plus every entry of the generated 200-entry
> fixture, re-serializes each, and asserts the bytes are identical; (b) a test proving
> `created`/`updated` survive as RFC3339 **strings** — an unquoted input parses, the
> written form is quoted, and the test fails if the marshalled YAML round-trips the
> field as `time.Time`; (c) an import-boundary test that fails when any package other
> than the local backend imports `os`, `io/fs`, or `path/filepath` for a `.dira/`
> path; and (d) the fixture generator producing byte-identical output across two runs
> from the same seed, with all 200 entries passing E0's schema validator.

**What this lane is for.** `dec-0005` commits to a storage interface *before the
first surface ships*, with `local` as the only implementation and `github` arriving
in E7 needing no change above the interface. `dec-0002` makes every mutation a
single-file change. This lane builds that seam and the entry codec that sits on it,
plus the fixture every other E1 lane measures against. It does not build any user-
facing verb — `dira log` is `E1-L2`, `why` is `E1-L4`, `brief` is `E1-L5`.

## Constraints that bind this lane

- **The interface is expressed in entry-file operations, not filesystem operations.**
  Get / put / list / delete of an entry by id, plus whatever E1-L3 needs to enumerate
  for a reindex. No method may take or return a path, an `*os.File`, or a `fs.FS`, or
  the `github` backend cannot implement it (`dec-0005`).
- **YAML timestamps are strings.** Go's `yaml.v3` coerces an unquoted ISO timestamp
  to `time.Time`, which has already broken schema validation in this repo once. Quote
  on write; tolerate quoted and unquoted on read. This is a named landmine, not a
  hypothetical.
- **`additionalProperties: false`.** An unknown frontmatter key is an error on read,
  not a field silently dropped on write — a codec that drops keys would delete data
  on any round-trip through a newer schema.
- **The markdown body is content, not a field.** Everything after the closing `---`
  is the entry's prose *because*, preserved byte-for-byte including trailing newlines.
- **No network, no daemon, no process** (`int-0002`, `cst-0004`).
- **`E0-L1` asserts `go list -deps ./cmd/dira` contains no non-stdlib module.** Adding
  a YAML parser breaks that predicate legitimately, and E0's lane file says so. Plan a
  task that **replaces the clause with an allowlist** naming exactly the modules E1
  adds, still failing on anything else. Deleting the check instead is not acceptable —
  it is the only thing standing between the binary and a dependency tree that spends
  `int-0002`'s cold-start budget.

## Task bound and required fields

Produce **at most 8 tasks.** Fewer sharp tasks beat more vague ones. Each task needs:

| field | rule |
|---|---|
| `id` | `E1-L1-T<n>` |
| `title` | one line, imperative |
| `files` | the actual paths it touches |
| `acc:` | one machine-checkable predicate — a command and an observable outcome. It must be **red before the task and green after.** A predicate that a stub satisfies is a defect. |
| `depends_on` | task ids, or `none` |

Provisional paths (reconcile against E0): `internal/ledger/` (entry type, codec, ids,
the `Store` interface), `internal/ledger/local/` (the filesystem backend),
`internal/fixture/` (the generator), `internal/ledger/testdata/`.

**Your task set must cover all of the following.** How you group them is your call:

1. The entry type and its mapping to `schema/entry.schema.json`, including the
   per-kind `state` rules and the closed edge/kind enums (`cst-0002`).
2. The frontmatter codec: parse and serialize, byte-identical round-trip over the 22
   real entries, unknown-key rejection, body preservation.
3. The RFC3339-as-string guarantee, with a test that fails if `time.Time` coercion
   ever returns.
4. The `Store` interface and its `local` implementation, shaped so E7's `github`
   backend needs nothing above it.
5. The import-boundary test that mechanically enforces item 4.
6. The deterministic 200-entry fixture generator: realistic mix of the five kinds,
   real `derives_from`/`blocks`/`realized_by` edges, decisions carrying alternatives,
   at least one `private: true` entry, at least one entry with an `adr` path, seeded
   and reproducible, every entry passing E0's validator.

**On the fixture, decide and state your choice:** 200 committed files versus a seeded
generator writing into a temp dir. The lane file leans generator (200 committed files
add review noise to every future diff), but golden-output tests in E1-L3/L4 need
stability, so whichever you choose must be byte-reproducible. Say which, and why, in
the task that creates it.
