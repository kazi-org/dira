# L1-E2 — Capture

**Read `docs/plan/prompts/_L1-CONTRACT.md` first.** It defines lane structure, the
`acc:` rules, the bounds, and how to emit your L2 prompts. This file supplies scope only.

**Your epic:** E2 — Capture
**L0 `acc:` line:** see the E2 section of `docs/plan.md`, verbatim. Your lanes must
collectively satisfy it; no single lane needs to.

## Scope

`dira sniff` (regex tier), the Claude Code skill (semantic tier), the `Stop` and
`PreCompact` hooks, `dira install-hooks`, and the staged-entry disposition flow.

## Specific things to get right

- **Two tiers, two trust levels** (`dec-0003`). Regex output is *always*
  `state: staged` + `source.tier: regex`. A regex may never write an accepted entry or
  assert a `why_not`. The semantic tier is the already-running Claude session via the
  skill — **the binary never embeds a model client and never holds an API key.**
- **`PreCompact` is the insurance policy.** It fires immediately before Claude Code's
  lossiest moment. If it is slow, a compaction still eats the session — so it gets a
  longer timeout than the others but must still terminate.
- **Hooks fail open.** A non-zero `dira` exit must never block a session. This is
  testable: plan a lane that asserts it.
- **`dira install-hooks` mirrors kazi's proven contract** (`dec-0008`): merge-never-
  clobber, idempotent, operator keys preserved byte-identically, `--uninstall`
  reverting exactly, `--local` targeting the uncommitted settings file. Read
  `kazi`'s `install_hooks` implementation — do not reinvent it.
  `hooks/settings.example.json` documents what it must write.
- The disposition flow is the product's entire clerical surface. If confirming a
  staged entry takes more than one keystroke, the design has failed.
