Everything else in `docs/design/` is locked. Two specific traps:

- **Do not turn the chain into a widget.** Design law 3 is absolute: the graph is selectable,
  copyable, diffable text at every viewport, and "may never become an image, a canvas, or an
  SVG of glyphs". A collapse rule is a *typographic* rule — elided lines with a count, the
  way `git log --graph` elides — not a JavaScript tree control. The mobile form is already
  precedent: `.chain-stack` re-forms the same data rather than clipping it.
- **Do not collapse the alternatives into a comparison list.** A fresh-eyes reviewer proposed
  exactly that for density and `DESIGN.md` records the rejection: it "would destroy the
  struck-through refusal with its grounds beneath, which is the strongest device in the
  system and the reason this direction was chosen". A 20-alternative decision is a *layout*
  problem, not a licence to re-litigate that.

**You are not answering `qst-0001`.** That question is E5-L1's, and it blocks the workspace
tier. Which of its three candidate answers wins changes *what data arrives at the renderer*;
it does not change how an unreadable ref is *drawn*. Under answer 1 (opaque refs) the state
is required; under answer 2 (public alias entries) it is required for the interval before an
alias exists; under answer 3 (strip on publish) it is unreachable but harmless. So the state
is safe to design now, and the lane must say so rather than implying the question is settled.

### E6-L4-T1 — Build the hostile fixture ledger

A separate fixture from `ledger-design` (which exists to be pixel-compared and must stay
byte-matched to the mockups). This one exists to break things: a supersession chain 40 entries
deep, a decision with a 400-word `why_not`, a decision with 20 alternatives, an entry whose
`derives_from` points at a namespaced ref the renderer cannot read, a title long enough to
wrap three lines at 390px, and an unbroken 120-character token (a URL or an id) that would
force horizontal overflow if nothing wraps it.

**acc:** every file under `docs/design/fixtures/ledger-hostile/entries/` validates against
`schema/entry.schema.json`; the fixture contains, verified by a script that counts them, a
supersession chain of ≥40 entries resolvable end to end, ≥1 `why_not` of ≥400 words, ≥1
decision with ≥20 `alternatives`, ≥1 `derives_from` pointing at an unresolvable namespaced
ref, and ≥1 unbroken 120-character token; `dira ui` starts against it and every route returns
200; and the real `.dira/` and `ledger-design` fixture are unchanged.

### E6-L4-T2 — Define and implement the chain collapse rule

The rule must be stated before it is coded, in one paragraph, with its line budget as a
number. Constraints it must satisfy: the root intent, the focus entry, and the terminal node
are **always** visible; elision is marked with a count of what was elided, in the same
box-drawing typographic idiom (`.tree`, `--ink-low`); the elided span is reachable without
JavaScript (a link to an expanded view, not a disclosure widget); and the rendered result is
still the same shape `dira why` prints in a terminal, because `DESIGN.md`'s signature detail
is that the web chain and the CLI chain are the same output.

**acc:** the rule is written in `DESIGN.md` with an explicit numeric line budget, and a
script asserts the rendered `.chain` on the hostile fixture's deepest entry never exceeds it
at any of the three viewports while always containing the root id, the focus id, and the
terminal node id; the elision marker states the number of elided entries and that number
equals the actual count elided (changing the fixture's chain depth changes the number);
following the elision link yields a page containing every elided id; the `.chain` contains no
`<svg>`, `<canvas>`, `<img>` or `<details>`; the served `<style>` block and
`docs/design/screens/s1-decision.html`'s remain byte-equal after the change; and the same
chain rendered for a short entry (the real `.dira/dec-0001`) is **unchanged** from E6-L2's
output, proven by pixel diff at 0.00% — the collapse rule must not touch the legible case.

### E6-L4-T3 — Prove the collapsed chain is still text

Design law 3's test is "select-all on any chain yields the ids and reasons as text". With a
collapse rule in place that test gets harder and more important.

**acc:** `laws.mjs` gains a check that selects the `.chain` region on the served page and
asserts the extracted selection text contains every visible id and every visible reason
string, at all three viewports, for both the collapsed hostile chain and the short real one;
the check **fails** when the chain is temporarily replaced by an `<img>` with the same
`alt` text, demonstrated; the mobile `.chain-stack` is subject to the same assertion; and the
extracted text preserves line order so a copied chain is still readable as a tree.

### E6-L4-T4 — Survive long content at every viewport

WEB.md 9's requirement, applied to the three places the mockups were never stressed: a
400-word `why_not` under `.arg .grounds` (which has `max-width: 64ch`), 20 `.arg` blocks in
sequence, and long unbroken tokens anywhere. The fix is layout — wrapping, measure, and
overflow containment — not restructuring the alternatives. The struck-through refusal with
its grounds beneath survives intact.

**acc:** on the hostile fixture, `document.body.scrollWidth` equals the viewport width at
390px, 1024px and 1440px in both schemes (zero horizontal overflow), and no descendant
overflows its container, asserted by a script; the 400-word `why_not` renders in full with no
clamping or truncation and holds its `max-width` measure; the 20-alternative decision renders
all 20 `.arg` blocks with exactly one `.arg.upheld`, still struck through with grounds
beneath and `--caught` nowhere; the 120-character token wraps or scrolls within its own
container rather than widening `body`; the `render.mjs` gate reports no layout shift on any
hostile route; and the short real entry's rendering is unchanged, proven by a 0.00% pixel
diff against E6-L2's baseline.

### E6-L4-T5 — Design the unresolved-ref state

`DESIGN.md`: "'unresolved' must not look like an error." Design law 1: `--caught` is drift and
`dira check` failures only — an unresolved parent is neither, it is a record of a boundary.
`cst-0003` sets the hard limit: the ref may appear, the private parent's **title and text may
not**, and a violation is a security bug. The state must also be honest about what it cannot
distinguish — `qst-0001` records that the orphan-drift flag can no longer tell "no parent"
from "private parent I cannot see", and the rendered page should not claim otherwise.

**acc:** the hostile fixture's unresolvable `derives_from` renders in `--ink-low` with the
literal word `unresolved` and the ref shown verbatim (e.g. `sire:int-0002`), with no
`--caught` token in any rule that applies to it and no `⚠` glyph; the entry is **not** counted
in the drift roll-up as an orphan, and the page states that the parent is outside this ledger
rather than absent; a test asserts no title or body text from any entry outside the served
ledger appears anywhere in the response — including in `<title>`, `aria-label`, and HTML
comments — and **fails** if a resolver is made to inline the parent's title, demonstrated;
this state is added to `docs/design/screens/s1-decision.html` so mockup and served markup stay
byte-equal; and `qst-0001` is left `state: open` and unmodified.
