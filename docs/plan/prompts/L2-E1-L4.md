## Constraints that bind this lane

- **The chain is type, never a picture** (DESIGN.md law 3). Box-drawing characters,
  selectable, copyable, diff-able. No ANSI-art boxes, no unicode that only renders in
  one font.
- **Neutral refusals** (DESIGN.md law 1). `--caught` red is reserved for drift,
  contradiction, and `dira check` failures — none of which are this lane's.
- **One screen** is the target for a typical entry. If a chain at scale does not fit,
  the collapse rule is an **open design question in DESIGN.md** (chain-at-scale
  collapse) owned by E6 — do not invent a collapse policy here; state the limit you
  hit and let it bind terminal and web together.
- **Output is a structured chain first, text second.** E6 renders the same chain in
  HTML. Plan for one producer with two renderers, so the terminal and web forms cannot
  drift.
- **`realized_by` targets are external URIs** (`kazi:goal-…`) and are printed
  verbatim. This lane must **not** call kazi, resolve a goal's status, or imply
  doneness — that is `dec-0004` and E4.
- **Term resolution must be predictable.** `dira why daemon` matching by term is in
  the design; a fuzzy matcher that silently picks one of five entries is worse than
  one that lists the candidates. Decide the rule and make the golden test pin it.

## Task bound and required fields

Produce **at most 8 tasks.** Each needs `id` (`E1-L4-T<n>`), `title`, `files`,
`acc:` (a command and an observable outcome; red before, green after; a predicate a

Provisional paths (reconcile against E0): `internal/why/` (chain construction and the
text renderer), `cmd/dira/` (the `why` subcommand), plus a golden-file directory.

**Your task set must cover all of the following:**

1. Chain construction: walk `derives_from` upward and `supersedes`/`informs`/`blocks`
   as the design requires, with cycle safety — a `derives_from` cycle must not hang.
2. The text renderer: box-drawing, no ANSI graphics, neutral refusals, `revisit_if`
   rendered when present.
3. Query resolution: by id, and by term with a stated, tested disambiguation rule.
4. The golden-file test over this repo's **real** ledger (not only the fixture), so a
   renderer regression shows up as a diff a human can read.
5. Error and empty cases: unknown ref, an entry with no alternatives, an entry with
   no parents, a superseded entry (it must show that it was superseded and by what).
6. The structured-chain output E6 will consume — shape it now, even if E6 renders it
   later, and state the contract in the task.
