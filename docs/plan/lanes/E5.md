# E5 — Tiers — lanes (L1)

**Epic:** E5, `docs/plan.md` §E5. **Prompt:** `docs/plan/prompts/L1-E5.md`.
**Status lives in `docs/roadmap.md` (M5), not here.**

**No L2 prompts were emitted for this epic, and that is deliberate.** `qst-0001` is
`state: open`. Every lane below L1 encodes an assumption about what a public repo
ledger may contain when its parent is private, and `cst-0003` makes a wrong assumption
a **security** defect rather than rework — a private strategic note committed into
public git history cannot be un-published. Task-level files written now would be
rewritten wholesale, and the dangerous failure is not the rewrite: it is a task that
survives the rewrite because nobody re-read it.

**Lanes E5-L2 … E5-L5 are provisional.** They are shaped by the *mechanisms*
`dec-0006` already fixes (namespaced refs through `[parents]`, one drift flag) which
hold under all three candidate answers, but their predicates name a resolution model
that L1 has not yet chosen. Re-derive L2-L5 after `qst-0001` is answered; do not
promote them to L2 prompts before then.

### E5-L1 — Answer qst-0001 and record the resolution model as a decision

**acc:** `.dira/entries/qst-0001.md` reads `state: answered`; a new `dec-00NN` entry
exists carrying `derives_from: dec-0006`, an edge to `qst-0001`, and an
`alternatives[]` array with ≥2 items whose `option` strings name the two rejected
candidates from `qst-0001` and whose `why_not` strings are non-empty; every ref in the
new entry resolves to a file under `.dira/entries/`; and
`grep -rn "qst-0001" docs/ | grep -i block` returns no rows in `docs/roadmap.md` or
`docs/plan.md`. Currently red: `qst-0001` is `open` and no such decision entry exists.

**Why the answer must be a decision entry and not prose in the question body.** The
schema has no field for a question's answer (`schema/entry.schema.json`,
`additionalProperties: false`), and the rejected candidates have to land in
`alternatives[].why_not` because that array is the substrate `dira check` reads to stop
relitigation (E3). An answer recorded only as prose is an answer the enforcer cannot
cite.

**risk:** answering it as an implementation detail. The entry itself says the question
is really "who is the public `.dira/` *for*" — decide that first, in writing, or the
mechanism gets chosen and the audience gets inherited by accident.

**entries:** `qst-0001` (answers), `dec-0006` (blocked by it), `cst-0003` (constrains
the answer, and see the appendix on whether the answer supersedes it), `dec-0010`
(names the public ledger's audience), `.agents/product-marketing.md` §3.

### E5-L2 — Resolve namespaced refs through `[parents]`, downward and read-only

Scope: the `.dira/config.toml` contract for this epic — `ledger.tier` and the
`[parents]` map, including whatever marker L1's answer requires for a declared-but-
unreadable parent — plus the resolver, and the `cst-0003` enforcement tests. This lane
owns the config keys; L3-L5 consume them and must not add their own.

**acc:** over a three-tier fixture (`me/` → `sire/` → `repo/`) a resolution test
passes, and: with the `me` ledger readable, resolving `me:int-0002` from `repo/`
returns the parent entry; with the same parent made unreadable (path absent or
mode 000) the resolver exits 0 and reports the ref in the withheld state rather than
erroring; after both runs `git status --porcelain` in `repo/` is empty, and a canary
string present only in a parent entry's body is absent from every file under
`repo/.dira/` (`grep -r <canary> repo/.dira/` finds nothing). Red today: no Go module
exists.

**risk:** the resolver acquiring a write path. `cst-0003` rule 1 says dira has **no
verb** that writes upward; a resolver that caches a parent entry to disk under the
child's tree satisfies every functional test and is a security bug. The canary grep in
the predicate exists for exactly that, and it must stay two-sided — it has to fail if
the caching is added back.

**entries:** `dec-0006` (namespaced refs, `[parents]`), `cst-0003` (all three rules),
`cst-0004` (a parent is fetched as files, never over a service), `dec-0002` (the parent
is a directory of files, so resolution is a read of that directory).

### E5-L3 — Make the orphan-work drift flag distinguish three states, not two

Scope: the drift computation and its rendering in the workspace report
(`docs/design.md` §8.1). The distinction is already present in the data — an entry with
a `derives_from` edge whose target does not resolve is not the same object as an entry
with no `derives_from` edge at all — so this lane is about not collapsing them.

**acc:** over a fixture where intent A has no `derives_from`, B derives from a
resolvable parent, and C derives from a withheld parent, the workspace report flags
exactly A as drift, renders C as withheld-parent and **not** as drift, and renders B as
oriented; re-running with C's parent made readable moves C to oriented and leaves the
drift set unchanged ({A}); and `git status --porcelain` is empty after every run — no
derived state is written into any entry file (`dec-0004`). Red today: no binary.

**risk:** the flag becoming a warning nobody reads. Its value is that unexplained work
is *structurally* visible; if withheld-parent renders with the same weight as genuine
orphan work, every public ledger looks like drift and the signal is spent — which is
precisely the objection that sinks candidate 3 in `qst-0001`.

**entries:** `dec-0006` (the orphan flag), `dec-0004` (status derived, never stored),
`qst-0001` (its candidate 3 is the failure mode this lane's predicate rules out).

### E5-L4 — Workspace and personal tiers: the inherited brief chain and the few-intents cap

Scope: `tier` semantics for `person` and `workspace`, the `SessionStart` chain
(repo context + the workspace bet it serves + current personal focus, `docs/design.md`
§8.2), and the cap-is-the-clarity rendering.

**acc:** in a repo fixture declaring both parents, the brief emits all three tiers of
the chain and is ≤1500 tokens by the binary's own counter with any omission named
(`cst-0001`); every entry in a `tier = "person"` fixture is treated as `private: true`
without the field being set, asserted by a test that a check message written to a
public path contains the private ref (`me:cst-0002`) and **zero** characters of that
entry's title or body; and a workspace fixture holding 12 active intents renders all 12
with the cap surfaced as a warning — the test fails if any intent is hidden or the list
is truncated. Red today: no binary.

**risk:** designing the cap away. Twelve active intents *is* the absence of clarity
rendered legibly (`dec-0006`); a tidy implementation that paginates or trims the list
deletes the only signal the personal tier exists to produce.

**entries:** `dec-0006` (tier mix, the cap), `cst-0003` (rule 3, ref-only citation),
`cst-0001` (the token ceiling applies to the *chain*, not just the local brief),
`int-0001` (a brief that does not fit on one screen will not be read).

### E5-L5 — `dira init --interview` — no successful init produces an empty ledger

Scope: the interview flow that seeds a workspace or personal ledger, and the guarantee
in `dec-0010` that a fresh ledger is never empty. The **import** half of onboarding is
excluded — see risk.

**acc:** `dira init --interview` driven from a scripted answer fixture (no live model —
`dec-0003`) produces a ledger containing ≥1 intent, ≥1 constraint and ≥1 question, all
of which validate against `schema/entry.schema.json`, and the brief run immediately
afterwards is non-empty; and an aborted or unanswered init exits non-zero leaving **no**
`.dira/entries/` directory behind, asserted by a test that fails if any code path
yields an initialized ledger with zero entries. Red today: no binary.

**risk:** this lane silently absorbing ADR/history import, which is blocked on
`qst-0003` and is a launch blocker in its own right per `dec-0010`. Interview and
import are both first-experience paths; only interview is plannable now. If the
interview alone cannot clear the empty-ledger bar for a *repo* tier ledger, say so
rather than reaching for import.

**entries:** `dec-0010` (init may never produce an empty ledger; import is the day-1
acquisition moment), `dec-0003` (no model client in the binary — the interview is
conducted by the already-running session, not by dira), `qst-0003` (the excluded half),
`cst-0002` (the interview may only produce the five kinds).

## Appendix — a recommendation on qst-0001

**RECOMMENDATION ONLY. `qst-0001` is still `state: open`.** Nothing here is a decision,
no lane may proceed as if it were, and this appendix is not the recorded rationale
E5-L1 must produce.

**Recommend candidate 1 — opaque refs — with one refinement.** Not because it is
cheapest, which is how the entry frames it, but because it is the only candidate
consistent with the constitution already in place.

1. **`cst-0003` rule 3 has already answered this for the adjacent case.** Where a check
   must cite a private constraint in a public context, "it cites the **ref only**
   (`me:cst-0002`), never the text." A `derives_from: sire:int-0002` edge in a public
   entry *is* that construction. Candidate 1 is the existing rule applied consistently;
   candidates 2 and 3 both require superseding an accepted constitutional constraint —
   2 by publishing derived content from a private parent, 3 by suppressing a ref the
   rule expressly permits. That asymmetry is the strongest argument available and the
   entry does not mention it.

2. **The audience question the entry says must be settled first is already settled
   elsewhere.** `dec-0010` makes the public renderer the growth engine, and
   `.agents/product-marketing.md` §3 names the secondary segment as the OSS maintainer
   who "wants contributors to stop asking *why is it built this way?* — a public dira
   ledger answers it once." That is documentation of the maintainer's reasoning that
   contributors *read*. It is not a shared planning surface: contributors do not write
   entries into the parent chain, and nothing in the design gives them a verb that
   would. By `qst-0001`'s own closing sentence, that reading makes candidate 1
   sufficient.

3. **Candidate 2 is disqualified on kind, not on cost.** A redacted public stub is a
   private→public *write* path whose safety depends on a human judgment made under time
   pressure on every write. `cst-0003` exists precisely because this boundary must be
   "enforced by the architecture rather than by care." Candidate 2 converts an
   architectural guarantee into a recurring judgment call, and the duplicate-drift
   problem the entry already names is the second-worst thing about it.

4. **Candidate 3 is the one that looks safest and is worst.** It makes the public
   artifact misrepresent the graph: the edge exists, and the published record denies it.
   Two concrete costs. First, it destroys the drift signal in the exact surface where a
   stranger evaluates the product — every adopting repo's ledger reads as unexplained
   work, which inverts `dec-0006`'s claim that the flag is the mechanism answering "what
   are we actually doing?". Second, "strip on publish" presumes a publish step, and
   `dec-0002` is built on there not being one: the files in git *are* the ledger, which
   is what makes `git log -p` a review surface and what lets the record outlive the
   tool. A transform between the working tree and the committed tree adds a new failure
   class — did the strip run? — to the one area where a miss is unrecoverable.

5. **The refinement, which removes candidate 1's only real cost.** The entry's
   objection is that the drift flag can no longer tell "no parent" from "private parent
   I cannot see." It can — that distinction is in the data, and collapsing it is an
   implementation choice, not a consequence of opaque refs. Resolution should report
   three states: **oriented** (edge present, target resolved), **withheld** (edge
   present, parent namespace declared but not readable here), **orphan** (no
   `derives_from` edge at all → drift). Only the third is drift. To let a reader tell
   withheld from broken, `[parents]` should be able to declare a namespace as private
   without a readable path — a `visibility = "private"` marker in `.dira/config.toml`,
   with the human-facing label optional so the venture name itself need not ship. This
   needs no schema change (`entry.schema.json` already permits namespaced refs at
   `$defs/ref` and already has `private`), no supersession, and no second copy of
   anything. It also supplies the state `docs/design/DESIGN.md:229` says is currently
   undesigned and "must not look like an error."

**What leaks under this answer, stated plainly:** the existence of a private parent
ledger, its namespace, and an integer id. No title, no body, no edge notes. The
namespace is typically the venture name, which is public anyway; where it is not, the
marker's label can be omitted while the ref remains. That is a real disclosure and it
should be written into the decision's own body rather than left for someone to discover.
