### E6-L1 — Build the fidelity gate the rest of E6 is measured by

**acc:** `node docs/design/scripts/contrast.mjs` reports `0 failures` and `hover > rest`
for all six surface/scheme combinations against the committed `tokens.css`, and exits
non-zero reporting ≥1 failure under `--probe-regression` (which substitutes the pre-r4
light `--bearing-lift` value `#b8862f`); `node docs/design/scripts/pixeldiff.mjs A.png A.png`
reports `0.00%` while any light PNG against its dark pair reports `>1%`; `render.mjs`
fails a target that loads any asset from a host other than `127.0.0.1`; every file in
`docs/design/fidelity/fixtures/ledger-design/` validates against `schema/entry.schema.json`; and
`DESIGN.md` states a numeric pixel tolerance and its token table matches `tokens.css`
value-for-value.

**risk:** The harness certifies itself. A cheap model can write a contrast script that
prints `0 failures` unconditionally — which is why every check in this lane is two-sided
(a known-bad input must produce a failure) and why the negative controls are in the
`acc:` line rather than in prose.

**entries:** constrained by `cst-0004` (no network dependency in the toolchain — Playwright
stays in the session scratchpad, gitignored, per `DESIGN.md`), `dec-0002` (fixture entries
are one file each and schema-valid).

### E6-L2 — Serve the read-only surfaces from the Go binary

**acc:** `dira ui` serves `s2-index` at `/` and `s1-decision` at `/e/<id>` over the same
query path the CLI uses; against the repo's own `.dira/` every id under `.dira/entries/`
appears in the served index (real ledger, not fixtures); against
`docs/design/fidelity/fixtures/ledger-design/` both routes pixel-diff within the tolerance
recorded in `DESIGN.md` from freshly regenerated `docs/design/screens/` baselines at
3 viewports × 2 schemes with the `render.mjs` gate passing and zero non-loopback asset
requests; the served `tokens.css` is byte-identical to `docs/design/tokens.css` and a Go
test fails on any drift; `grep -oE '#[0-9a-fA-F]{3,6}'` over every served HTML body
returns only `#0f151c` and `#f7f4ed`; and both routes render their full content with
JavaScript disabled.

**risk:** Fidelity is claimed instead of measured. The lane passes only if the pixel
baseline is regenerated in the same run and the same environment as the capture — a
stale or hand-committed baseline makes the whole gate decorative. (The renders directory
is gitignored, which forces regeneration; that is a feature here, not an obstacle.)

**entries:** implements `dec-0010` (the renderer surface), reads through `dec-0005` (the
storage interface, `local` backend), constrained by `cst-0004` (works with the network
unplugged), `dec-0004` (status is derived at read time and never stored — the index's
roll-ups and `converged` markers are joins, not fields), `int-0002` (one binary, no
daemon, no port to own permanently).

### E6-L3 — Serve the distill surface, keyboard and no-JS alike

**acc:** `dira ui` serving `docs/design/fidelity/fixtures/ledger-design/` renders `/distill`
pixel-within-tolerance of a freshly regenerated `s3-distill` baseline at 3 viewports ×
2 schemes with the gate passing; a script reads the *served* DOM's computed styles and
asserts `.stage .because` font-size exceeds `.stage .titleline` font-size at all three
viewports (design law 2, measured not eyeballed); Confirm and Reject work with
JavaScript disabled — a form POST changes the entry file on disk and a subsequent GET no
longer offers that entry — and with JS enabled `Y`/`N`/`E` produce the same file change
without a full page load; and the mobile swipe hint is present at 390px and absent at
1440px.

**risk:** The seam with E2. E2 owns the staged-entry disposition state machine; this lane
owns only the surface and must call into it. If this lane reimplements disposition, two
state machines exist and they will disagree — so the lane's write path must go through
E2's exported function, not through its own file writes.

**entries:** implements the dispose-surface half of `docs/design.md` §9, reads and writes
through `dec-0005`, constrained by `dec-0003` (regex-tier entries arrive `staged` with
`source.tier: regex` and this surface must never present them as accepted), `dec-0002`
(one file write per disposition).

### E6-L4 — Close the three open design questions against hostile data

**acc:** against a hostile fixture ledger containing a 40-entry supersession chain, a
decision with a 400-word `why_not`, a decision with 20 alternatives, and an entry whose
`derives_from` points at a ref the renderer cannot read, every route passes the
`render.mjs` gate at 3 viewports × 2 schemes with no horizontal overflow on `body` and no
post-load layout shift; a script asserts the rendered chain never exceeds the documented
line budget while always showing the root, the focus entry, and the terminal node, and
that select-all on a collapsed chain still yields every visible id as text (design law 3
— the graph stays type); the unreadable ref renders in `--ink-low` carrying the literal
word `unresolved`, and `grep` for `--caught` over all served HTML matches only drift and
`dira check` states (design law 1); and `DESIGN.md` records the collapse rule, the
long-content result, and the unresolved-ref state, with `docs/design/screens/` updated in
step so the mockups and the served pages remain the same markup.

**risk:** This lane is where "do not redesign" is easiest to violate. Its licence is
narrow: `DESIGN.md`'s own *Open design questions* section, and nothing else. A collapse
rule that turns the chain into a widget, or a long-content fix that collapses the
alternatives into a comparison list, would break the device `DESIGN.md` explicitly
protected when it rejected exactly that fix in r3→r4.

**entries:** informed by `qst-0001` — this lane renders the *unresolved* state and does
**not** answer the question. Which of qst-0001's three answers wins changes what data
arrives; it does not change how an unreadable ref is drawn. Also constrained by
`cst-0003` (a private parent's text and title never appear; the ref alone does) and
`cst-0001` in spirit — a chain nobody can read reproduces `int-0001`.

### E6-L5 — Ship the public renderer and prove it is additive

**acc:** `dira render --out <dir>` over the repo's own `.dira/` emits static HTML in
which every id under `.dira/entries/` is reachable, which opens from `file://` with zero
external requests, passes the `render.mjs` gate at 3 viewports × 2 schemes, carries the
attribution sentence on every page, and contains no `<form>`, no `/distill` page, and no
mutating affordance; a suite runs `log`, `why`, `brief`, `map`, `check`, `ui`, and
`render` with every non-loopback dial forced to fail and all seven exit 0 with unchanged
output; and the export contains no title or body text from any entry marked
`private: true` or from a `tier = "person"` ledger, only its ref.

**risk:** The additivity claim is the one an audience will actually check, and the
failure mode is silent: one `<img src="https://…">`, one analytics snippet, one font
fetch, and "your data never touches our servers" becomes false in a way no test catches
unless the test is written first. Second risk: a signed-out visitor path that needs
anything dira operates would drag Tier 3 (`docs/design.md` §9) forward by a year.

**entries:** implements `dec-0010` (the growth engine, read-only, stores nothing, no
account to view), enforces `cst-0004` (never required) and `cst-0003` (no leakage through
derived artifacts — a hosted render is named there explicitly), reads through `dec-0005`.
Copy follows `.agents/product-marketing.md` §7 and §10: compounding organic distribution,
never virality, and never implying the renderer is required.

## Divergences proposed, not taken silently

Both concern written architecture in `docs/design.md`, not the locked design. Each is a
task in the lane that hits it, and each lands as a dira entry with its reasoning — not as
a quiet code choice.

1. **Server-rendered HTML, not a client-side SPA.** `docs/design.md` §9 and `docs/plan.md`
   §E6 both say "static SPA". The three built screens contain zero JavaScript, and the
   growth engine depends on pages a crawler can read (`.agents/product-marketing.md` §7,
   channel 4: "every rendered decision page is a page answering *why did project X choose
   Y*"). An SPA makes those pages invisible to exactly the channel they exist to feed, and
   buys nothing on localhost, where the data is already in-process. Proposal: Go
   `html/template` + `embed.FS`, JavaScript only as progressive enhancement on `/distill`.
   Recorded in E6-L2-T1.
2. **The public renderer is a static export, not a service dira operates.** `dec-0010`
   settles *that* the renderer ships and that it stores nothing; it does not settle what
   serves it, and `docs/design.md` §9 puts hosted rendering in Tier 3, "much later".
   `dec-0005` already rejected dira-operated infrastructure for sync on ops-burden grounds
   — a solo maintainer cannot carry on-call alongside kazi — and that reasoning transfers
   intact. Proposal: `dira render` emits static HTML the user deploys to their own GitHub
   Pages, so M6 needs no dira-operated infrastructure at all. Recorded in E6-L5-T1.

## Known defects in inherited documents

- **`DESIGN.md`'s token table contradicts `tokens.css` in three of four rows** —
  `--bearing` light (`#9a6c1c` vs `#8a5f18`), `--bearing-lift` light (`#b8862f` vs
  `#6d4a12`, the pre-r4 value the r3→r4 section describes fixing), `--caught` dark
  (`#d4614d` vs `#d97060`). `tokens.css` is the declared single source, so the table is
  drift. Reconciled in E6-L1-T6, and the stale `#b8862f` is reused as the contrast
  script's negative control.
- **`docs/plan.md` §E6 `acc:` cites "the pixel tolerance recorded in DESIGN.md", which
  does not exist.** No tolerance is recorded anywhere. E6-L1 establishes and records one;
  until it does, that clause of the L0 predicate is unfalsifiable.
- **The contrast matrix is an inherited test with no artifact.** `DESIGN.md` requires it
  re-run "whenever a colour token moves", but `docs/design/scripts/` contains only
  `render.mjs`. It was run ad hoc during the design phase and cannot currently be re-run.
  E6-L1 writes it.
