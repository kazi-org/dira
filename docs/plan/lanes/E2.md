# E2 — Capture · lanes (L1)

**Epic:** E2 — Capture (`docs/plan.md` §E2, roadmap M2)
**L0 `acc:` (verbatim):**

> a recorded transcript fixture containing decision language yields ≥1 staged entry
> and zero accepted entries; `dira install-hooks` is idempotent and `--uninstall`
> restores the settings file byte-identically; hooks fail open — a non-zero `dira`
> exit never blocks a session.

**Four lanes.** L1 covers clause 1, L3 covers clauses 2 and 3, L2 covers the tier-2
half of `dec-0003` that no L0 clause asserts, L4 covers the disposition surface the
whole epic exists to feed. Status lives in `docs/roadmap.md`, not here.

### E2-L1 — Build `dira sniff` — the regex tier that may only ever stage

**acc:** `go test ./internal/sniff` passes against `testdata/transcripts/` holding ≥3
recorded Claude Code transcripts, asserting on the entries actually written to a temp
ledger: every entry has `state: staged`, `source.tier: regex`, `source.hook: Stop`, and
a non-empty bounded `source.excerpt`; **zero** entries are in `accepted`, `active`, or
`open`; **zero** entries carry a non-empty `alternatives[]` or any `why_not`; every
written file validates against `schema/entry.schema.json`; and a fixture with no
decision language writes no file and, under `--quiet`, prints nothing and exits 0.

**risk:** the regex fires on hypotheticals. A transcript full of *"we could go with X"*
and *"suppose we don't do Y"* stages a ledger of decisions nobody made, and the distill
queue becomes a chore — which is `int-0001`'s failure with new syntax. The negative
fixture in the `acc:` line is the guard, and it must contain deliberate near-misses,
not merely unrelated text.

**entries:** implements `dec-0003` (tier 1), `dec-0002` (one file per entry),
`cst-0004` (offline, no network); constrained by `cst-0002` (five kinds, closed) and
`schema/entry.schema.json`.

**Two schema conflicts this lane must resolve before it writes anything** — both are
real, both are named in `L2-E2-L1.md` as its first task:

1. **`state: staged` is valid only on `kind: decision`.** The schema's `allOf` gives
   `question` the enum `open | answered`. But `docs/design/screens/s3-distill.html`
   puts a staged `qst-0006` in the distill queue, and writing a regex-inferred question
   straight to `open` makes the ledger assert an open question no human ever saw.
2. **`kind: decision` requires `alternatives`, and a regex may not assert a
   `why_not`.** `alternatives: []` satisfies the letter of the schema (no `minItems`)
   while violating its stated intent — *"a decision without alternatives is an
   assertion"*. The honest fix is conditional: `minItems: 1` unless `state: staged`.

### E2-L2 — Build the semantic tier: the skill and the `--deep` handoff, with no model client in the binary

**acc:** `go test ./internal/sniff -run TestDeepHandoff ./internal/skill ./internal/nomodel`
passes: `dira sniff --deep --stage` on `testdata/transcripts/pre-compact.jsonl` both
stages the regex candidates **and** emits a handoff block on stdout naming each staged
id plus the fields the live session must fill (`because` body, `alternatives[].why_not`,
`derives_from`); a linkage test over `go list -deps ./cmd/dira` fails if any
model-provider client module is linked and if any non-test source file references an
API-key environment variable; and the skill's own documented `dira log` invocation,
replayed verbatim from `testdata/skill/`, produces an entry that validates against
`schema/entry.schema.json` with `source.tier: semantic`, `confirmed_by` absent or
non-`human`, and ≥1 `alternatives[].why_not`.

**risk:** the handoff mechanism may not exist. `dira sniff --deep` cannot *ask* the
session anything — it is a subprocess. It works only if `PreCompact` hook stdout is
actually injected into the session's context by Claude Code, and unlike `SessionStart`
that is not established here. If it is not, `--deep` degrades to "stage the regex
candidates and leave a note for the next turn", the PreCompact insurance policy is
weaker than `settings.example.json` claims, and the claim in that file needs correcting
rather than the test being loosened. Task 1 of the lane is to determine this against
Claude Code's real hook contract and record the finding as a `.dira/` entry.

**entries:** implements `dec-0003` (tier 2, and the no-model-client rule this lane
turns into a build-time test); constrained by `cst-0004` (no network, no account),
`int-0002` (no daemon), `cst-0001` (the handoff block is not a brief and must not grow
into one).

### E2-L3 — Build `dira install-hooks` to kazi's proven contract, and prove hooks fail open

**acc:** `go test ./internal/installhooks` passes with, against a temp settings
directory: (a) installing into a `settings.json` that already holds an operator's own
hooks and unknown top-level keys leaves every pre-existing entry present and unchanged;
(b) a second install is a no-op — file bytes identical, exit 0, `UNCHANGED` on stdout;
(c) `--uninstall` immediately after a fresh install restores the pre-install bytes
exactly (equal sha256), and deletes the file if and only if install created it;
(d) `--local` writes `.claude/settings.local.json` and never a committed
`.claude/settings.json`; (e) malformed input JSON writes nothing and exits non-zero;
(f) **every command string the installer writes is accepted by the built binary** — the
test parses the installed settings and rejects any unknown flag; and (g) a fail-open
test that puts a `dira` on `PATH` exiting 1 shows each installed `Stop` and `PreCompact`
command string still exiting 0.

**risk:** reinventing what kazi solved. The clobbering failure mode is already paid for
at `/Users/dndungu/Code/kazi-org/kazi/lib/kazi/teach/install_hooks.ex` with a test suite
at `test/kazi/teach/install_hooks_test.exs`; a fresh Go implementation that does not
port those cases will rediscover them on somebody's hand-tuned settings file. The
second risk is clause (f): `hooks/settings.example.json` currently writes
`dira brief --context --chain`, and `--chain` walks the tier parents that belong to
**E5, which is blocked**. Writing a flag the binary rejects produces a hook that fails
open and silently never briefs — the worst possible failure, because it looks like
success.

**entries:** implements `dec-0008` (mirror kazi's `install-hooks` contract exactly);
constrained by `cst-0004` (nothing installed needs a network), `int-0002` (no daemon).
Documents itself against `hooks/settings.example.json`.

### E2-L4 — Build the disposition flow — one keystroke per staged entry

**acc:** `go test ./internal/distill` passes against a temp ledger seeded with 3 staged
entries: a scripted stdin of exactly the three bytes `y`, `n`, `e` disposes all three,
after which no entry in the ledger has `state: staged` and a second `dira distill` exits
0 printing one line; the confirmed entry gains `confirmed_by: human` and a state legal
for its kind; the discarded one leaves **no** entry that a later reader could cite as
rationale (no `accepted` or `rejected` decision exists carrying `source.tier: regex`
without `confirmed_by: human`); `e` changes only the markdown body, leaving frontmatter
byte-identical apart from `updated`; and stdout contains no second confirmation prompt
between cards.

**risk:** "Reject" is two different verbs wearing one button.
`docs/design/screens/s3-distill.html` offers Confirm / Reject / Edit, but rejecting a
*bad capture* ("the regex misread me") and recording a *decision against an option*
("we considered a daemon and said no") are not the same act, and the schema has exactly
one word — `rejected` — which `dira check` (E3) will later cite as binding rationale.
Conflating them means a regex misfire gets quoted back at the user three weeks later as
their own reasoning. This lane must separate the two before it writes the keymap; the
`acc:` line is worded to hold under either resolution.

**entries:** implements `dec-0003` (staged output requires human disposition),
`dec-0002` (one file write per mutation); constrained by `cst-0002`,
`schema/entry.schema.json`, and `.agents/product-marketing.md` §10 for the wording of
every line it prints.

## Boundaries worth stating, so two lanes do not build the same thing

- **The `SessionStart` hook entry belongs to E2-L3, `dira brief` belongs to E1.**
  `install-hooks` writes all three hook entries, including `SessionStart`. E1 owns the
  command that entry invokes. Neither should grow its own installer.
- **`dira log` belongs to E1.** E2-L2's skill *calls* it and must not reimplement entry
  writing; E2-L1 writes staged entries through the same E1 writer.
- **`dira check` belongs to E3.** The lifecycle in `docs/design.md` §10 has the skill
  run it at step 4; E2 stops at capture and disposition.
- **Automatic capture of kazi dispositions is out of scope for E2.** It is blocked on
  `qst-0005` issue 2 and tracked in the roadmap's Blocked table; the recorded fallback
  is that the skill wraps `approve`/`reject`, which is E2-L2's skill text, not a
  separate lane.
