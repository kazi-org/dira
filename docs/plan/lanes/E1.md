# E1 — The ledger (L1: lanes)

**Level 1 of the plan tree.** L0 is `docs/plan.md`; L2 task files land at
`docs/plan/tasks/E1-L<n>.md` and are written from the prompts listed below.

**Epic:** E1 — the ledger. **Maps to:** roadmap M1.
**L0 `acc:` (verbatim):**

> `dira brief` returns in <100ms on a cold cache over a 200-entry ledger;
> `dira brief --context` output is ≤1500 tokens measured by the binary and drops by
> priority rather than truncating mid-render; `dira reindex` rebuilds the cache from
> files alone and a cache/file disagreement resolves to the file.

**Status:** `docs/roadmap.md` is authoritative. Nothing in this epic exists yet —
there is no `go.mod` in the repo, so **every `acc:` line below is red today.**

**Blocks on:** all of E1 blocks on E0 landing a Go module, package layout, and the
schema-validation test. Lane paths below are provisional (see *Provisional paths*).

Six lanes, which is the bound. Justification for not being five: the epic prompt
explicitly instructs *"plan a lane that measures it against a 200-entry fixture
rather than assuming it"* — L6 exists because that instruction is a lane, not a
footnote on L5. Justification for not being seven: the entry codec and the write
path would have been two lanes touching the same package with an internal handoff,
so they are one (L1 owns the codec and shape; L2 owns the verb).

### E1-L1 — Commit the storage interface, the entry codec, and a deterministic 200-entry fixture

**acc:** `go test ./internal/ledger/...` passes with (a) a round-trip test that reads
every `.dira/entries/*.md` in this repo plus every entry of the generated 200-entry
fixture, re-serializes each, and asserts the bytes are identical; (b) a test proving
`created`/`updated` survive as RFC3339 **strings** — an unquoted input parses, the
written form is quoted, and the test fails if the marshalled YAML round-trips the
field as `time.Time`; (c) an import-boundary test that fails when any package other
than the local backend imports `os`, `io/fs`, or `path/filepath` for a `.dira/` path;
and (d) the fixture generator producing byte-identical output across two runs from
the same seed, with all 200 entries passing E0's schema validator.

**risk:** the storage interface gets shaped around the local filesystem — atomic
rename, file locks, glob, path walking leaking into its method set — so E7's `github`
backend cannot implement it without changes above the interface, which is precisely
the retrofit `dec-0005` was written to prevent. Mitigation: the interface is
specified in terms of *entry-file get/put/list/delete*, and the import-boundary test
is the mechanical check that nothing above it knows what a path is.

**entries:** implements `dec-0005` (interface on day one, `local` the only impl) and
`dec-0002` (one file per entry, edges on the subject). Constrained by `int-0002`
(nothing in the read path may cost a network call or a process).

### E1-L2 — Build the write path: `dira log` writes exactly one file per mutation

**acc:** `dira log` invoked to create a decision with two alternatives and a
`derives_from` edge creates exactly one new file under `.dira/entries/`, that file
passes E0's schema validator, and its id is the lowest unused number for its kind;
32 concurrent `dira log` invocations against one ledger produce 32 distinct ids and
32 files with zero overwrites and zero collisions; adding an edge to an existing
entry produces a modified-path set of cardinality exactly 1 (asserted, not observed
by eye); and an injected failure mid-write leaves the ledger with no partial or
malformed file — the pre-write state is byte-identical.

**risk:** id allocation is a shared-counter problem being solved on a filesystem with
concurrent unattended writers (`Stop` hooks in parallel sessions). A naive
"max(existing)+1" scan races, and the failure is silent: two entries with one id, or
one clobbering the other. It also has to work over the `github` backend later, where
there is no local lock to take.

**entries:** implements `dec-0002` (single-file mutation, edges on the subject) via
`dec-0005`'s interface. Bound by `cst-0002` — `dira log` accepts five kinds and
rejects a sixth with a message naming the constraint, rather than accepting it.

### E1-L3 — Make the SQLite cache derived and disposable, rebuilt by `dira reindex`

**acc:** the full read-path test suite runs twice against the 200-entry fixture —
once cache-warm, once with `.dira/cache/` deleted before every query — and both runs
produce byte-identical output for every query; `dira reindex` after deleting
`.dira/cache/` reproduces a byte-identical cache-derived query result; editing an
entry file so it disagrees with an existing cache makes every query return the
**file's** value without a manual reindex; `git check-ignore .dira/cache/index.db`
exits 0 in a test; and a read-only or unwritable `.dira/cache/` directory degrades to
direct-from-files answers with a stated notice and exit 0, never an error.

**risk:** the cache quietly becomes authoritative — a query path that reads the cache
without a validity check, or a staleness check cheap enough to skip under the
<100ms budget. Then a stale row outlives the file that contradicts it and dira lies
about a decision, which is the one failure the product cannot survive.

**entries:** implements `dec-0002`'s "if the cache and the files ever disagree, the
files win." Constrained by `int-0002` (no daemon may be introduced to keep the cache
warm) and `cst-0003` (the cache is a derived artifact; it must stay gitignored so a
`private: true` entry cannot reach a public commit through it).

### E1-L4 — Ship `dira why` — the chain, the alternatives, the why_nots

**acc:** `dira why dec-0002` against this repo's real ledger prints, asserted by a
golden-file test, every element `docs/design/DESIGN.md` and `docs/design.md` §10.8
require: the decision, each alternative with its `why_not` (and `revisit_if` when
present), the title of each `derives_from` parent, any `realized_by` target verbatim,
and the `adr` path when the field is set; the chain is drawn in box-drawing
characters that are selectable text with no ANSI box graphics (test: stripping ANSI
leaves the tree intact); `dira why daemon` resolves by term to the same entry set as
its id form; `dira why` on an entry with no alternatives states that explicitly
rather than rendering an empty section; and `dira why nonexistent-0000` exits
non-zero with a message that does not resemble a crash.

**risk:** the terminal renderer and the web renderer drift, breaking the design
system's load-bearing claim that the web why-chain *is* `dira why`'s output
(`DESIGN.md`: "the same output `dira why` prints in a terminal"). If E6 has to
re-implement the chain, the signature detail becomes a lookalike. Mitigation: the
chain is produced by a renderer that emits a structured chain E6 can consume, and
the golden file is the shared contract.

**entries:** serves `int-0001` (retrieval at zero effort — this is the on-demand half
that the brief's push half does not cover). Reads `dec-0009`'s `adr` pointer without
treating the ADR as truth. Reads only through `dec-0005`'s interface.

### E1-L5 — Ship `dira brief`, the in-binary 1,500-token cap, and SessionStart injection

**acc:** `dira brief --context` over the 200-entry fixture emits ≤1500 tokens by the
binary's own counter, with the ceiling read from `brief.max_tokens` in
`.dira/config.toml` and a test proving a lowered ceiling is honored; against a
fixture engineered to overflow, the omitted content is whole entries dropped from the
low-priority end (recent decisions dropped first, then current focus, open blockers
last to go), every rendered entry block is structurally complete (no entry is cut
mid-render), and the output names both what it omitted and the verb to see the rest;
a ceiling low enough to admit only one section still yields a well-formed brief
containing the open blockers; and `dira brief --context --chain` with no `[parents]`
configured exits 0 and states that no parent ledger is configured rather than
erroring or printing nothing.

**risk:** "1,500 tokens measured by the binary" has no tokenizer behind it. dira
cannot call a model (`dec-0003`) and must not fetch a BPE file at runtime
(`cst-0004`, `int-0002`), so the counter is either a vendored tokenizer or a
documented offline estimator — and if it under-counts, the constitutional cap is
decorative. The lane must choose, must be conservative in the direction of dropping
too much rather than too little, and **must record the choice as a new `.dira/`
decision entry** with its alternatives.

**entries:** implements `cst-0001` (the cap, in the binary, drop-not-truncate) and
`int-0001`'s inversion 2 (review is push). Bound by `dec-0003` (no model client, so
no tokenizer that phones home) and `int-0002` (this runs in a hook in the latency
path of a waiting human).

---

### E1-L6 — Hold the cold-start budget: <100ms `dira brief` on a cold cache

**acc:** a committed test executes the built `dira` binary as a subprocess against
the 200-entry fixture with `.dira/cache/` removed before each run, and fails if the
median of N≥20 cold runs exceeds 100ms wall clock or if any single cold run exceeds
150ms; the same test fails if warm `dira brief` exceeds the cold budget, and if
`dira reindex` over 200 entries exceeds a budget stated in the test; the run happens
with no network available and the test asserts the binary opened no socket; and the
budget numbers live in one place in the test so a regression names which budget it
broke.

**risk:** this lane owns a number it does not own the code for. Hitting it may
require changing decisions inside L1, L3, and L5 (lazy body parsing, not loading 200
markdown bodies to render 8 titles, avoiding a cache open on the happy path). It
therefore lands **last and serially**, after L3 and L5 merge, and its owner is
explicitly authorized to modify their code — otherwise it becomes a lane that can
only file bugs. A benchmark that only runs on the maintainer's laptop is also worth
nothing: it must fail in CI, on CI's slower hardware, which means the budget needs a
stated CI multiplier or a dedicated runner, decided in-lane.

**entries:** implements `int-0002`'s "achieved when… `dira brief` returns in well
under 100ms on a cold cache" and its no-daemon clause — the budget may not be met by
introducing a resident process. `cst-0004` forbids meeting it with a network cache.

## Pinned interpretations

These were ambiguous in L0 and are pinned here so six lanes do not each guess:

1. **`dira log` is the write verb, not a list command.** It appends an entry to the
   ledger (`dec-0003`: *"the skill… then calls `dira log` with the complete entry"*;
   *"degrades to `dira log` typed by hand"*). Nothing in E1 lists entries as a
   `log`-style history. A `git log`-shaped reading of the name is wrong.
2. **Drop order under the cap is keep-priority, read low-end first.**
   `cst-0001` lists "open blockers, then current focus, then recent decisions" as the
   order of *importance*. Therefore recent decisions are dropped first and open
   blockers last. For E1, with no kazi join (E4) and no tiers (E5): *open blockers* =
   open questions carrying a `blocks` edge; *current focus* = `active` intents;
   *recent decisions* = `accepted` decisions, most recent first.
3. **`--chain` exists in E1 as a defined degradation, not a stub.**
   `hooks/settings.example.json` already ships `dira brief --context --chain`, and
   tier resolution is E5, which is BLOCKED on `qst-0001`. So in E1 `--chain` must
   exit 0 and say no parent ledger is configured. Shipping the documented hook
   command as an error or a silent no-op is a defect, and E1-L5's `acc:` covers it.
4. **`private: true` is not a leak vector in E1**, because E1 exports nothing and
   mirrors nothing. `cst-0003` binds E1 in exactly one place: the derived cache must
   stay gitignored (E1-L3). Ref-only citation of private entries belongs to E3 and
   E6, and is deliberately not planned here.

## Provisional paths

E0 has not yet fixed the package layout, so the paths in the L2 prompts
(`internal/ledger/`, `internal/ledger/local/`, `internal/index/`, `internal/brief/`,
`internal/why/`, `cmd/dira/`) are provisional. Every L2 prompt instructs its agent to
read `docs/plan/lanes/E0.md` and `docs/plan/tasks/E0-*.md` first and use E0's actual
layout where it differs. `internal/ledger` is used for the core because the L1
contract's own worked example does (`go test ./internal/ledger -run TestReindex`).

## Deliberately not in these lanes

- **The ADR mirror** (`dec-0009`, `mirror.adr = true` in `.dira/config.toml`, the
  `adr` field in the schema). No epic in L0 owns writing the mirrored ADR file. It is
  a write-path concern, but the trigger is *accepting* a decision, and disposition is
  E2's. Flagged upward rather than absorbed here; `E1-L4` only *reads* the `adr`
  field, and until someone owns the writer, that field is never set by dira and the
  config key is a promise the binary does not keep.
- **`dira init`.** `int-0002` says onboarding is `brew install dira && dira init`, and
  the only epic naming an `init` is E5 (`--interview`), which is BLOCKED. Bootstrapping
  a fresh `.dira/` therefore has no owner. Flagged upward; not absorbed.
- **`dira sniff`, hook installation, staged-entry disposition** — E2. E1 makes the
  brief injectable and correct; E2 installs the hook (`dec-0008`'s merge-never-clobber
  contract).
- **`dira map`, the kazi join, any bucket** — E4. No E1 lane may store or compute
  execution status (`dec-0004`).
- **Tier/parent resolution and namespaced refs** — E5, blocked on `qst-0001`.
