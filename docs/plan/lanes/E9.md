## Verification of the claims in `L1-E9.md`

Read-only, against `/Users/dndungu/Code/kazi-org/kazi`, 2026-07-29.

**Claim 1 — `portfolio --json` exists but is absent from `Kazi.CLI.Schema`: CONFIRMED.**
- `parse_command(["portfolio" | rest], flags)` at `lib/kazi/cli.ex:1252`; `--json` and
  `--full` are its only flags (`cli.ex:417`).
- `portfolio_json/1` at `lib/kazi/cli.ex:4249` — the prompt's line number is exact. It
  emits `schema_version: @run_schema_version`, `kind: "portfolio"`, `planned`, `by_repo`,
  `fleet_remote`, `totals`, `todo`, `blocked`, `rate`, with helpers
  `portfolio_totals_json/1` (`:4269`) and `portfolio_blocked_json/1` (`:4277`).
- The bucket enum is exactly `done | running | blocked | todo | planned`
  (`@portfolio_bucket_labels`, `cli.ex:4283`) — `dec-0004`'s join table is safe.
- `grep portfolio lib/kazi/cli/schema.ex` → **zero matches.** `@schemas` has exactly four
  keys: `"apply"` (`:36`), `"plan"` (`:176`), `"bus"` (`:252`), `"status"` (`:343`), and
  `@ordered_commands` at `:419` is `["apply", "plan", "status", "bus"]`. `Schema.fetch/1`
  reads `@schemas`, so `kazi schema portfolio` does not resolve.

**Claim 2 — goal-files carry a free-form verbatim `metadata` table, so the `why` ask is
genuinely unnecessary: CONFIRMED, with both cited line numbers exact.**
- `lib/kazi/goal/loader.ex:24` — the documented key table row: `` `metadata` | table |
  no | `Goal.metadata` (string-keyed map, verbatim) ``.
- `lib/kazi/goal/loader.ex:640` — `metadata: Map.get(data, "metadata", %{})`, no
  validation, no key allowlist.
- So `metadata.why = "dira:dec-NNNN"` works against kazi today. **Do not re-file that
  ask** — the reduction from three asks to two is correct.

**Claim 3 — the bus is daemon-hosted and no-ops when the daemon is down: CONFIRMED.**
`docs/adr/0067-session-coordination-bus.md:59-60`: "Everything else in this ADR degrades
gracefully when the daemon is not running: bus surfaces report 'no daemon' cleanly and
no-op." Retention and cap also confirmed: `event`/`intent` is an "age-bounded, ~24h"
limits-retention stream (`:76`) with "a hard per-message size cap (~1 KB)" (`:89`). The
prompt's reasoning for rejecting `bus post` holds on kazi's own text.

**Claim 4 — `dec-0008` / `docs/roadmap.md`: "nothing in kazi's test suite pins it as a
public contract." FALSE. Needs correcting in the repo.**
`test/kazi/cli_portfolio_test.exs:181` is a test titled "v1 --json keys are
byte-identical and new keys are additive" that decodes `kazi portfolio --json` and
asserts `schema_version == 2`, `kind == "portfolio"`, the types of `planned`, `by_repo`,
`fleet_remote`, and the additive `totals`/`todo`/`blocked`/`rate` keys. The shape **is**
pinned by a test — just a command-specific one rather than the schema registry.

This does not weaken ask 1; it changes what the ask is. The true gap is discoverability
(`kazi schema portfolio` fails, so an agent cannot introspect a shape kazi does emit) and
governance (the moduledoc establishes a lockstep-version rule over the registered
schemas, and `portfolio` sits outside it). It also makes registration cheaper to grant,
which is worth saying: the shape is already stable and already covered by a test.

**Bonus finding, independently verified, that strengthens ask 1.** The registry has
drifted from `docs/schemas/` in a second, different way: `docs/schemas/roadmap.md:8`
states "`kazi schema roadmap` emits this shape as a machine-readable descriptor", but
`roadmap` appears nowhere in `lib/kazi/cli/schema.ex` (zero matches), so that command
does not resolve either. Two distinct defect classes — an emitted-but-unregistered shape
(`portfolio`) and a documented-but-unregistered one (`roadmap`) — which supports framing
ask 1 as closing a gap in kazi's public contract rather than as a dira request.
`docs/schemas/collective-result.md` describes a third shape, `apply --parallel --json`,
which shares the registered `apply` key while being a different object; worth a sentence,
but confirm the current behaviour before asserting anything about it in an issue.

**Duplicate check — no duplicates for either ask.** `kazi-org/kazi` has **8 open issues
total**. Searches over `--state all`: "portfolio schema" → only #1427 (CLOSED, the
feature that *built* `portfolio`); "Kazi.CLI.Schema" → none; "approve hook" → only #974
(CLOSED, unrelated skill coverage); "reject hook" → none; "post-disposition" → none;
