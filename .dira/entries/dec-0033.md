Triage finding, 2026-09-02, from GH issues #35 and #36. Today the only way to remove a bad auto-capture (regex misfire, quoted duplicate of an existing decision) is to delete the file, which frees its number for reuse (#35) and which dira supersede refuses to touch because the target is state: staged, not confirmed (#36, with a misleading error: 'answer and 1 is never a verdict'). Proposed: a distill disposition (or a dira log/distill verb) that marks an entry rejected/tombstoned in place -- id retained, content marked disposed of -- so a junk capture can be cleared without either freeing its number or leaving an orphaned staged entry with no path to closure. Pair with a clearer supersede error naming the actual precondition ('entry state must be confirmed, not staged') instead of the current cryptic message.
