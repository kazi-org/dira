A public ledger publishes a cross-boundary parent ref **verbatim and opaquely** —
`derives_from: sire:int-0002` ships as written. Nothing is stripped, nothing is
duplicated, nothing is redacted.

**Why this and not the alternatives: it is the only candidate that does not require
superseding an accepted constraint.** `cst-0003` rule 3 already settles the adjacent
case — where a check must cite a private constraint in a public context, "it cites
the **ref only** (`me:cst-0002`), never the text." A namespaced `derives_from` edge in
a public entry *is* that construction. Candidate 1 is that rule applied consistently;
both other candidates would have required overruling it. That asymmetry is decisive
and `qst-0001` never named it.

## Resolution reports three states, not two

The only real objection to opaque refs was that drift could no longer distinguish
"no parent" from "private parent I cannot see." It can — the distinction is present
in the data:

| State | Condition | Is it drift? |
|---|---|---|
| **oriented** | edge present, target resolved and readable | no |
| **withheld** | edge present, parent namespace declared but not readable here | **no** |
| **orphan** | no `derives_from` edge at all | **yes** |

Only `orphan` is drift. This preserves the signal that `dec-0006` depends on, and it
supplies the state `docs/design/DESIGN.md` recorded as undesigned with the note that
"unresolved" must not look like an error. Withheld is a legitimate, designed state —
not a failure, not an error, not a warning.

## What it costs, stated plainly rather than left to be discovered

**What leaks:** the existence of a private parent ledger, its namespace, and an
integer id. **What does not leak:** the parent's title, its body, its alternatives,
its edge notes — anything a human wrote.

The namespace is typically a venture name that is public anyway. Where it is not,
`[parents]` may declare the namespace with `visibility = "private"` and omit the
human-facing label, so the ref remains resolvable-as-withheld without shipping the
name. This is a real disclosure and adopting a private parent should be a considered
act, not a default.

## Implementation notes

No schema change is required. `schema/entry.schema.json` `$defs/ref` already permits
namespaced refs (its own examples are `sire:int-0002` and `me:cst-0002`), and a
`private` boolean already exists on entries.

What is new is one config field — `visibility` on a `[parents]` entry — and the
three-state resolution in the query layer. A namespaced ref whose namespace is **not**
declared in `[parents]` is an error rather than a withheld state: an undeclared
foreign ref is a typo or an invention, and treating it as withheld would let real
mistakes hide behind the privacy boundary.
