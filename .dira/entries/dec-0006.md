```
~/.dira/                    you       — private git repo, syncs across machines
└─ sire/.dira/              venture   — derives_from: me:int-…
   └─ kazi/.dira/           repo      — derives_from: sire:int-…
   └─ dira/.dira/           repo
```

The tier is metadata (`ledger.tier` in config), not a type system. What changes per
tier is only which mix of the five kinds is idiomatic:

- **person** — intents as *directions* ("ship dira v0.1"), cross-project decisions
  ("parked X in March because Y"), personal constraints ("no new projects until
  dira ships"), portfolio-scope questions.
- **workspace** — intents as *bets* ("kazi is the wedge product"), cross-cutting
  decisions no single repo owns, standing constraints every repo inherits.
- **repo** — the technical decisions, alternatives, and questions of one codebase.

Two mechanisms make the tiers work, and they are the same mechanisms at every
level: **namespaced refs** (`sire:int-0002`) resolved through `[parents]` in
config, and **the orphan flag** — an active intent with no `derives_from` into a
parent is surfaced as drift. At the repo tier that flag asks "why does this work
exist?"; at the personal tier it asks the same question of a whole project.

The few-intents cap matters most at the top: a personal ledger holding twelve
active intents *is* the absence of clarity, rendered legibly. dira's job there is
to show that, not to fix it.
