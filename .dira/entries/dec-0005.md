One abstraction, decided now because everything downstream assumes it: all reads
and writes go through a storage interface with two implementations.

- **local** — the filesystem, for the CLI, the hooks, and `dira ui`.
- **github** — the GitHub Contents API over OAuth, for the phone and any surface
  that has no checkout.

Every mutation is expressed as **an entry-file change** (which dec-0002 made a
single-file operation). So a write is `PUT one file` on the github backend and
`write one file` on local — the same operation shape, and therefore the same code
above the interface.

The consequence is that GitHub *is* dira's sync server, and it was already paid
for: auth, offline caching, conflict handling, audit history, and access control
are all problems GitHub solved. A tap on the phone becomes a commit; the laptop's
next `dira reindex` picks it up; the next session's brief contains it. No dira
server exists anywhere in this picture — which is what makes the "never required"
half of cst-0004 structurally true rather than a promise.
