Any **public** `.dira/` ledger can be rendered as a browsable why-graph by a
read-only web surface. This is dira's distribution mechanism, and it is promoted ahead
of the paid apps in the roadmap.

**Why this is the growth engine.** dira has three structural growth problems, all of
them consequences of decisions that are correct on their own terms:

| Problem | Root | Answer |
|---|---|---|
| Invisible by design | int-0001's "you never open a file" | the ledger renders — every adopting repo becomes a linkable artifact |
| Delayed value | the payoff is week 12 benefiting from week 1 | lead with retrospective import, not prospective logging |
| Fatal empty state | a fresh ledger has nothing to say | `dira init` must never produce an empty ledger |

The loop the renderer closes is architecturally free, because the ledger is *already*
committed to git (dec-0002) and GitHub is *already* the sync layer (dec-0005):

```
point dira at a repo → decision graph + contradiction report in 60s   (day-1 value)
  → hooks keep it current at zero effort                              (retention)
    → the ledger is committed, public in OSS repos                    (artifact)
      → it renders as a why-graph a stranger can read                 (distribution)
        → they want it for their own repo                             (acquisition)
```

**This does not violate cst-0004, and the distinction must be stated wherever the
renderer is mentioned.** That constraint forbids dira *requiring* a network service to
function. The renderer is strictly additive and strictly read-only: it stores nothing,
owns no user data, requires no account to view, and the CLI behaves identically whether
it exists or not. If it disappeared tomorrow, no user loses a capability. An audience
that checks this claim will check it, so the honesty has to be structural rather than
reassuring.

**Two consequences that bind other work.**

1. **qst-0003 is promoted from a deferred risk to a launch blocker.** The import path
   is the acquisition moment: pointing dira at an existing repo and getting back a real
   graph plus the contradictions already in it. If import yields entries with empty
   `alternatives` arrays, the first impression is an empty shell at exactly the moment a
   user decides whether this is real. The quality of ADR/history import is now a growth
   variable, not a convenience.
2. **`dira init` may never produce an empty ledger.** Import and interview are the
   product's first experience, not setup that precedes it.

**The honest limit.** This buys compounding organic distribution, not virality. There
is no invite mechanic, no social graph, and no k-factor in a single-player developer
tool. Published artifacts inside a fast-growing ecosystem compound; they do not go
viral. Internal targets and copy should both say so — see
[`.agents/product-marketing.md`](../../.agents/product-marketing.md) §7.
